# 对话框系统异步安全收敛
## 第 1 步：Skip 止血执行文档

## 1. 本文档用途

本文档只覆盖对话框系统异步安全收敛的**第 1 步**：

- 处理 `~` 跳过链路
- 去掉最危险的同步队列硬裁剪
- 把 skip 冷却 timer 收口到联机安全工具

这是一份**可直接执行**的改单文档。  
执行人不需要从中二选一，不需要自行补方案，只按本文档落地即可。

## 2. 作用范围

本轮允许修改：

- `TS/系统/09．表现系统/02．对话框系统/20．对话框渲染-任务回调与命中.ts`
- `TS/系统/09．表现系统/02．对话框系统/17．对话框渲染-Dz与状态.ts`

本轮不改：

- `TS/系统/09．表现系统/02．对话框系统/19．对话框渲染-播放与状态管理.ts`
- `TS/系统/09．表现系统/02．对话框系统/18．对话框渲染-创建帧.ts`
- `TS/系统/09．表现系统/02．对话框系统/05．对话框业务逻辑.ts`
- `TS/系统/09．表现系统/02．对话框系统/09．对话构建.ts`
- `TS/系统/09．表现系统/02．对话框系统/12．任务提交流程.ts`

## 3. 本轮目标

本轮只做三件事：

1. 去掉 `skip` 回调里的危险队列裁剪
2. 保留 `~` 为 `sync=true`，但把回调体收敛到最小安全范围
3. 把 skip 冷却 timer 改走联机安全工具

本轮明确**不做**：

- 改 accept/reject 业务链
- 改播放状态机
- 抽本地渲染器
- 改任务 UI 刷新桥

## 4. 当前问题

当前高危点在 `20．对话框渲染-任务回调与命中.ts`：

- `skipDialogLocal()` 由 `sync=true` 键盘回调触发
- `fastForwardQueueToLastNormalLine()` 内存在 `state.queue = [last]`

这相当于在同步回调里直接重写共享队列头尾关系。  
只要各端此前已有轻微状态偏差，这里就会把偏差放大。

## 5. 最终执行方案

### 5.1 `~` 保持 `sync=true`

本轮**不把** `~` 改成 `sync=false`。

原因：

- 当前 skip 仍会改 `strNow/strLen`
- 当前 skip 仍会改当前展示语义
- 当前 skip 仍会改当前条目的文本完成态

这些操作本轮仍需全端对称执行。

因此，本轮固定结论：

- `registerKeyEventByCode(KEY_SKIP_DIALOG, KEY_STATE.DOWN, true, skipDialogLocal)` 保持不变

### 5.2 删除危险逻辑

必须删除或改写下面这种语义：

```ts
state.queue = [last];
```

本轮禁止在 skip 回调链中出现：

- `state.queue = [last]`
- 任何“按视觉目标直接重建 queue”的写法

### 5.3 `fastForwardQueueToLastNormalLine()` 的收敛方式

本轮不再把 skip 定义为“跳到队尾最后一条普通对话”。  
本轮把 skip 收敛为：

> **只补全文字，只让当前条目进入可继续状态，不再在 skip 中推进多条队列。**

也就是说：

- 如果当前在打字，skip 只补全文字
- 如果当前已经打完字，维持等待点击或任务按钮态
- 不在 skip 中跨越多条普通对话
- 不在 skip 中跳到最后一条普通对话

### 5.4 具体改法

保留 `fastForwardQueueToLastNormalLine()` 这个函数名也可以，但函数体必须改成“当前条目补全文字”的安全语义。

推荐直接改成：

```ts
function fastForwardQueueToLastNormalLine(state: PlayerDialogState): void {
  if (state.queue.length === 0) return;
  const entry = state.queue[0];
  if (!entry || entry.isQuest) return;

  dzTimerPause(state.tickTimer);
  state.strLen = stringLengthCompat(entry.text);
  state.strNow = state.strLen;
  state.waitingClick = true;
  state.clickCooldown = false;
  setActivePlayerId(state.playerId);

  dzSetFont(state.frames[2], DEFAULT_FONT, entry.titleFontSize ?? DEFAULT_TITLE_FONT_SIZE);
  dzSetFont(state.frames[3], DEFAULT_FONT, entry.bodyFontSize ?? DEFAULT_BODY_FONT_SIZE);
  dzSetText(state.frames[2], entry.title);
  dzSetText(state.frames[3], entry.text);
  showDialogFrames(state, true);
  applyPortraitFrames(entry, state, dzGetLocalPlayer, dzPlayer, dzSetTexture, dzShow);
  showQuestButtons(state, false, dzGetLocalPlayer, dzPlayer, dzShow);
  showContinueHintLocal(state, true);
}
```

允许实现细节微调，但必须满足：

- 不改 `queue`
- 不做 `splice`
- 不做 `shift`
- 不在 skip 中跨条目推进

### 5.5 `skipDialogLocal()` 的调用逻辑

把“多条队列时快进到最后普通行”的逻辑收口为“当前普通条目补全文字”。

执行后，`skipDialogLocal()` 应满足：

- 遇到任务条目：只补全当前任务条目的文字并显示任务按钮
- 遇到普通条目：只补全当前普通条目的文字并显示继续提示
- 不因 `queue.length > 1` 就做多条推进

## 6. Timer 收口

### 6.1 要求

`startSkipKeyCooldown()` / `finishSkipKeyCooldownForPlayer()` 中的冷却 timer 必须收口到联机安全工具。

本轮目标：

- 启动用 `safeTimerStart`
- 销毁用 `safeDestroyTimer`

### 6.2 允许做法

可选两种方式，二选一即可：

1. 在 `20．对话框渲染-任务回调与命中.ts` 直接引入 `safeTimerStart/safeDestroyTimer`
2. 在 `17．对话框渲染-Dz与状态.ts` 增加安全销毁封装后复用

建议优先第 1 种，改动最小。

### 6.3 完成标准

以下裸调用不应再保留在 skip 冷却链里：

- `jass.TimerStart(t, ...)`
- `jass.DestroyTimer(t)`

允许保留：

- `jass.CreateTimer()`
- `jass.PauseTimer(t)`

## 7. 明确不改的点

本轮不要顺手改下面这些：

- `runQuestAcceptForPlayer`
- `runQuestRejectForPlayer`
- `advanceDialog`
- `playEntry`
- `skipTyping`
- accept/reject 的 reopen 设计
- `questManager.triggerUIRefresh` 任务 UI 联动桥

这些属于下一轮或后续步骤。

## 8. 代码要求

执行时必须遵守：

- 不新增匿名闭包进 JASS / Dz 注册点
- 不把 `~` 改为 `sync=false`
- 不把 skip 改成多条 `advanceDialog()` 循环推进
- 不引入新的本地分支写共享状态

## 9. 完成定义

本轮完成后，必须同时满足：

1. `20．对话框渲染-任务回调与命中.ts` 中不再出现 `state.queue = [last]`
2. skip 链中不再出现 `queue.splice(...)`、`queue.shift()` 这种跨条目推进
3. `~` 仍然是 `sync=true`
4. skip 冷却 timer 改走 `safeTimerStart/safeDestroyTimer`
5. 当前普通对话按 `~` 后，只补全文字并等待继续
6. 当前任务对话按 `~` 后，只补全文字并显示任务按钮
