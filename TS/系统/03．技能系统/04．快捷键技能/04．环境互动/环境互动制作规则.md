# 环境互动制作规则

本规则适用于当前目录下全部环境互动，以及剧情、任务侧对环境互动的接入。

## 生命周期与奖励归属

1. 正式区域探索点默认是世界级一次性互动，不是“每位玩家各一次”。
2. 首位玩家成功触发并领取奖励后，立即注销点位；后续任何玩家都不能再次触发。
3. 奖励只发给首次成功触发者。不得因为多人任务的全体奖励惯例，把探索奖励扩散给所有玩家。
4. 回调只有在剧情反馈和奖励均成功处理后才返回成功；通用核心根据成功结果负责注销，业务文件不重复维护按玩家领取表。
5. 任务调查点必须有明确清理时点。取消、失败、完成、场景切换或剧情跳过后不得残留监听、特效和状态。
6. 只有用户明确要求可重复服务、冷却设施或每玩家独立领取时，才允许覆盖世界级一次性默认值，并在配置和规划中写清例外。

## 内容与表现

1. 每个正式环境互动必须同时提供场景剧情信息和实际奖励，不能只有一句空提示。
2. 环境物件、遗迹、痕迹、书架、祭坛等使用广播消息；只有玩家与 NPC 直接交流时才使用对话框。
3. 环境互动可以触发一次性小怪遭遇：调查只负责唤醒现有单位，击杀单位后才结算该点奖励；遭遇期间禁止重复创建，击杀结算后必须注销死亡监听。
4. 广播文本用玩家可理解的自然语义，不显示 raw id、任务 ID、配置字段、技能操作说明或演员不可能知道的系统信息。
5. 文本应说明玩家实际发现了什么，并让奖励与物件内容对应；不让环境物件代替 NPC 长篇说话。
6. 世界坐标由用户、地图数据或现有代码明确提供，不从截图像素猜坐标。

## 奖励设计

1. 同一批探索奖励必须有类型变化，不能全部做成金币/经验，也不能全部堆永久属性。
2. 可混合使用：永久属性、装备、材料、消耗品、恢复、短时祝福、金币、经验和能量碎片。
3. 环境探索奖励优先从生命恢复、魔法恢复、生命值、魔法值、力量、敏捷、智力及实用装备中组合；不强行给每个点装备，也不把稀有机制属性作为默认奖励。
3. 永久属性应偶尔使用并控制数值；恢复点在满状态时仍应有可领取的实物或其他有效收益。
4. 重要剧情线索可以奖励专属装备或物品。新增物品必须一次完成图标、物编、装备数据、名字反查可用性和业务接入，不挂占位图标。
5. 新装备必须按装备规则至少横向对比三件现有同阶段装备，明确核心用途、取舍、等级和评分；不得先定分数再拼属性。
6. 玩家文本统一使用“能量碎片”，不得写成木材或木头。

## 实现约束

1. 优先复用环境互动核心、广播、物品名反查、创建物品和属性安全封装，不重复造底层函数。
2. 物品识别优先使用“物品名 -> 反查 -> 类型 ID”，业务配置不凭记忆散写 raw id。
3. JASS/TSTL 回调必须使用具名函数并显式标注 `this: void`；禁止匿名 JASS 回调。
4. 不使用 Lua/TS 数学库，不修改 `fix-lua-for-pack.js`，不混用 `jass`、`BJ`、`japi`。
5. 新 TS 文件顶部统一加 `@noSelfInFile`；不得为了规避 TSTL 问题随意给底层 lib 增加该标记。

## 文档与验收同步

1. 运行时代码、总规划、坐标登记和截图标注中的名称、奖励与领取规则必须一致。
2. 修改奖励后同步更新规划表和标注图，不能留下旧数值。
3. 验收至少覆盖：首次触发、第二位玩家无法触发、背包满时物品落点、奖励对象、重复施法、场景重载和清理时点。
4. 修改 TS 后先对本次文件执行 `build:files`；涉及公共类型、公共导出、删除/重命名或最终交付时再执行完整构建。
