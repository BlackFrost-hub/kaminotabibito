# 环境互动总规划

> 状态：运行时接入持续维护。精灵王城、灼热火山、熔岩小镇、恶魔城、恶魔迷宫、盗贼洞窟，以及本次补齐的悲风山谷、蛇人领地门口和恶魔城野外点位均已接入；万浴熔灵入口已改为固定传送。焚丝蛛痕仍需进图验证模型与战斗表现。  
> 范围：全地图、全章节的环境互动、剧情补充、奖励与运行时接入。  
> 本文是环境互动内容规划的统一记录，不等同于已经落地的 TS 配置。

## 一、目标与边界

环境互动不只用于推进主线，也用于补充场景信息、提供探索奖励、记录世界线细节和建立短小的可选剧情。

统一目标：

- 每个正式环境互动都必须有实际奖励，不能只播放一句提示。
- 互动由玩家英雄使用环境互动技能触发，默认扫描范围为 300。
- 环境物件互动使用广播消息；只有和 NPC 的直接交流才使用对话框。
- 环境互动默认不直接推进主线，只有明确标记为“剧情节点接入”的互动才可以写入剧情进度。
- 奖励必须写清楚领取者：提交者、触发玩家、所有玩家，不能依赖默认猜测。
- 同一场景的不同截图视角不重复创建点位；以实际物件和世界坐标为准。
- 不把内部单位 ID、物品 ID、任务 ID 直接展示给玩家，玩家文本使用自然语义。
- 新互动优先复用现有注册、广播、奖励、物品和状态封装，不重复造底层函数。

## 二、现有接入模型

### 2.1 技能入口

环境互动技能当前使用 A08E，由通用环境互动核心负责：

1. 校验施法单位是已注册的玩家英雄。
2. 以英雄当前位置扫描附近触发点。
3. 调用触发点的具名回调。
4. 回调返回成功后，按点位规则清理或保留。
5. 没有可用互动时，只向施法玩家发送轻量空挥提示。

环境互动配置不负责伪造技能事件，也不直接依赖 JASS 触发器。回调保持具名函数，避免匿名闭包和 TSTL 的 self/nil 风险。

### 2.2 点位生命周期

每个点位必须记录：

| 字段 | 要求 |
|---|---|
| 场景 | 所属地图场景和章节 |
| 点位名称 | 玩家能理解的语义名称 |
| 世界坐标 | X、Y，必要时记录 Z |
| 触发范围 | 默认 300，特殊点明确填写 |
| 触发条件 | 章节、剧情状态、任务状态或世界线条件 |
| 触发方式 | 调查、采集、触碰、阅读、祈愿、破坏后调查等 |
| 表现 | 特效、动画、镜头或其他环境表现 |
| 广播文本 | 触发后显示给玩家的自然语义 |
| 奖励 | 类型、数值、领取者、领取次数 |
| 状态键 | 防重复领取或记录剧情线索 |
| 清理时点 | 永久点、任务结束清理、场景切换清理或 Boss 结束清理 |

多人地图中，正式探索点默认是世界级一次性：首位玩家成功触发并领取奖励后，点位立即注销，奖励只归该触发者。只有明确标记为可重复服务、冷却设施或每玩家独立领取时，才允许覆盖这一默认值。

## 三、内容分类

### 3.1 常驻区域探索

适合城镇、道路、墓地、遗迹、野外营地等固定场景。

特点：

- 不绑定某一个任务。
- 以章节和场景组织目录。
- 每个点都有一次性奖励或明确的冷却奖励。
- 可以记录隐藏线索，但不能无条件改写主线进度。

推荐内容：

- 残缺军令、旧碑文、被遗弃的工具。
- 花圃、祭坛、古树、圣泉、火盆和魔法阵。
- 城墙器械、路标、旗帜、书架、会议桌。
- 失物、异常痕迹、旧战场残留。

### 3.2 任务环境互动

适合任务要求的调查、搜寻、采集和现场取证。

特点：

- 由任务状态决定是否注册。
- 完成任务、取消任务、失败或场景切换时注销。
- 任务互动只负责现场动作和反馈，任务完成由任务系统统一判定。
- 取消任务或 ESC 跳过不能误发奖励，也不能留下监听和特效。

### 3.3 剧情环境互动

适合主线或支线中的无 NPC 互动，例如调查遗迹、读取记录、触碰封印和启动机关。

特点：

- 需要明确剧情挂接点：剧情前、对白后、战斗后或场景切换后。
- 互动发生前确认参与者和场景已经就位。
- 若互动会改变剧情状态，必须有唯一状态键和幂等保护。
- 剧情对白仍遵守说话者在场、顺序、时长和场景切换规则。
- 不把环境广播写成 NPC 隔空对白。

### 3.4 可重复环境服务

适合圣泉、祭坛、训练器械和城镇设施。

特点：

- 必须有明确冷却、消耗或每日/每场景限制。
- 不能因反复施法无限叠加永久属性。
- 恢复、临时祝福和材料领取要分别记录。
- 反馈文本要说明当前无法再次领取的原因。

## 四、剧情设计方法

每个互动按以下顺序设计：

1. 先确定它在场景中是什么物件。
2. 再确定玩家为什么会注意到它。
3. 用一到两段广播补充信息，不替 NPC 说话。
4. 给一个与内容相称的奖励。
5. 如果需要，写入一个隐藏线索状态。
6. 只有在剧情节点明确要求时，才触发任务或主线承接。

剧情文本要求：

- 让物件提供信息，不让物件替角色长篇解释。
- 采用具体细节，例如日期、刻痕、残页、损坏方式和残留气息。
- 不出现“选择我、点击技能、接受任务”等越界提示。
- 不把内部编号、四位 ID、配置字段名写给玩家。
- 文本短而有信息量；重要剧情再交给 NPC 对话或电影演出。
- 奖励和文本要相互对应，调查军令给线索类奖励，恢复设施给状态类奖励，危险遗迹才给较高价值奖励。

## 五、奖励规划

### 5.1 小型探索点

适用于道路、花圃、普通失物：

- 5000～15000 金币。
- 1 份已存在的材料。
- 1 能量碎片。
- 当前完整升级所需经验的 10%～20%。

### 5.2 重要剧情线索点

适用于王宫档案、古树祭坛、封印残迹：

- 当前完整升级所需经验的 20%～35%。
- 1～2 能量碎片。
- 已有装备、材料或临时祝福。
- 可选地写入隐藏线索状态，但不把线索奖励重复发放。

### 5.3 恢复与祝福点

适用于圣泉、祭坛和城市设施：

- 恢复施法英雄生命或魔法。
- 给予短时、可控的生命恢复、魔法恢复、护甲或抗性效果。
- 如果玩家已经满状态，仍要有其他实际奖励或明确的祝福结果。
- 不直接堆叠永久属性；永久属性必须经过装备数据和评分对比。

### 5.4 奖励校验

正式落地前逐项检查：

- 奖励对象是否正确。
- 是否保持世界级一次性，奖励是否只发给首次成功触发者。
- 物品是否在装备数据中存在。
- 新装备是否有实际用途，并与同档装备对比评分。
- 文本中的“能量碎片”保持游戏设定，不写成木材或木头。
- 失败、取消、重复触发和场景重载不会重复发奖。

## 八、制作顺序

### 阶段 1：盘点与定位

- 按章节和场景收集坐标。
- 区分截图视角、实际物件和可用触发点。
- 查找已有模型、特效、物品和单位封装。
- 对缺失资源单独登记，不在代码里伪造路径。

### 阶段 2：先完成通用运行时

- 保持环境互动核心只负责扫描和生命周期。
- 抽取通用的奖励发放、每玩家领取、冷却、状态键和清理函数。
- 具名回调负责业务，配置只保存数据和入口引用。
- 不把场景剧情硬编码到底层通用库。

### 阶段 3：按章节落地

每个场景单独建立配置入口：

- 场景常驻探索。
- 任务环境互动。
- 剧情节点互动。
- 可重复服务设施。

不同章节的内容不能因为坐标相近而混在一个配置文件中；公共逻辑才进入通用库。

### 阶段 4：接入剧情与任务

- 环境互动只提供线索、状态和奖励。
- 主线节点仍由主线剧情系统写入和引导。
- 支线任务由任务系统判定接取、完成和提交。
- 场景切换、Boss 战开始/结束、取消和 ESC 跳过都必须有清理路径。

### 阶段 5：资源与对象数据

- 使用项目已有模型、特效和安全封装。
- 新物品先查装备数据，再确认物编父 ID、技能壳、叠加类型和图标。
- 装备奖励必须与同档装备对比属性和评分。
- 资源不足时单独制作和记录，不能在 TS 中引用不存在的资源。

### 阶段 6：验证

- 先运行本次修改 TS 文件的局部构建。
- 涉及公共类型、导出签名、删除/重命名或最终交付时再完整构建。
- 检查触发范围、一次性领取、多人奖励、重复施法、任务取消、场景切换和重载。
- 未明确要求时不打包地图。
- 只有怀疑 TSTL 的 self/nil、回调或桥接错位时才检查相关生成 Lua。

## 九、验收清单

每个环境互动完成前必须回答：

- 玩家在什么地方、为什么会触发？
- 是否明确使用玩家英雄和环境互动技能？
- 是否有自然的广播文本或必要的对话？
- 是否有实际奖励，且奖励对象明确？
- 奖励是否与内容强度和现有装备/材料平衡？
- 多人重复触发是否安全？
- 取消、失败、重复和场景切换是否清理？
- 是否使用了现有封装，是否误用了普通版底层函数？
- 是否存在匿名闭包、Lua 数学库、混用 JASS/BJ/JAPI 或内部 ID 外显？
- 坐标、特效、模型和物编资源是否都已确认？
- 局部构建和必要的最终构建是否通过？
