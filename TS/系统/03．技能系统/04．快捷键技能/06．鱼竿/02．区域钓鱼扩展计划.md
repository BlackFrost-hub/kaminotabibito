# 区域钓鱼内容扩展计划

## 目标

- 在现有鱼竿系统上增加四个剧情区域的区域鱼池。
- 使用运行时坐标矩形判断，不创建地图矩形，也不依赖地图编辑器区域对象。
- 保留现有通用淡水鱼池；只有命中特殊区域时才使用该区域的额外规则。
- 熔浆区域只允许钓出第三章已经制作好的四种熔岩鱼。
- 米亚区域根据 Boss 状态切换污染鱼池和净水鱼池。
- 新鱼统一接入现有物品数据、篝火加工和物品使用效果，不另起一套加工系统。

## 模拟钓鱼区域

坐标均为 Warcraft 3 世界坐标，边界包含。运行时只做矩形包含判断。

|---|---:|---:|---:|---:|---|

| `钓鱼.战斗湖边水域` | 27552 | 29984 | 10176 | 10624 | Boss 战斗湖边区域 |

实现时建议将这些坐标集中放在鱼竿配置附近的区域配置模块中。不要直接把坐标散落在鱼竿结算函数内。

## 鱼池选择顺序

1. 鱼竿先执行现有水域判定；不满足水域条件时直接失败。
2. 按优先级检查四个模拟矩形。矩形不重叠时按任意稳定顺序即可，仍建议保留显式优先级。
3. 命中恶魔城野外熔浆时，使用熔岩专属鱼池，跳过通用鱼池和单位结果池。
4. 命中精灵城水池时，读取米亚 Boss 状态：
   - 米亚未击败或净化未完成：使用污染水池，只能获得污染鱼。
   - 米亚击败且净化完成：使用净水水池；净水鱼为主要结果，并保留少量通用鱼概率。
5. 其他两个水池使用“通用鱼池 + 区域特色鱼额外概率”。未命中特色鱼时回落到现有通用鱼池。
6. 区域特色鱼与通用鱼均使用一次随机值结算，不能因回落再次完整抽取，避免概率被放大。

## 建议概率

概率是区域鱼池内部概率，不改变现有普通水域的概率。

| 区域 | 特殊结果 | 特殊结果总概率 | 其他结果 |
|---|---|---:|---|
| 蛇人族水池 | 蛇纹翡翠鲤、月瞳鳗 | 25% | 75% 回落通用鱼池 |
| 战斗湖边水域 | 战痕月鳞鱼、湖心星鲟 | 20% | 80% 回落通用鱼池 |
| 精灵城水池，米亚未击败 | 污潮鳗、黑水鳐 | 100% | 不掉通用鱼、不出单位结果 |
| 精灵城水池，米亚已净化 | 净泉鳗、清辉水母鱼 | 85% | 15% 回落通用鱼池 |
| 恶魔城野外熔浆 | 赤魔鱼、熔岩食鱼、熔岩灵鱼、熔岩焰鱼 | 100% | 不掉通用鱼、不出单位结果 |

熔浆四种鱼建议在专属池内等概率；如果后续需要稀有度差异，再改成显式权重，不复用现有 `1~100` 区间硬编码。

## 属性平衡基线

- 第一章普通烤鱼是基础恢复档位：生命百分比或固定生命，加少量魔法。
- 白鳍鱼和黄金鱼代表中等恢复与已损失资源恢复。
- 熔岩鱼代表第三章战斗恢复档位，允许更高固定恢复、已损失恢复或附加增益。
- 本计划新增鱼应处于第一章与第三章之间：蛇人族、战斗湖和净水鱼偏 C/C+；污染鱼偏 C；不直接超过熔岩灵鱼和熔岩焰鱼的已损失资源恢复。
- 所有新增附加效果必须先确认现有属性或 Buff 封装可复用；没有封装时先只配置 `hot`，不要在鱼竿系统中写临时战斗逻辑。

## 剧情状态接口要求

实现时不要通过区域名称或当前剧情进度硬推米亚状态。应读取现有米亚任务运行状态，封装为一个无副作用查询：

- `米亚是否已击败`
- `米亚水源是否已净化`

只要净化完成条件成立，精灵城水池立即切换到净水池。若任务状态只记录 Boss 死亡而没有单独净化状态，则在米亚任务运行模块中补一个明确的完成标记，鱼竿系统只读取该标记。

## 接入顺序

1. 确认四个矩形与地图实际水面一致，必要时缩小边界，避免把岸边判为可钓点。
2. 为四个区域增加集中式配置和区域包含函数。
3. 为新鱼分配未占用物品 ID，补充物品数据、物编和图标；路径必须按资源规则登记，不能臆造资源路径。
4. 为新鱼增加篝火配方和烤熟物品，复用现有加工系统。
5. 接入米亚状态查询和鱼池切换。
6. 接入鱼竿结算，并验证：普通水域、四个特殊区域、米亚战前、米亚净化后、熔浆禁用通用结果。
7. 最后再补测试日志；调试输出统一使用项目调试输出封装。

# 实施修订（最终实现，2026-09-10）

本节记录实际落地结果，**与上文冲突处一律以本节为准**。

## 1. 判定顺序改为「先判区域」

上文的「先水域判定、再查矩形」**已废弃**。原顺序会让熔浆钓点在逻辑上不可达——现有水域判定要求
`IsTerrainPathable(FLOATABILITY) === false`（即"可漂浮"），而熔岩地形通常 walk/float 皆不可通行。

最终实现（`01．鱼竿核心.ts` → `处理鱼竿生效`）：

```
命中钓点区域 → 直接放行，跳过水域判定
未命中区域   → 走原水域判定，不满足则失败
```

结算同样区域优先：命中区域只走该区域鱼池，**完全不走通用单位结果池**。

## 2. 单位结果的限制（含 94–100 人类渔夫）

命中任一钓点区域时**完全禁用单位结果池**，包括 `94–100 人类渔夫`。
因此区域内的「回落通用池」也**只走通用物品表**（由 `结算通用结果(..., 含单位结果 = false)` 保证）。

未命中区域时，通用池行为与本计划前完全一致（含 74–75 双给与 16–19 级空档两个已知问题，本次不修）。

## 3. 概率：单次掷骰 + 区间档，不做二次完整抽取

不再使用"特色概率 + 回落再抽一次"的写法。改为**一张 1–100 的区间档表**：

- 档带 `物品ID` → 产出该物品；
- 档**不带** `物品ID` → 该区间**回落通用物品池**，把掷骰值按
  `映射值 = floor((随机值 − 区间最小) × 100 / 区间跨度) + 1`（夹取到 1–100）映射后再查通用表。

实际区间：

| 区域 | 区间档 |
|---|---|
| 蛇人族水池 | 蛇纹翡翠鲤 1–13、月瞳鳗 14–25、**回落 26–100** |
| 战斗湖边水域 | 战痕月鳞鱼 1–10、湖心星鲟 11–20、**回落 21–100** |
| 精灵城水池·污染 | 污潮鳗 1–50、黑水鳐 51–100（无回落、无失败） |
| 精灵城水池·净化 | 净泉鳗 1–43、清辉水母鱼 44–85、**回落 86–100** |
| 恶魔城野外熔浆 | 赤魔鱼 1–25、熔岩食鱼 26–50、熔岩灵鱼 51–75、熔岩焰鱼 76–100 |

说明：回落档会把 1–5 的失败判定一并带回（通用表口径不变），因此普通水域的失败手感得以保留；
熔浆与污染池为 100% 产出、不存在失败，属有意设定的区域福利。

## 12. 图标生成管线（本次实际使用）

1. **生成**：`gpt-image-2.5`，请求 `1024x1024`，`n=1`。提示词 = 「魔兽经典 RTS 物品图标风格 + 单主体居中 + 主体描述 + 原生 BTN 边框规格 + 无文字」四段拼接。
   - **边框规格（照 `04．图标资源与物遍规则.md`）**：暗铁/暗银金属外框、低亮度冷灰倒角、左上角窄高光、右下角暗角；禁止金框/白框/鲜艳边框/现代扁平 UI/明显双层内边框。
   - ⚠️ **接口实测两个坑**：①默认 Python UA 会被 Cloudflare 以 `403 / error code 1010` 拦掉，必须带浏览器 UA；②`size` 参数**不被严格遵循**，请求 1024 实际返回 **1254×1254**。
   - 16 张串行生成约 11.5 分钟（单张 33–90 秒），脚本幂等可续跑。
2. **缩放**：`1254×1254` → `64×64`，等比（非整数比，19.59 倍）。
3. **编码**：复用项目既有工具链（`war3icon` 插件）—— `new Image().loadFromBuffer().resize(64,64).toBuffer(TYPE_PNG)` → `blp2Image(tmpPng, outBlp, 'blp')`。
   - 本批图标 alpha 全不透明，故可用插件编码路径；依赖 Alpha 的 BLP 必须改用 `scripts/war3-transparent-blp.js`。
4. **暗版**：`mergeImages(正常64PNG, <war3icon>/images/bm_dis.png, 临时暗版PNG)` → 再 `blp2Image`。
5. **校验**：逐文件读头，必须 `magic=BLP1`、`compression=0`、`alphaBits=8`、`width=height=64`、`pictureType=4`，任一不符即中止。
6. **PNG 只作中间产物**：源图留在系统临时目录、缩放后的 64 图与暗版图在转换后立即删除，**不入工程、不入包**（已核对 `imports/` `objediting/` 无本次 PNG 残留）。
7. 可复跑：`FISH_ICON_SRC=<源图目录> node scripts/migrate-fishing-icons.js`。
