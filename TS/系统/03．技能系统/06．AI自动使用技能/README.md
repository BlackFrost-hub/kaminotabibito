## 当前已实现

### 1. 受击反应施法

目录：

- `01．受击反应施法/00．配置类型.ts`
- `01．受击反应施法/01．单位名反查.ts`
- `01．受击反应施法/02．受击反应配置表.ts`
- `01．受击反应施法/03．受击反应特殊逻辑.ts`
- `01．受击反应施法/04．受击反应执行.ts`
- `01．受击反应施法/05．受击反应驱动.ts`

语义：

- 这是对 `JASS\jass复制粘贴\部分AI放技能.j` 的 TS 迁移入口。
- 入口统一挂 `registerAppliedFinalDamageListener`。
- 只注册一次全局受伤最终回调，不给每只怪单独挂事件。
- 每次受伤时按受击单位查配置，命中则执行对应反制施法。
- 只响应注册玩家英雄造成的伤害：
  - `getRegisteredPlayerHero(GetOwningPlayer(source)) === source`
- 单位配置表写单位名字，不直接在配置里写单位 4 位 raw id。
- 技能 ID 允许保留内部 ID；复杂条件走 `03．受击反应特殊逻辑.ts`。
- 冷却不是旧 JASS 的全局 `DisableTrigger 1.05 秒`，而是每个单位独立冷却。

适用场景：

- 大量杂鱼 / 精英 / 小 Boss
- 单位会死亡、复活、重新创建
- 只能在“被打到之后”立刻反应的技能

不适用场景：

- Boss 主动扫描找目标放技能
- 阶段切换后主动开技能
- 战斗开始时注册长期 tick 的主动施法 AI

### 2. Boss战启动桥接

目录：

- `09．Boss战启动桥接/00．常量定义.ts`
- `09．Boss战启动桥接/01．Boss自动技能注册表.ts`
- `09．Boss战启动桥接/02．Boss战启动STES桥接.ts`
- `09．Boss战启动桥接/03．战斗启动属性`

语义：

- 这是 Boss 主动施法 AI 的过渡桥接层，不是完整 Boss AI。
- 目前只负责接收旧 JASS 的 `Boss战启动` STES 事件，并把 Boss 登记到本地注册表。
- 真正的 Boss 主动扫描施法逻辑后续再接。

当前读取顺序：

1. 先读 STES 里的 `Boss`
2. 如果没有，则延迟一帧再读：
   - `YDUserData("Boss战", "单位")`
   - `YDUserData("Boss战", "绑定单位")`
3. 如果三处都没有，说明旧 JASS 侧上下文有问题，直接调试跳过

补充：

- 这层 STES 只是为了迁移期让 Lua/TS 知道“当前是哪只 Boss 开战了”。
- 后续完整迁移 Boss 战流程后，目标是让核心 AI 逻辑不再依赖 STES，只保留 TS 内部状态驱动。

## 2026-05 更新说明

以下内容以当前 TS 实现为准；若与上文旧描述冲突，以本节为准。

### 1. Boss 主动扫描 AI 已落地

- `02．Boss主动扫描施法/01．Boss主动扫描驱动.ts` 已接入当前 TS 框架
- 当前不再是“只有启动壳子”，而是已经有可运行的 Boss 主动施法扫描逻辑
- 后续重点从“补框架”转为“补具体 Boss 配置、技能本体、特效和阶段逻辑”

### 2. 当前 Boss 主动扫描的工作方式

- Boss 战开始后，通过 `09．Boss战启动桥接` 把 Boss 注册到扫描列表
- 使用 TS 的统一周期扫描驱动，不沿用旧 JASS 的“每只 Boss 各起一个长期 timer”写法
- 每轮扫描会检查：
  - 单位是否存活
  - Boss 是否拥有对应技能
  - 技能当前真实 CD 是否结束
  - 公共施法间隔是否结束
  - 是否存在可用目标
  - 技能附带的生命 / 魔法 / 距离条件是否满足

### 3. 目标选择默认原则

- 优先选择最高仇恨目标
- 如果仇恨系统里没有可用敌人，再回退到最近敌人

### 4. Boss AI 配置原则

- AI 配置表现已统一支持“方案 1 + 2”：
- 方案 1：写 `单位名`，用于可读性、同名同策略归并、以及旧表迁移时的兜底匹配
- 方案 2：写 `单位ID`，用于精确匹配真实单位类型，避免颜色码、等级后缀和重名问题
- 运行时匹配一律优先走 `单位ID`，只有没填 `单位ID` 时才回退到 `单位名`
- 若手头只有 4 位内部 ID，可以直接填 `单位ID`；`单位名` 继续保留作可读备注
- 当前 AI 配置层按用途拆成 `Boss / 英雄Boss / 异界Boss` 三类；英雄形态或带英雄骨架的 Boss 优先写到 `06．英雄BossAI配置表.ts`
- 运行时匹配 Boss 主动 AI 时，优先按单位类型匹配，名字只作为兜底，避免 `Name` 重名撞配置

### 5. 权重与条件的含义

主动扫描不是“纯随机放技能”，而是“权重 + 条件”：

- 权重：多个技能同时可放时，Boss 更倾向先放谁
- 条件：这个技能什么时候才允许进入候选

当前主动扫描已实际支持的配置字段：

- `权重`
- `施法目标类型`
- `目标选择方式`
- `最小施法距离`
- `最大施法距离`
- `最低生命百分比`
- `最高生命百分比`
- `最低魔法百分比`
- `最高魔法百分比`

推荐理解方式：

- 大招 / 终结技：高权重，但通常配合长 CD、低血量或阶段条件
- 常规主力技：中高权重，构成 Boss 主循环
- 位移技 / 召唤技 / 机制技：中权重，靠条件决定插入时机

### 6. 后续协作方式

以后如果继续做 Boss 设计、技能说明、技能本体或特效，实现流程按这个顺序走：

1. 确认 Boss 真实单位名、技能真实名字
2. 如果只有 4 位内部 ID，先反查成真实名字
3. 先补 AI 配置：
   - 目标类型
   - 权重
   - 生命 / 魔法 / 距离条件
   - 公共施法间隔
4. 再补技能本体、特效、阶段逻辑
5. 最后统一调试 Boss 的整体施法节奏

常见改动入口：

- 只补 Boss AI 配置：`03．BossAI配置表.ts`、`06．英雄BossAI配置表.ts`、`07．异界BossAI配置表.ts`
- 补 Boss 主动扫描逻辑：`02．Boss主动扫描施法/01．Boss主动扫描驱动.ts`
- 补技能本体或表现：进入具体技能系统和表现系统，不只改 AI 配置表

## 2026-05 Boss战启动属性配置补充

- `09．Boss战启动桥接/03．战斗启动属性` 目录用来集中写 Boss / 英雄Boss / 异界Boss 的战斗启动附加属性表。
- 目前按 `01．Boss战斗启动属性配置表.ts`、`02．英雄Boss战斗启动属性配置表.ts`、`03．异界Boss战斗启动属性配置表.ts` 分表维护，`04．战斗启动属性应用.ts` 统一应用。
- 战斗启动属性配置推荐优先填写 `单位ID`；`单位名` 只作为可读备注和名字反查兜底，避免被颜色码、等级后缀或重名影响。
- 当前配置表已支持一批常见启动词条：如 `魔抗`、`暴击率`、`暴击伤害`、`命中率`、`闪避率`、`魔法伤害吸血`、`魔法穿透`，以及 `剑弱 / 短剑弱 / 杖弱 / 火弱 / 雷弱 / 光弱` 等弱点布尔项。
- 当前护盾值系统、弱点数量系统的底层 TS 化迁移还没有完成。
- 现阶段在 Boss 战启动时直接写 `YDUserData` 仍然兼容旧 JASS 侧读取逻辑，可以先作为过渡方案使用。
- `默认Boss弱点数量基础值` 是共享常量；后续其他 Boss 如果沿用这套默认口径，应优先复用这个常量，而不是各自再写硬编码。
- 如果以后某个 Boss 需要特殊弱点数量，再在单个配置项里覆盖，不影响全局默认值。
