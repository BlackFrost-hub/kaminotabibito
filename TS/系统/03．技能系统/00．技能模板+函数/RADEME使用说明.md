技能模板+函数 目录说明

这个目录是技能开发的复用层。

它的作用不是存放某一个完整技能，而是把技能里反复出现的能力、流程、表现、判定与测试拆成稳定模块，方便后续继续组合、补充和扩展。

后续 AI 使用这个目录时，默认不要先造新底层。先拆技能需求，再优先从现有零件里拼组合；只有发现重复胶水代码或明确缺口时，才沉淀新模板。

这个目录当前大致分成四层：

00．技能模板
- 放偏“技能组织方式”的内容。
- 更关注一个技能由哪些阶段组成、前摇怎么接执行、引导怎么接下一段、路径类模板怎么复用。
- 现在已经包含：
  - 多阶段技能编排
  - 前摇与持续施法
  - 前摇提示工厂
  - 生效帧 / 后摇 / 收尾
  - 自我打断预留
  - 技能引导阶段
  - 技能阶段链执行器
  - 路径技能模板

01．技能函数
- 放偏“技能具体行为”的模块。
- 更关注技能能做什么动作、什么判定、什么结算。
- 当前已有的主要方向包括：
  - 弹幕
  - 冲锋 / 击退
  - 跳跃 / 击飞
  - 区域效果
  - 吸附 / 牵引
  - 施法 / 蓄力 / 充能
  - 护盾
  - 扩散伤害
  - 形状区域
  - 落点打击

02．通用函数
- 放技能开发时会高频复用、但不专属于某一个行为模块的公共工具。
- 当前主要包括：
  - 单位动画等待
  - 控制与 Buff
  - 单位与范围
  - 调试输出
  - 召唤物
  - 闪烁
  - 单位组工具
  - 无敌帧
  - 提示特效

03．技能测试
- 放各模块对应的独立测试入口。
- 这些文件主要用于验证模块行为、生成 Lua 形态和游戏内表现。
- 当前已经覆盖了充能、区域效果、动态范围、提示特效、扇形、动态扇形、冲锋路径结算、落点打击、地面路径持续区域、牵引、跳跃、冲锋击退等方向。

如何 DIY 拼技能

1. 先把技能拆成阶段

常见技能不要直接写成一坨逻辑，先拆成：

- 前摇 / 蓄力 / 引导
- 提示特效
- 主动作：冲锋、跳跃、牵引、弹幕、落点、区域持续等
- 判定：扇形、矩形、胶囊、圆形、路径区域、弹幕命中
- 结算：伤害、护盾、扩散、跳链、Buff、控制
- 表现：命中特效、音效、残影、镜头震动、进度条
- 后续阶段：再前摇、再执行、收尾

例子：

- 冲锋斩杀 = 前摇提示 -> 硬直施法动作 -> 冲锋 -> 路径矩形 / 胶囊判定 -> 伤害与命中特效。
- 跳跃砸地 = 前摇提示 -> 跳跃到点 -> 落地圆形 / 胶囊判定 -> 范围伤害 -> 落地特效。
- 多段落雷 = 前摇提示 -> 延迟落点生成 -> 每段提示圈 -> 到点伤害 -> 落雷命中特效。
- 路径燃烧 = 路径铺设表现 -> 总区域或分段区域 tick -> 持续伤害 -> 到期清理特效。
- 弹幕跳链 = 发射弹幕 -> 命中目标 -> 复用弹幕或新建弹幕跳向下一目标 -> 每跳衰减 / 命中特效。

2. 再按目录选零件

- 需要组织阶段：优先看 `00．技能模板/01．多阶段技能编排`。
- 需要前摇、蓄力、进度条、打断：看 `01．技能函数/06．施法·蓄力·充能` 和多阶段编排里的前摇 / 引导文件。
- 需要范围提示：看 `02．通用函数/09．提示特效.ts` 和前摇提示工厂。
- 需要形状判定：看 `01．技能函数/09．形状区域`。
- 需要冲锋、击退、路径结算：看 `01．技能函数/02．冲锋·击退`。
- 需要跳跃、击飞、原地顶飞：看 `01．技能函数/03．跳跃·击飞`。
- 需要吸附、拉扯、牵引断开：看 `01．技能函数/05．吸附·牵引`。
- 需要落雷、随机落点、延迟打击：看 `01．技能函数/14．落点打击`。
- 需要地面路径持续伤害：看 `00．技能模板/03．路径技能模板` 和 `01．技能函数/04．区域效果`。
- 需要弹幕、贝塞尔、回旋、弹道跳链：看 `01．技能函数/01．弹幕`。
- 需要纯闪电链 / 治疗波这类瞬时跳链：看 `01．技能函数/10．跳链`。
- 需要通用单位工具、动画等待、无敌帧、单位组处理：看 `02．通用函数`。
- 需要施加快速 Buff、清除增益/负面 Buff：看 `02．通用函数/01．控制与Buff.ts`。底层清除实现在 `TS/系统/05．Buff系统/05．Buff清除函数.ts`，按 `01．Buff表.ts` 的 `type` 前缀区分 `Buff:` / `Debuff:`。

3. 组合优先，沉淀其次

制作具体技能时，推荐顺序：

- 先在 `03．技能测试` 写一个可触发的测试文件，验证技能手感。
- 测试里允许先写少量胶水代码，把现有模块串起来。
- 如果同一类胶水第二次出现，再抽到 `00．技能模板` 或合适的 `01．技能函数` 子目录。
- 不要为了一个还没验证的设想提前做大而全的模板。

4. 成品组合应该怎么放

如果某个组合已经稳定、并且明显会复用：

- 偏“技能流程编排”的，放 `00．技能模板`。
- 偏“某类行为能力”的，放 `01．技能函数` 对应子目录。
- 偏“表现打包”的，放技能表现预设相关位置。
- 只用于验证的，放 `03．技能测试`。

不要把完整业务技能散落到通用函数里。`02．通用函数` 只放跨技能高频工具。

后续 AI 编写代码时的硬规则

- 先读 `.cursor/rules/README.md`、`.cursor/rules/GLOBAL_AGENT_PROMPT.mdc`、`.cursor/rules/agent-shared/tstl-hard-rules.mdc`，再读相关子系统文件。
- 中文文件必须按 UTF-8 处理，优先 `apply_patch` 小补丁。
- 不准为了 TSTL 去改 `fix-lua-for-pack.js`，优先改 TS 源码规避。
- JASS / Dz 回调必须用长寿命具名函数，不要传匿名闭包。
- `jass.common` / `jass.japi` API 先绑定局部别名再调用。
- 运行时逻辑不要用 `Math.*`，随机、三角、取整走 JASS 或项目封装。
- 不要随便给底层 lib 加 `@noSelfInFile`；优先 `this: void`、局部包装、局部别名。
- 改到 helper、导出函数、回调、计时器、事件、桥接后，必须 `npm run build`，并检查生成 Lua 形态。
- 测试和临时代码也要遵守这些规则。

推荐验证方式

- 新增或改动 TS 后运行 `npm run build`。
- 如果涉及回调、计时器、事件注册、导出 helper，检查 `src` 下生成 Lua 是否出现 `nil/self` 错位、冒号调用、匿名回调等问题。
- 如果是技能表现或判定，优先补一个 `03．技能测试` 文件，让地图里可以直接用聊天命令测试。
- 调试输出默认使用 `TS/lib/扩展函数/自定义扩展函数/03．调试输出.ts`。

当前缺口

基础零件已经基本齐全，可以开始按具体需求拼技能。后续主要缺的是“更好拼”的胶水层：

- 成品技能组合库：前摇提示冲锋斩、跳跃砸地、蓄力落雷、路径燃烧、弹幕命中跳链等。
- 统一配置结构：把伤害、范围、前摇、提示、命中特效、音效、冷却消耗等参数风格统一。
- 测试 / 调参工具：统一聊天命令注册、快速生成敌人、快速显示范围与命中结果。
- 复杂弹幕玩法：反弹、分裂、穿透次数、拦截规则、被技能阻挡后的标准回调。
- 表现组合预设：提示特效、命中特效、音效、镜头震动、残影打包成风格包。

这些缺口不建议一次性空做。更好的方式是先做具体技能，遇到重复代码后再沉淀。

这个目录的定位

- 它是技能系统里的“复用能力池”。
- 它既服务正式技能，也服务后续继续沉淀新模板。
- 它强调模块可以被反复组合，而不是一份逻辑只服务一次。

一句话概括

这里不是“技能成品区”，而是“技能模块库 + 技能组合层 + 技能测试层”。

当前补充说明

这份说明原本只覆盖早期技能模块。现在目录已经继续扩展，后续 AI 使用时还要注意下面这些新结构。

新增顶层目录

02．通用函数/01．便捷短函数集合
- 放跨技能、跨装备都可能复用的小型便捷能力。
- 例如“同类伤害类型”这种不属于具体弹幕、护盾、控制、DOT 的判断/映射函数。
- 不要把完整装备业务放进这里。

01．技能函数 里的新增重点模块

07．护盾
- 统一护盾系统。
- 支持通用、物理、魔法、强化，以及火、冰、雷、风、暗、光、毒等属性护盾。
- 创建属性护盾优先用 `开始属性护盾(unit, "毒", params)` 这类 API，不要在装备里自己写伤害抵扣表。
- 护盾吸收已经接入伤害修正回调；新增护盾类型后必须检查伤害类型判断是否能传到护盾结算。
- 例如“抗毒药水”就是使用 `毒` 属性护盾抵挡 2000 点毒/金属性桶伤害。

16．扩展控制
- 放眩晕、减速、恐惧、易伤、击退等控制/扩展状态能力。
- 装备或技能需要控制效果时，优先查这里和 `19．拓展效果`，不要回到 JASS 马甲施法。

19．拓展效果
- 放 DOT、HOT、buff、debuff、易伤、暗影突袭、持续恢复生命魔法等运行时效果。
- 注意：`Buff表` 只负责 UI 和规则声明，不等于实际效果已经实现。
- 持续效果必须在 tick 时检查 Buff 是否仍存在；被驱散后要提前结束并回滚属性或停止 DOT/HOT。

20．物品辅助
- 放“物品迁移时反复出现，但可以被技能复用”的工具函数。
- 已有方向包括：
  - 获取/丢弃监听
  - 持有型周期效果
  - 条件开关效果
  - 范围脉冲效果
  - 物品次数转移
- 装备技能里如果出现“持有时每秒生效”“拾取加属性丢弃回退”“物品次数转移/累计”这类逻辑，优先查这里。

21．攻击效果
- 放公共攻击效果机制。
- 适合普攻命中触发、攻击来源/目标条件、攻击者近战/远程判断、内部 CD、延迟伤害、攻击命中特效、递归防护等能力。
- 这里必须区分“纯普攻”和“技能普攻/攻击效果”：纯普攻要求 `isNormalAttack === true`，并且 `isSkillAttack/isSkillDamage` 都不是 `true`；技能造成的攻击效果不要混进纯普攻触发。
- 强化下一次/若干次普攻统一走 `04．强化普攻.ts` 的 `添加强化普攻`，支持持续时间、次数、伤害倍率、额外伤害、仅远程/仅近战、命中回调和结束回调；默认只消耗纯普攻，需要技能普攻也能消耗时必须显式传 `允许技能普攻: true`。
- 远程强化普攻如果需要临时改变原生普攻弹道，可以传 `弹道`；由于当前 JAPI 只有 Set 没有通用 Get，结束后要恢复原弹道时必须同时传 `恢复弹道`，不要假设底层能自动读回物编原值。
- `05．同目标普攻计数触发.ts` 负责“X 秒内对同一敌人纯普攻 X 次后触发额外效果”，例如 2 秒内纯普攻同一敌人 3 次后造成额外伤害，内置 CD 5 秒；默认按攻击者+目标配对冷却，也可以改成攻击者全局冷却。

04．机制组件/01．层数状态
- `05．事件叠层状态` 负责把普攻命中、造成/受到伤害、释放英雄技能、手动触发转换成可配置层数。
- 支持内置 CD、最大层数、刷新持续时间、独立持续时间、满层回调、消耗层数。
- 装备的“普攻叠层”“技能叠层”“受击叠层”“满层后下一次普攻消费”优先走这里，再组合 `21．攻击效果/04．强化普攻`。

04．机制组件/08．机制触发
- `07．战斗状态触发器` 负责进入战斗、脱离战斗、持续战斗 X 秒、战斗中每 X 秒触发。
- 默认战斗保持时间读取 `00．核心系统/03．脱战系统/00．脱战规则`：玩家英雄 18 秒，当前 Boss 10 秒，普通单位默认跟玩家英雄 18 秒；特殊需求可以通过 `主体类型` 或 `战斗保持秒` 覆盖。
- 装备的“进入战斗后每 X 秒获得强化”“脱战后获得护盾”“持续战斗 X 秒触发额外动作”优先走这里；例如“进入战斗 4 秒后下一次普攻强化”用 `持续战斗秒: 4` + `on持续战斗满足`，回调里调用 `添加强化普攻`。

04．机制组件/09．装备通用机制
- 放未来物品技能、英雄技能、Boss 技能都可能复用的状态型装备机制。
- 已有：累计承伤触发、距离伤害修正、延迟承伤、失去生命/魔法档位转换、治疗/护盾联动、控制/Debuff 联动。
- 真正修改最终伤害的机制必须走伤害修正器；普通触发/统计优先走最终伤害监听。
- 具体装备文件仍然放在：
  `TS\系统\02．物品系统\15．装备技能\00．物品`
- 装备侧可以有 `08．攻击效果` 作为配置/编排入口，但公共机制不要重复写在装备系统里。

技能函数与装备技能的边界

- `00．技能模板+函数` 是公共能力池。
- `02．物品系统\15．装备技能` 是装备业务层。
- 如果一个能力未来技能、装备、怪物 AI 都可能用，放技能函数。
- 如果只是一件装备的语义，单文件放到 `15．装备技能\00．物品`。
- 不要把一件装备的完整业务塞进技能函数目录。

物品/装备迁移时的推荐路径

1. 先判断触发来源：
- 主动使用物品：接 `15．装备技能\05．物品使用`。
- 施放英雄技能后触发：接 `15．装备技能\03．主动技能`。
- 受到/造成伤害触发：接 `15．装备技能\04．伤害事件` 或 `02．累计伤害`。
- 拾取、丢弃、持有周期：接 `06．获取丢弃` 或 `07．获得物品`。
- 普攻命中追加效果：装备侧接 `08．攻击效果`，公共能力查 `21．攻击效果`；“强化下一次/若干次普攻”直接用 `添加强化普攻`。
- 事件叠层、累计承伤、距离减伤、延迟承伤、卖血档位、治疗护盾触发、控制 Debuff 触发：优先查 `04．机制组件/09．装备通用机制`。

2. 再找公共函数：
- 治疗/回蓝：走 `TS\系统\04．伤害系统\02．治疗系统`。
- 扣血/扣蓝：走治疗系统里的资源变更/减少生命值/魔法恢复统一入口。
- 护盾：走 `07．护盾`。
- 控制：走 `16．扩展控制` 或 `02．通用函数\01．控制与Buff.ts`。
- DOT/HOT/Buff/Debuff：走 `19．拓展效果`。
- 弹幕：走 `01．弹幕`，不要手写马甲施法。
- 扩散/溅射：走 `08．扩散伤害`。
- 跳链/治疗波/闪电链：走 `10．跳链`。
- 反击：走 `13．反击`。
- 物品持有、周期、次数：优先查 `20．物品辅助`。

3. 最后写单装备文件：
- 一个装备一个文件。
- 装备名用 `01．装备数据.ts` 的 `name`，不要写 4 位 raw id。
- index 文件只做 `export *` 聚合。

伤害类型与属性护盾

- 项目伤害系统里，毒、酸、缓毒、疾病归入金/毒属性桶。
- 火、雷、暗、光、强化等已从伤害快照传到伤害修正回调。
- 护盾系统读取这些上下文来判断是否吸收。
- 如果新增更细的属性，例如单独区分“毒”和“金”，需要同时检查：
  - 伤害快照
  - 伤害修正回调 context
  - 护盾伤害结算
  - 伤害数字颜色
