# 技能模板+函数 指引

这个目录是技能开发的组合层。

它的目标不是只服务某一个技能，而是把“常见技能行为”拆成可以复用、可以拼装、可以继续扩展的模块，让后续 AI 和开发者能快速组合出新的技能效果。

## 这个目录大概负责什么

- 提供技能模板
- 提供技能执行函数
- 提供技能常用通用函数
- 为复杂技能做“模块化拼装”入口

这里适合放的是：

- 施法前摇、动作播放、等待
- 冲锋、击退、跳跃、弹幕
- 选取、范围判定、目标处理
- 技能开发常用的控制、Buff、调试、单位工具

这里不强调“一个文件只对应一个完整技能”，而是强调：

- 一个技能可以由多个模块组合出来
- 同一个模块可以被很多技能复用
- 后续可以继续新增更多模块，而不需要推翻旧结构

## 目录分层约定

### `00．技能模板`

放技能模板、技能流程骨架、偏业务侧的可复用技能片段。

更偏“怎么组织一个技能”。

### `01．技能函数`

放技能行为模块。

这里的模块通常是：

- 可以直接调用的技能行为
- 有独立目录和独立 `index`
- 可以被别的技能组合使用

例如未来可以继续扩：

- 弹幕
- 冲锋
- 击退
- 跳跃
- 拉拽
- 吸附
- 连锁
- 落雷
- 持续区域效果

更偏“技能能做什么动作”。

### `02．通用函数`

放技能开发时高频会用到、但不属于某一个具体行为模块的辅助函数。

例如：

- 控制与 Buff
- 单位与范围
- 调试输出
- 单位动画等待

更偏“技能写起来需要的公共工具”。

## 推荐使用方式

写一个技能时，优先先想“要组合哪些模块”，而不是先写一大段单独逻辑。

通常可以按这种思路：

1. 明确技能流程
2. 拆成几个行为阶段
3. 找已有模块组合
4. 不够用时，再补新的模块函数

例如一个技能可能是：

- 播放动作并等待
- 冲锋到目标点
- 选取区域敌人
- 对单位组做扩散击退
- 结算固定伤害

这类技能应优先走“组合已有模块”的路线。

## 对后续 AI / 开发者的建议

- 不要把这里当成一次性脚本堆放区
- 优先补可复用模块，而不是只为当前技能写死逻辑
- 新增模块时，尽量给它独立目录和 `index`
- 如果一个能力以后大概率还会被别的技能复用，就应该沉淀到这里
- 如果只是某个技能自己的非常特殊流程，再考虑留在技能模板或具体技能文件中

## 一句话理解

这里是技能的“模块库 + 组合层”。

它的价值不在于当前已经有多少功能，而在于后续可以持续扩展，并通过组合越来越快地制造新技能。
