# 技能模组能力规划

本文档用于整理 `TS/系统/03．技能系统/00．技能模板+函数` 当前能力覆盖情况，以及后续建议补齐的模块。

目标不是一次性做完，而是给后续 AI / 开发者一个统一的扩展顺序，避免重复造轮子或优先级失衡。

## 当前已有

当前已经具备的核心模块：

- 位移类：冲锋、击退、跳跃、牵引
- 区域类：持续区域、动态范围
- 表现类：提示特效、进度条特效、残影表现
- 机制类：充能、护盾、扩散伤害
- 通用类：控制与 Buff、单位与范围、动画等待、调试输出、闪烁、无敌帧、单位组工具

当前结构的优点是“动作模块”已经开始成形，但“完整技能流程模板”和“复杂轨迹/复杂命中规则”仍然偏薄。

完成备注：

- 已补 `扇形区域.ts`、`动态扇形.ts`、`矩形区域.ts`、`胶囊区域.ts`
- 已补对应测试：`105．扇形区域测试.ts`、`106．动态扇形测试.ts`

为什么优先级高：

- 当前提示特效已经有矩形、扇形、圆形，但玩法层主要还是圆形范围。
- 很多技能“看起来像扇形/矩形”，实际只能靠圆形近似，复用价值不够。
- 这是大量近战技能、冲击波、地裂、横扫、喷吐类技能的基础设施。

### 2. 弹道轨迹层（优先挂到 TS 弹道框架）

建议目录：

- `01．技能函数/11．弹道/01．轨迹`

建议先补：

- 二阶贝塞尔轨迹
- 三阶贝塞尔轨迹
- 圆弧轨迹
- 追踪插值轨迹
- 路径采样接口：按进度返回 `x/y/z`

为什么优先级高：

- 当前跳跃只有“水平直线 + 垂直抛物线高度”，没有 XY 平面的曲线轨迹层。
- 很多技能需要弧线突进、回旋刀、绕点飞行、蛇形飞行、回收型武器。
- 二阶贝塞尔不建议单独做成孤立系统，更适合作为 TS 原生弹道框架里的首个轨迹实现。
- 这样能直接复用弹道层已有的生命周期、命中、结束、回调管理，避免再造一套独立飞行逻辑。

### 4. TS 原生弹道框架

建议目录：

- `01．技能函数/11．弹道`

建议先补：

- 直线弹道
- 轨迹可插拔接口
- 追踪弹道
- 曲线路径接入（优先接二阶贝塞尔）
- 延迟发射
- 最大转向角 / 最大追踪时间
- 生命周期 / 穿透 / 回收 / 超时管理
- 命中、失效、超时回调

为什么优先级高：

- 当前弹幕系统更多是对旧 JASS DMXT 的封装，不是 TS 原生、可编排的弹道层。
- 如果直接把 JASS 弹幕系统的核心运行框架迁到 TS，再把轨迹层挂进去，会比“先做孤立贝塞尔、再做弹道”更省代码。
- 简单直线够用，但复杂追踪、回旋、回收、锁敌切换仍然不够顺手。
- 这一层完成后，贝塞尔、圆弧、回收型武器都能作为同一框架下的轨迹策略复用。

## 中优先级

### 5. 连锁 / 跳链执行器

建议目录：

- `01．技能函数/12．连锁效果`

建议先补：

- 跳下一个目标
- 已命中列表
- 每跳衰减
- 最大跳数
- 每跳表现回调

为什么是中优先级：

- 现在有扩散伤害，但没有真正的链式传播执行器。
- 闪电链、跳火、连锁治疗这类技能会频繁用到。
- 重要，但优先级低于形状区域和曲线路径，因为基础覆盖面没那么广。

### 6. 持续施法 / 引导系统（已完成，落在模板层）

建议目录：

- `00．技能模板/01．多阶段技能编排`

完成情况：

- 已补 `05．技能引导阶段.ts`
- 已支持：开始引导、周期回调、提前取消、被控中断、引导完成、引导结束
- 已支持：提示特效、进度条、自我打断、统一结束原因
- 已可直接作为多阶段技能中的一个阶段与前摇/执行串联

为什么是中优先级：

- 这层现在已经不再只是“充能完成触发”，而是有独立的引导阶段模板。
- 暴风雪、持续喷火、持续读条 beam、长按类技能已经有可复用入口。
- 后续若需要再下沉到 `01．技能函数` 层，可视复用密度决定是否再拆。

### 7. 位移/弹道命中规则模板

建议目录：

- `02．通用函数/10．命中规则`

建议先补：

- 首个命中
- 每单位只命中一次
- 允许重复命中
- 穿透上限
- 命中后停止 / 命中后继续
- 回程再次命中规则

为什么是中优先级：

- 这层不是新的位移系统，而是把“命中后怎么处理”抽成统一模板。
- 当前冲锋、击退、弹道、区域各自有一部分命中规则，但没有统一复用。
- 模块越来越多后，如果不统一，后面会出现很多“类似但不完全一样”的命中逻辑副本。
- 更适合在冲锋、跳跃、弹道、区域这些基础技能组合稳定后，再做统一收口。

### 8. 技能目标选择模板

建议目录：

- `00．技能模板/02．选目标模板`

建议先补：

- 单目标
- 地点目标
- 单位组目标
- 最近目标
- 最远目标
- 血量最低 / 最高
- 主目标 + 副目标

为什么是中优先级：

- 现在底层有 `getUnitsInRange`、敌友判断，但技能层缺少“可直接拿来用”的目标选择模板。
- 这会导致每个技能自己再手写一遍筛选流程。

## 低优先级

建议目录：

- `01．技能函数/14．落点打击`

已落地：

- 延迟后生效
- 多段落点
- 随机散布
- 圆形 / 矩形随机区域
- 轻度打散与最挤点重抽
- 每单位最大命中次数限制
- 命中区域与表现分离

现有测试：

- `03．技能测试/108．落点打击测试.ts`

为什么是低优先级：

- 很常见，但可以先用“延迟执行 + 区域效果 + 提示圈”拼出来。
- 有专门模块会更方便，但不是当前最卡开发效率的缺口。

## 建议实现顺序

推荐按下面顺序推进：

1. 真实形状区域判定
2. 通用曲线路径层
3. 技能阶段编排模板
4. TS 原生弹道 / 追踪弹道
5. 连锁 / 跳链执行器
6. 持续施法 / 引导系统
7. 位移/弹道命中策略库
8. 技能目标选择模板
9. 其余低优先级模板与表现预设

## 一句话总结

当前技能模组已经有“动作模块”的雏形，但还缺：

- 更真实的玩法判定
- 更强的轨迹表达能力
- 更通用的技能流程骨架

后续优先补“基础层”，再补“花样层”，这样复用价值最高。
