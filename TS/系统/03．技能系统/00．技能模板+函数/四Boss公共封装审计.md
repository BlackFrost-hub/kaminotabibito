# 四 Boss 公共封装审计

本文档记录以下四套规划反推出的公共能力，供正式实现 Boss 与奖励装备时索引：

- `01．主线Boss/08．沉睡英魂亚伦柯斯`
- `02．挑战与隐藏Boss/06．祖地双灵卫`
- `03．异界Boss/03．安兹乌尔恭`
- `03．异界Boss/04．夏提雅`

目标是复用稳定的流程、状态和行为，不把具体 Boss 语义塞进公共层。

## Boss 对应关系

### 沉睡英魂亚伦柯斯

- 普通轮转使用战斗技能调度模板；血量阶段继续组合现有阶段上下文和血量节点触发器。
- 亡冥英斩、归魂回斩、英灵陨星分别组合现有路径、延迟命中和落点模板，不新增亚伦柯斯专属底层。
- `旧誓残响徽记`使用不同技能序列状态，作用域选“主体”，重复策略选“忽略”。
- `亡者凝视面甲`复用方位判定、伤害修正与下一次普攻强化。
- `安魂守墓灯`复用治疗护盾联动与延迟状态结算。

### 祖地双灵卫

- 两名守卫各自保留冷却与运行状态，但共享技能互斥锁。
- `断誓践踏 -> 约 2 秒缓冲 -> 失名祷潮`和封门校验使用固定组合技能执行器，整条时间轴期间禁止随机技能插入。
- 两名守卫登记进同一个联合成员生命周期，且都标记为参与最终结算；第一名进入崩解不能触发 Boss 奖励，只有双方都进入配置的最终状态才收束。
- `苍影校魂法典`使用不同技能序列状态，作用域选“主体与目标”，从而只在两个不同技能命中同一目标时就绪。
- 位移后强化、低血触发、重复伤害适应和治疗护盾联动均已有公共模板，不再新增同义组件。

### 安兹乌尔恭与雅儿贝德

- 两套 AI 调度器共享技能互斥锁和可抢占独占状态管理器。
- `守护者之职责`使用低优先级、可抢占状态；任意正常技能开始时先静默清理职责连接，再无阻塞释放新技能。
- 时间停止后的固定结算顺序使用固定组合技能执行器，不把多个延迟回调散落在技能文件。
- 安兹登记为主目标并参与最终结算；雅儿贝德登记为护卫，可锁血、倒地或离场，但不单独触发挑战完成。
- 伤害分担复用现有友军范围承伤转移或其底层伤害标记，必须继续防止转移递归。
- 三件奖励装备分别复用引导流程、单次承伤门槛和伤害转移能力，无需再加新的基础组件。
- 高阶魔法箭改用分批点名落点模板；每轮开始时重新取得有效目标并锁定坐标，Boss 清理时统一取消尚未结算的轮次。
- 安兹运行时上下文改为监听现有 Boss 自动技能启动注册表，不再每秒自行扫描全部 Boss。

### 夏提雅

- 普通技能轮转使用战斗技能调度模板；同目标三次纯普攻继续使用现有同目标普攻计数触发器。
- 英灵战乙女的延迟复刻和镜像夹击使用固定组合技能执行器，确保复制动作不会启动第二套随机 AI。
- `英灵战乙女蔷薇镜`使用不同技能序列状态，作用域选“主体”；就绪后由下一次符合条件的技能伤害消耗。
- 血晶使用事件叠层/Buff 层数状态，低血时消费并组合护盾与攻速效果。

## 本轮新增判断

### 可以立即公共化

- **分批点名落点：**至少被安兹高阶魔法箭、亚伦柯斯英灵陨星和夏提雅净化投枪复用。公共层只负责每轮重新取目标、轮换点名、坐标快照、提示圈、延迟结算与取消；伤害、特效和 Boss 阶段仍由调用方处理。
- **既有模板组合优先：**同批点名继续使用 `点名预警结算模板`，预先确定坐标的静态波次继续使用 `多波延迟AOE`；只有“轮次开始时才重新选目标”的技能使用新模板。
- **现有注册表扩展优先：**Boss 启动上下文绑定直接扩展 `Boss自动技能注册表` 的监听接口；安兹、巴尔扎罗斯和菲尼克斯尔共用该入口，不另建第二份启动绑定器或周期扫描器。

### 续审后必须优先复用的既有能力

- **Buff 层数状态：**`04．机制组件/01．层数状态/06．Buff层数状态.ts` 已经存在，Boss 阶段层数、血晶、侵蚀和誓约等需要同步 Buff UI 的状态直接复用，不列为本轮新增能力。
- **站圈进度：**亚伦柯斯墓碑安魂、夏提雅血印主动净化和类似“进入范围持续一段时间后完成”的机制，直接使用 `04．机制组件/08．机制触发/06．单位停留触发器.ts`。具体 Boss 只负责中心单位、半径、进度表现、完成反馈和离开后的回退规则；不要在 Boss 文件里私有轮询玩家坐标。
- **限时摧毁目标：**夏提雅血之复生结晶、安兹黑翼拘束核心、生命锚点封锁屏障等“生成若干可攻击目标，限时全部摧毁或按剩余数量结算”的机制，优先组合 `04．机制组件/05．机制单位/02．限时摧毁目标组.ts` 与 `可攻击机制单位`。耐久、目标数量、失败后恢复比例留在 Boss 配置。
- **伤害分担与递归防护：**安兹与雅儿贝德的守护者之职责、黑翼守护重盾装备，先复用 `04．机制组件/09．装备通用机制/20．友军范围承伤转移.ts` 的修正入口；Boss 侧只补直接伤害过滤、双方候选、转移伤害标记和表现。不要在技能文件里绕过伤害系统手动扣两边生命。
- **持续连接表现：**双灵同誓、守护者之职责、鲜血回收、失名祷潮牵魂线优先使用 `04．机制组件/07．机制连线/01．持续单位连线.ts`。连接能否阻挡、分担、牵引属于调用方语义，公共层只管连线生命周期和清理。
- **同目标普攻计数：**夏提雅滴管长枪三连与奖励长枪的三连汲血，应先搜索并复用现有同目标普攻计数触发器；只有确认其无法表达“换目标、超时、控制中断、枯竭保护”后，才在装备通用机制里小幅扩展。
- **单位状态与短时数值：**夏提雅鲜血枯竭、雅儿贝德失衡、安兹大招回落窗口、双灵卫节点净化阶段，优先用 `单位时限标记`、`单位时限数值`、`单位战斗状态托管` 或 Boss 专属状态表组合，不新增同义状态容器。

### 不再新增模板的明确场景

- **普通冲锋斩 / 路径伤害：**亚伦柯斯亡冥英斩、夏提雅滴管穿心、雅儿贝德至尊拦截、双灵卫誓锋壁进都应由前摇提示、战斗自身位移封装和线性扫掠/路径结算组合实现。虽然技能很多，但底层零件已经存在，不需要再做一个“Boss 冲锋技能模板”。
- **延迟镜像与固定复刻：**夏提雅英灵战乙女、安兹时间停止、双灵卫封门校验和双钥净化都属于固定时间轴，继续使用 `固定组合技能执行器` 与阶段链延迟阶段。不要为每个 Boss 建私有计时器串。
- **奖励装备的“不同技能充能”：**亚伦柯斯旧誓残响徽记、夏提雅蔷薇镜、双灵卫苍影校魂法典均使用 `不同技能序列状态`，通过作用域和重复策略区分，不新增三套装备私有充能表。

### 暂不公共化

- **普通形态与变异形态换模：**双灵卫和夏提雅都需要形态变化，但一个可能替换单位、一个可能切模型；在仇恨、Buff、技能冷却和动画继承方案确定前不抽象。
- **定向屏障：**苍影誓盾、雅儿贝德屏障和其他防御罩的判定分别涉及正反面、伤害吸收或单位阻挡，目前只共享几何与清理工具，不建立统一业务模板。

## 不应公共化

以下内容仍属于具体 Boss 业务，不能为了“复用”硬塞进公共层：

- 亚伦柯斯的誓约墓碑、安魂进度和剧情挑战媒介。
- 双灵卫的侵蚀择形、双钥净化、封门误判具体规则。
- 安兹的时间停止世界规则、一切生命的终点破解条件和挑战台词演出。
- 夏提雅的鲜血印记净化、血宴层数、复生结晶和挑战入口。

公共层只负责调度、预约、状态、生命周期和可组合行为；数值、资源、台词、阶段语义与最终结算仍留在各 Boss 配置和技能文件。
