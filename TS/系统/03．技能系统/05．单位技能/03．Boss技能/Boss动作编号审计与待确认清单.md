# Boss 动作编号审计与待确认清单

本文档记录旧 Boss 技能动作的代码现状，供后续与安兹·乌尔·恭、夏提雅、沉睡英魂亚伦柯斯、祖地双灵卫四套 Boss 的实际落地代码一起集中处理。

## 判定口径

- 配置表中存在动作编号，只能证明代码会读取该编号，不能证明编号经过用户确认。
- 没有用户截图、口述或模型序列实测记录的编号，一律标记为“来源未记录 / 待复核”，不能继续当作权威动作映射复制到新 Boss。
- `SetUnitAnimationByIndex` 中除恢复默认姿态 `0` 外的数字属于硬编码，后续必须迁移到对应 Boss 的数值与表现配置。
- 被动光环、伤害修正、层数状态、拾取物和纯场地后台 Tick 可以没有施法动作；主动技能、召唤、引导、反击、阶段转换和大招必须检查动作时点。
- 动作确认时同时记录编号、模型路径、动作含义、持续时间、建议倍速、生效帧和恢复时点。
- 原始时长统一从正式 `.mdx` 的 `SEQS` 区块读取，计算方式为 `(IntervalEnd - IntervalStart) / 1000`，保留到毫秒；不得只看模型查看器截图估算。
- 同时记录 `SEQS` 循环标记。循环攻击或施法动作接入运行时时，必须明确恢复动画和恢复时点，不能假设动作会自动回待机。
- `原始时长秒` 只描述模型序列本身；技能硬直、实际播放窗口和 `动画速度` 分开配置，不能互相替代。
- 本轮已重新解析并核对：米亚、瑟兰迪尔、巴尔扎罗斯、菲利斯常态/异形、卡瑟拉、莫尔特斯；更早记录的安兹、雅儿贝德、夏提雅常态/女武神、亚伦柯斯、双灵卫四模型时长也已与正式 MDX 复核一致。

## 与四套新 Boss 一起处理

后续处理批次包含：

1. 安兹·乌尔·恭与雅儿贝德。
2. 夏提雅·布拉德弗伦。
3. 沉睡英魂亚伦柯斯。
4. 祖地双灵卫。
5. 本文档列出的十套旧 Boss 动作修正。

处理顺序：

1. 先确认技能实际使用的正式模型，双形态、护卫和双 Boss 必须分模型记录，禁止串用动作表。
2. 对照用户截图/口述与模型序列，记录动作编号、持续时间和真实生效帧；来源不明的现有编号逐项重新验证。
3. 将所有技能动作、倍速、恢复延迟和必要的重复播放间隔集中到各自 `02．数值与表现配置.ts`。
4. 删除技能文件中的非默认姿态数字硬编码；恢复默认姿态也优先读取统一动作配置。
5. 主动技能在前摇开始时播放动作，命中/结算帧与模型动作对齐；长引导需要按动作时长决定冻结、循环或重播。
6. 被动与后台机制不为了“看起来都有动作”强行打断普攻；只给玩家可感知的召唤、阶段、大招和反击流程补动作。
7. 每完成一个 Boss 后构建，并检查对应生成 Lua 的动画参数和回调时点；最终通过实机验证，不以模型预览器单独作为结论。
