# 安兹乌尔恭技能复盘

## 伤害类型

- 问题：现实断裂、高阶魔法箭、时间停止和天空坠落使用了 `ATTACK_TYPE_MAGIC` 提交技能伤害。
- 原因：把原生攻击类型误当成项目的魔法伤害分类。
- 结论：统一技能链路使用 `ATTACK_TYPE_NORMAL`，具体伤害分类继续由原有 `DAMAGE_TYPE_*` 决定。

## 心脏掌握与高阶魔法箭黑底

- 问题：`AinzHeartCountdown.mdx` 的心脏面片和 `AinzUndeadArrowVolley.mdx` 的箭身面片在 1.27 实机显示为黑色矩形，透明背景没有生效。
- 原因：两张 BLP 回读后均有完整 Alpha，但对应私有贴图层最初使用了 `Blend`；改为 `Transparent` 后黑底仍存在，进一步确认贴图是插件直通编码的 `compression=1 / pictureType=5`，插件可回读但 Warcraft 1.27 实机没有正确应用 Alpha。
- 结论：私有贴图层保持 `Transparent`，贴图改由内置原生转换器输出 `compression=0 / alphaBits=8 / pictureType=4`；生成脚本同时校验材质和 BLP 头。以后遇到整块黑底时必须同时检查 BLP 实机兼容格式与 MDX 材质，插件回读透明不能单独作为结论。

## 心脏掌握读秒与点名提示

- 问题：十二个刻度使用线性 Alpha 插值，已熄灭刻度在读秒过程中出现半透明残留或恢复，玩家无法清楚判断剩余时间。
- 模型修复：仅将十二个刻度的 Alpha 轨道改为 `DontInterp` 离散显隐；心脏本体和外圈的出生、死亡淡入淡出保持线性。回读 MDX 确认 12 条刻度轨道的 `interpolationType` 均为 `0`。
- 表现修复：胸口骨爪点名层按原模型 `2` 倍显示，处决层按原模型 `6` 倍显示，缩放集中在安兹数值与表现配置中。
- 提示修复：点名真正生效时通过 `QuestMessageBJ(..., bj_QUESTMESSAGE_WARNING, ...)` 向全队显示玩家名、技能名、倒计时、救援范围和失败处决效果，同时播放原生任务警告音；不额外创建或播放私有音效句柄。
- 音效定位：私有 `ainz_grasp_heart.mp3` 不再于施法者坐标单次播放；点名生效后改为目标坐标立即播放一次，倒计时每 `1` 秒重复一次，并由实例清理统一取消周期回调。
- 表现叠加：保留 `AinzHeartCountdown.mdx` 的十二秒读秒层，并叠加 `AinzHeartGraspCountdownRing.mdx`。后者不走 `origin` 绑定，而是在被点名目标的当前坐标每 `1` 秒重建一次，缩放 `0.20`、单次持续 `1` 秒并播放 `0` 号动作，避免移动时脱离目标且不积累特效句柄；倒计时失败时，`AinzHeartGraspExecutionBurst.mdx` 在目标结算瞬间的当前坐标创建，缩放为原先的 `50%`。爆发不再挂目标 `chest`，避免随单位胸口骨骼偏移或在死亡时丢失落点。

## 现实断裂路径表现

- 问题：旧实现只在整条路径中点播放一次静态空间切面，表现没有沿结算路径移动，命中反馈也无法区分路径主体和目标命中层。
- 修复：复用 TS 原生弹幕的固定起终点轨迹，让图 1 路径主体按预警锁定方向移动；技能开始时记录可命中的敌对英雄，每个目标最多结算一次。
- 叠加关系：图 2 只在目标命中坐标额外播放，必须叠加在图 1 路径主体上，不能取代图 1。
- 颜色：图 1 使用真实 RGB `255 / 8 / 255`，图 2 使用 `255 / 255 / 255`。模型预览器虽然按 `R / B / G` 展示输入项，TS 与 JAPI 仍必须按真实 `R / G / B` 字段传递。
- 预警坐标：矩形提示底层把传入坐标视为路径起点，并自行前移半个长度得到模型中心；调用方不得预先传中点，否则预警会沿技能方向额外偏移半条路径。
- 模型朝向：`AinzRealityFractureMovingSlash.mdx` 的视觉正向与需求相反，只通过原生弹幕附加特效的 `朝向角偏移: 180` 翻转模型，不得反转弹幕移动方向或伤害路径。
- 命中层角度：`AinzRealityFractureHitSlash.mdx` 每次命中都用 JASS `GetRandomReal(0, 360)` 独立随机角度，不继承路径主体或 Boss 面向。
- 音效时机：现实断裂技能音效与路径主体实际发射使用同一个 `on生效` 节点；预警阶段只播放台词，不提前播放发射音效。
- 载体：现实断裂保留默认 `eaaa` 单位载体，附加特效只承担视觉；单位壳移除蝗虫并设置弹幕生命，因此可被攻击摧毁，也可进入按单位识别的反弹链路。不得把该技能切成纯特效载体。

## 高阶魔法箭音效与死亡序列

- 音效时机：模型内部七支箭的落地关键帧为 `510 / 620 / 740 / 860 / 990 / 1120 / 1250ms`；配套 MP3 长 `450ms` 且 `0ms` 已有明显波形。因此音效在第一轮箭阵特效创建后延迟 `0.51` 秒播放，使音效起点对齐第一支箭落地；不额外叠加落点预警时间。延迟回调登记到 Boss 清理篮子，台词仍在前摇阶段播放。
- 模型问题：`AinzUndeadArrowVolley.mdx` 原 `Death` 序列持续 `500ms`，三层箭体 Alpha 在该区间渐隐，导致落地结算后仍显示横躺箭阵。
- 模型修复：`Death` 改为 `3000-3001ms`，三层 Alpha 在 `3000ms` 首帧直接为 `0`，所有复用该模型的结算都会直接消失。

## 高阶亡灵召唤模型

- 人物主体使用 `Unit\\Summon\\T13ScourgemaleDeathKnight.mdx`；单位壳从英雄类型 `Udre` 改为非英雄近战类型 `hfoo`，继续承载移动、攻击和单位识别，避免召唤物显示为英雄。
- 模型缩放从 `1.15` 调整为 `2.3`，即在原显示尺寸上扩大 `100%`。
- 主体模型与 `_Portrait` 肖像共同迁入 `imports\\Unit\\Summon`，三张私有贴图统一放入共享 `Texture`，模型内部私有路径同步改写；原生 `Textures\\...` 与队伍色槽保持不变。

## 时间停止结算表现与提示

- 问题：时间停止内部保留了旧的静态 `AinzRealityFracture.mdx`，与普通现实断裂已经升级的路径移动和随机命中叠加表现不一致；魔法箭预警也没有安排对应技能音效。
- 修复：时间停止直接复用普通现实断裂的具名移动入口，继续使用可攻击、可反弹的 `eaaa` 弹幕载体，并在每个目标命中时播放随机角度命中层；时间停止魔法箭也从箭阵特效出现时复用普通技能的 `0.51` 秒延迟音效安排。
- 提示：原 `4.4` 秒合并进度条拆为 `2.8` 秒“时间停止前走位”和 `1.6` 秒“时间停止中”两段，文本明确说明解冻后立即开始伤害结算。
- 尺寸：持续钟面和齿轮碎片均在原配置基础上扩大 `60%`，缩放分别为 `2.24` 与 `1.76`。
- 动作与硬直：原实现虽然调用了限时 `5 channel` 动作，但没有给 Boss 本人施加真实硬直，动作可能被移动或攻击覆盖。现在按项目既有成对写法，在完整时间停止序列期间调用 `开始硬直`，动作与硬直使用同一总时长。

## 光辉翠绿体颜色

- 问题：技能直接手算 `80 * 65536 + 255 * 256 + 120` 作为顶点色，缺少 Alpha 通道，`BigYellowOrbShield.mdx` 实机仍显示金黄色。
- 修复：通用特效封装新增 `设置特效颜色`，内部统一使用 `DzGetColor(alpha, red, green, blue)` 组装完整颜色；光辉翠绿体从配置读取 `RGB 80 / 255 / 120`，Alpha 默认 `255`。
- 二次修复：实测确认普通特效实例可以正确染为翠绿，但不采用 `AddSpecialEffectTarget` 或 `DzBindEffect`。最终复用 `创建单位坐标跟随特效`，由中心计时器每 `30ms` 按 Boss 坐标刷新特效位置，并用专属跟随键统一销毁。
- 实机调参：坐标跟随特效高度暂定 `200`，模型缩放调整为 `1.5`（相对原尺寸扩大 `50%`），均集中在安兹数值与表现配置中。

## 天空坠落落地与余波

- 问题：冲击特效创建后立即结算全部伤害，早于模型主体真正落地；模型落地后的循环余波没有对应伤害。
- 模型依据：`AinzFallingSkyImpact.mdx` 的 `Stand` 序列为 `4000-5000ms`，`Descent` 骨骼在 `4200ms` 位于高度 `1000`、到 `4700ms` 降至高度 `20`，因此以特效创建后 `0.70` 秒作为首次落地；该序列每 `1.00` 秒循环一次。
- 修复：引导完成时创建光柱和冲击特效，并锁定当时未进入墓碑阴影的目标；模型视觉于 `0.70` 秒首次落地，主伤害及贯穿音效额外延后 `0.10` 秒、即特效创建后 `0.80` 秒结算；随后余波仍按模型 `1.00` 秒循环节奏结算两次。
- 数值：原总预算 `250% Boss攻击力 + 95%目标最大生命` 不变，拆分为主伤害 `200% + 75%`，两次余波各 `25% + 10%`。延迟回调全部登记到 Boss 清理篮子。
- 落点：当前测试命令与正式调度共用同一入口，均以释放瞬间 Boss 所在位置生成法阵、墓碑与安全区，并在引导完成时于 Boss 位置生成冲击；没有固定测试目标，也没有随机选择玩家脚下。
- 视觉调参：天空法阵、光柱和墓碑分别以原有配置缩放为基础扩大 `50%`；冲击模型扩大 `100%` 并抬高 `200` 高度，首次与后续循环余波均沿用同一实例高度。安全区提示保持原判定半径，避免视觉放大后误导躲避范围。

## 黑翼拘束单人控制

- 问题：多人分支会暂停被点名者，单人分支只创建可攻击的核心和黑翼特效，没有实际限制，拘束核心成为纯视觉单位。
- 修复：单人时由配置施加 `70%` 攻击与移动减速，持续到天空坠落结束；核心死亡或销毁时立刻解除。
- 清理约束：快速减速使用共享 `C007` Buff。清理时先确认当前运行记录仍为本次黑翼拘束创建，只有匹配才移除，避免核心死亡误清之后施加的其他减速。
- 表现补全：所有被拘束目标都会获得不可驱散的“黑翼拘束” Debuff；其 Buff 特效以 `origin` 挂载 `AlbedoWingBindChains.mdx`，和既有黑翼外壳、可攻击核心叠加。核心死亡、销毁或天空坠落结束时按同一生命周期清除 Buff 与锁链。
- BuffUI 图标：`BAZ2` 改用 `BuffIcon\\Boss\\AinzOoalGown\\black_wing_restraint.blp`；资源为 `64x64` 的 Warcraft III 黑铁边框图标，中心为黑翼、暗金锁链与红色拘束核心，替代语义不符的原生蛛网图标。

## 生命锚点激活进度

- 问题：一切生命的终点的生命锚点只有地面范围和最终激活提示，玩家无法判断连续停留 `0.8` 秒的实时进度。
- 修复：复用世界坐标进度 UI，在每座锚点上方显示当前范围内玩家的最高连续停留秒数；UI 使用现有单位停留触发器的同一轮刷新结果，不另起计时器或复制范围判定。
- 生命周期：进度条初始隐藏；进入范围时显示，离开范围重置为 `0` 并隐藏，锚点被封锁、激活完成或技能清理时销毁，避免残留 Frame。

## 生命锚点循环表现与封锁锁链

- 地面环：`RingOfBright.mdx` 复用现有循环点特效封装，每座锚点在 `0 / 4 / 8` 秒创建三次；十二秒到期、锚点提前清理或 Boss 进入挑战收束时停止，避免常驻单实例没有重新播放 `Birth`，也不在 Boss 死亡后继续创建后续轮次。
- 圣光层：`AinzLifeAnchorHolyAura.mdx` 缩放从 `1.25` 调整为 `3.0`，即相对原始模型尺寸扩大 `200%`。
- 封锁外观：生命锚点封锁不再复用雅儿贝德共同护盾模型，改为 `AlbedoWingBindChains.mdx` 的 `origin` 锁链层，缩放 `1.2`；护盾生命、可击破性和破碎回调保持原逻辑。

## 女妖哭嚎路径叠加表现

- 问题：女妖哭嚎原本只有八向瞬时灰黑死亡波，路径推进过程较弱，难以辨识死亡波的扩散轨迹。
- 修复：导入 `AinzBansheeWailDesecrate.mdx`，在八个方向叠加紫黑腐蚀灵焰；每条路径长度 `1600`，段间距 `160`，每 `0.1` 秒创建一段。
- 底层：新增纯表现封装 `创建逐段直线路径点特效`，只负责按方向分段创建点特效，不借用伤害、区域或弹幕机制。
- 清理：挑战结束时停止尚未铺设的段；已创建的特效按自身 `1.5` 秒生命周期自然销毁。

## 雅儿贝德冲锋路径附加特效

- 范围：雅儿贝德的至尊拦截、守护回归、护卫反击和时间停止冲锋四条路径全部走同一个护卫专用冲锋表现入口，不保留绕过入口的直接 `开始冲锋` 调用。
- 表现：`AlbedoGuardianChargeTrail.mdx` 在冲锋起点立即创建，并在整个有效位移期间每 `0.05` 秒于雅儿贝德当前坐标继续创建一次；每个实例独立持续 `0.35` 秒，因此形成连续的紫色路径拖尾，而不是只在技能开始时播放单个特效。
- 资源：模型与六张私有贴图均来自 `MapTest\\file_000927` 依赖链；源模型 SHA-256 为 `0CFD8D73DB11FF56`，重写贴图路径后的正式模型 SHA-256 为 `5C4C152928C8B088`。模型内部贴图已统一改写到 `Common\\Effect\\Form\\Charge\\Texture`，校验结果无 errors/severe。

## 雅儿贝德护卫反击

- 崩溃根因：护卫冲锋表现层导入的 `开始冲锋` 与 `获取单位当前位移ID` 缺少 `this: void`，TSTL 将普通函数误编译为带接收者调用，生成了 `开始冲锋(nil, 单位, 参数)`；底层收到的参数整体错位，读取空参数的 `角度` 时崩溃。修复只收紧本地导入签名，生成 Lua 已恢复为 `开始冲锋(单位, 参数)`，未改底层位移接口。
- 反击语义：两秒正面守势期间，敌方一次直接普攻或技能伤害达到雅儿贝德最大生命 `4%` 后触发；目标超过 `220` 距离时先向其冲锋，冲锋上限 `280`，随后延迟 `0.3` 秒结算 `110% 攻击力 + 2% 目标最大生命` 的单体伤害。
- 测试命令：`14-2` 默认让伤害来源站在雅儿贝德正面 `270` 距离，再造成恰好 `4%` 最大生命的测试伤害；该距离必定越过 `220` 阈值并保留约 `50` 距离的可见冲锋，不用于改动正式技能数值。
- 命中表现：反击伤害成功提交后，在攻击者当时坐标叠加 `Common\\Effect\\Form\\Explosion\\AlbedoGuardianCounterHit.mdx`。资源保留四段原始 `Birth`，补齐安全 `Stand / Death` 与序列起始轨道，模型检查为 `errors=0 / severe=0`。
- 冲锋朝向与动作：至尊拦截和守护回归都在预警锁定路径时、冲锋真正开始时各调用一次 `立即设置单位朝向`，同步原生面向与扩展面向，避免沿新路径移动时保留旧动作朝向；两者只在冲锋阶段统一播放雅儿贝德动画 `9`，不再让至尊拦截从预警期提前播放冲锋动作。
- 冲锋路径预警：`方向直线` 提示封装把传入坐标定义为路径起点，并会在底层自行前移半个长度到模型中心。至尊拦截和守护回归必须传雅儿贝德锁定时的 `startX / startY`；传起终点中点会造成二次前移，使白色路径从单位身前错开。
- `14-2` 阈值：测试伤害仍以普通攻击事件进入反击过滤，但伤害类型改为 `DAMAGE_TYPE_UNIVERSAL` 绕过雅儿贝德护甲，并按正面守势承伤倍率反推输入伤害。当前 `40%` 承伤倍率下输入 MaxHP `10% + 1`，最终伤害刚超过 MaxHP `4%`，稳定覆盖实际触发条件。
- 护卫反击硬直：守势开始时施加与窗口一致的 `2` 秒真实硬直；若触发反击，先清除本次守势剩余硬直，避免通用硬直占用导致冲锋系统判定“存在其他暂停”并中断，再由冲锋自身接管最多 `0.25` 秒位移暂停。冲锋结束或无需冲锋时重新施加 `0.65` 秒硬直，覆盖 `0.3` 秒延迟结算与攻击动画收尾。
