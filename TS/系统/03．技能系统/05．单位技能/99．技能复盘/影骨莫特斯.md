# 影骨莫特斯技能复盘

## 阴影穿梭施法函数导出异常

- 问题现象：旧测试命令 `影骨莫特斯` 后输入 `1`，运行时在 `03．阴影穿梭.lua` 调用 `开始影骨莫特斯常规施法` 时报告 `attempt to call a nil value`。
- 根因：`03．阴影穿梭.ts` 已从 `11．公共工具.ts` 导入该函数，且 TS 源中的导出存在；但增量构建只刷新了调用方，没有同时刷新被修改的公共工具文件。运行时加载的旧版 `11．公共工具.lua` 没有该导出字段，因此调用方得到 `nil`。这不是技能参数错位或 `self/nil` 调用形态问题。
- 涉及文件：`03．阴影穿梭.ts`、`11．公共工具.ts`、`03．阴影穿梭.lua`、`11．公共工具.lua`；排查入口包含 `09．技能入口.ts`、`16．影骨莫特斯AI.ts` 和 `影骨莫特斯Boss技能测试.ts`。
- 修改内容：本次未改动已有 TS 业务源；使用局部构建同时编译 `03．阴影穿梭.ts` 与 `11．公共工具.ts`，使调用方和模块导出重新同步。未修改 `scripts/fix-lua-for-pack.js`，未手动打包地图。
- 复用封装：`11．公共工具.ts` 的施法包装继续复用 `开始硬直` 和 `显示常规技能吟唱条`；技能入口、AI 调度和测试命令保持现有结构。
- 构建验证：`npm run build:files -- "TS/系统/03．技能系统/05．单位技能/03．Boss技能/02．挑战与隐藏Boss/05．影骨莫特斯/03．阴影穿梭.ts" "TS/系统/03．技能系统/05．单位技能/03．Boss技能/02．挑战与隐藏Boss/05．影骨莫特斯/11．公共工具.ts"` 成功；`fix-lua-for-pack` 更新 `0` 个文件，Lua 同步完成。生成 Lua 已确认公共工具导出存在，调用方以普通函数形态调用。
- 测试命令：选择命令已从 `Boss影骨莫特斯` 改为 `Boss莫特斯`；`Boss名称` 仍保留 `影骨莫特斯`，只影响提示文本，不改变单位或技能配置。
- 待实测：尚未进图验证。需要通过 Warcraft VSCode `Run Map`，输入 `Boss莫特斯` 后输入 `1`，确认不再报错，并观察硬直、吟唱条、透明、无敌、位移和背刺准备是否完整生效。
- 可复用经验：新增或修改模块导出函数时，`build:files` 必须同时传入导出方和调用方的实际修改 TS 文件；只刷新调用方会留下旧 Lua 模块表，最终表现为运行时 `nil` 导出。

## 背刺成功后的血月特效

- 问题现象：测试命令 `1` 的下一次纯普通攻击命中后，即使目标正面朝向莫特斯、仅触发正面减伤，仍然会创建背刺血月特效。
- 根因：血月特效原先只判断“背刺准备后的普攻命中”，没有复用 90 度背刺判定区分正面命中与真正背刺。
- 修改内容：保存 `目标正面朝向来源` 的结果；保留正面命中的 `正面减伤比例`，仅在非正面命中、即背刺成功时创建 `背刺命中血月` 特效。爪痕特效和背刺音效保持原有命中反馈。
- 复用封装：继续使用 `目标正面朝向来源` 和 `创建点特效`，未新增公共函数或重复角度计算。
- 构建验证：`npm run build:files -- "TS/系统/03．技能系统/05．单位技能/03．Boss技能/02．挑战与隐藏Boss/05．影骨莫特斯/03．阴影穿梭.ts"` 成功；`fix-lua-for-pack` 更新 `0` 个文件，Lua 同步完成。
- 待实测：尚未进图验证。需分别让固定测试目标正面和背面承受命令 `1` 强化后的下一次普攻，确认正面只有普通背刺命中特效，背面才出现血月特效；同时确认正面减伤仍为配置值 `0.5`。

## 施法表现审查

- 阴影穿梭和暗影禁锢会在施法开始前面向锁定目标；阴影穿梭的消失、无敌和现身仍按同一目标运行，暗影禁锢的圆形预警与结算使用同一坐标快照。
- 阴影穿梭、骸骨召唤、暗影禁锢、幽影爆发和盗贼的遗产均已接入统一常规施法封装，使原有动作窗口同时具备 Boss 硬直和吟唱条。
- 幽影爆发、骸骨召唤和盗贼的遗产属于中心展开或分批召唤，不存在需要朝某个玩家锁定的直线方向；未强行添加无意义转向。
- 测试命令现按阶段覆盖骸骨召唤：`2` 为 P1 基础、`2-2` 为 P2、`2-3` 为 P3 强化。P1/P2 召唤组全灭后会重组骸骨战士，P3 明确不再重组；命令处理会同步设置 Boss 实际生命比例和运行时阶段。
- 影骨的背刺准备、幽灵形态和暗影强化都由 `1`、`4`、`2`/`2-kill` 的正式技能链自然产生，没有独立的“纯被动空命令”。
- 本 Boss 当前没有矩形/方向直线提示调用，未发现“中心点误传为路径起点”的风险点。
- 待实测：需要进图观察各技能读条与第一批召唤/领域表现的时点，并确认阴影穿梭清理时能恢复可见和可受击状态。

## 骸骨召唤快速击杀测试命令

- 问题现象：普通命令 `2` 会按 3 秒时间线分批召唤骷髅盗贼；验证“全部死亡后 3 秒重组骸骨战士”时，必须等待召唤完成后再手动逐个击杀，测试路径过长。
- 根因：正式 `04．骸骨召唤.ts` 已具备召唤物创建、死亡掉落、死亡计数和阶段一/二重组能力，但莫特斯测试入口没有直接创建同一召唤组并批量死亡的命令。
- 涉及文件：`04．影骨莫特斯Boss技能测试.ts`、其生成 Lua；正式复用链路为 `04．骸骨召唤.ts` 的 `创建影骨召唤物`、死亡回调和重组调度。
- 修改内容：新增自定义命令 `2-kill`。它绕过吟唱，立刻在 Boss 周围创建 4 个骷髅盗贼并组成正式召唤组；2 秒后由模块级具名回调逐个调用 `KillUnit`。死亡后的符咒掉落、P1/P2 的 3 秒骸骨战士重组和 P3 停止重组都继续走正式逻辑。重复输入时会先终止上一组测试骷髅的重组资格并击杀其存活成员，避免堆积；延迟回调登记到 Boss 上下文清理篮子。
- 复用封装：复用 `创建影骨召唤物`、`极坐标X/Y`、`addDelayedCallback`、`Boss测试单位存活` 和上下文的 `登记延迟回调`，未复制正式召唤物的死亡、符咒或重组实现。
- 构建验证：`npm run build:files -- "TS/系统/12．测试系统/01．Boss测试/02．挑战与隐藏Boss/04．影骨莫特斯Boss技能测试.ts"` 成功；`fix-lua-for-pack` 更新 `0` 个文件，Lua 同步完成。已检查生成 Lua：`2-kill` 已注册，2 秒回调是具名函数，`创建影骨召唤物`、`addDelayedCallback` 和 `KillUnit` 均未出现 `nil/self` 参数错位。
- 待实测：需进图输入 `Boss莫特斯` 后输入 `2-kill`。确认 0 秒同时出现 4 个骷髅盗贼、约 2 秒全部死亡并掉落符咒，P1/P2 再约 3 秒生成 1 个骸骨战士；将 Boss 调整到 P3 后应只死亡且不重组。还需确认在 2 秒内重复输入命令不会留下额外重组。
- 可复用经验：需要验证“全部召唤物死亡”的 Boss 机制时，测试命令应直接复用正式创建函数和同一召唤组，再通过具名延迟回调触发死亡；不要在测试层重写死亡、掉落或阶段判定。

## 骸骨符咒改为敌对单位拾取

- 问题现象：骸骨符咒使用“敌对英雄列表”命名的筛选入口，实际拾取条件需要覆盖普通敌对单位；测试场景中玩家英雄也不应被误认为可拾取对象。
- 根因：公共目标模块同时维护敌对英雄和普通敌对单位，但莫特斯技能调用的是名称较窄的 `获取Boss技能敌对英雄列表` 别名，无法直观表达符咒对所有敌对目标的意图。
- 涉及文件：`04．骸骨召唤.ts`、生成的 `04．骸骨召唤.lua`；公共目标封装为 `系统.01．单位系统.06．仇恨系统.05．技能目标选择`。
- 修改内容：骸骨符咒的 `可拾取单位列表` 改为调用 `获取Boss技能敌对目标列表`，复用公共敌对目标筛选。公共筛选会排除无效单位、友军、召唤物、幻象、蝗虫单位和远古单位；正式战斗返回敌对英雄与普通单位，测试场景有注册测试目标时仍优先使用注册目标列表。
- 复用封装：继续复用 `创建战斗内拾取物` 的 50ms 距离检测和 140 码拾取半径，没有改成右键物品，也没有复制单位枚举逻辑。
- 构建验证：`npm run build:files -- "TS/系统/03．技能系统/05．单位技能/03．Boss技能/02．挑战与隐藏Boss/05．影骨莫特斯/04．骸骨召唤.ts"` 成功；`fix-lua-for-pack` 更新 `0` 个文件，Lua 同步完成。生成 Lua 已确认导入并调用 `获取Boss技能敌对目标列表`，旧入口引用已消失。
- 待实测：需进图验证正式敌对单位和莫特斯测试注册目标进入 140 码后会自动拾取并获得 12 秒骸骨符咒 Buff；当前测试 Boss 与玩家英雄同属玩家一阵营，玩家英雄仍不会因“敌对单位”筛选自动成为拾取者。
- 可复用经验：技能语义涉及英雄和普通单位时，优先调用“敌对目标列表”而不是名称含“英雄”的兼容别名；同时保留测试目标注册机制，避免测试场景枚举整张地图。
