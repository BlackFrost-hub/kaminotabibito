## 三、必须持续遵守的硬约束

- 修改前先确认规则、现有实现和公共封装；不要凭记忆直接改代码。
- JASS/Dz 回调使用模块顶层具名函数；尽量避免匿名闭包，不能用匿名闭包绕过 TSTL 问题。
- 不使用 Lua 数学库；随机数、距离、角度和三角函数优先使用项目已有 `lib`/技能封装。
- 优先复用 `TS/lib` 和 `TS/系统/03．技能系统/00．技能模板+函数/01．技能函数`，先查封装再新增逻辑。
- 读取装备属性键时必须查 `TS/lib/扩展函数/物品相关函数/装备数据查询.ts`，不能凭字段名猜测。
- 不随便给底层 `lib` 添加 `@noSelfInFile`；优先 `this: void`、局部具名包装函数、局部别名或安全版封装。
- 不修改 `fix-lua-for-pack.js`；不混用 `jass`、`BJ`、`japi`，各自走正确入口。
- 调试输出统一走 `TS/lib/扩展函数/自定义扩展函数/03．调试输出.ts`。
- 除非排查 TSTL 的 `self/nil` 错位，否则不主动检查生成 Lua；有高风险调用形态时只检查相关产物。
- 不调用没有 `@noSelfInFile` 的普通版封装；优先使用项目已有安全版。
- 中文文件和文档使用 `apply_patch` 局部编辑，避免整文件重写、编码漂移和无关格式化。
- TS 修改优先执行：

  ```powershell
  npm run build:files -- "本次修改的TS文件1" "本次修改的TS文件2"
  ```

  参数只能是本次修改或新建的 `TS` 目录下 `.ts` 文件。只改文档时不运行 TS 构建；除非用户明确要求，不打包地图。
