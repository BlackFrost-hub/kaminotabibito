# 单位技能复盘

本目录记录单位技能开发中已经发生过的问题，并将结论固化为实现与验收规则。新增或修复单位技能时，提交前必须逐项检查本文。

## 一、先确认技能语义

- 明确技能目标是施法瞬间锁定、持续追踪、每段重新选取，还是仅以目标提供初始方向。
- 明确伤害区域跟随施法者、跟随目标、固定在世界坐标，还是按施法瞬间快照结算。
- 主动、被动、场地效果、阶段机制和护卫逻辑分别确认入口，不能只看到主动技能能释放就认为 Boss 已完整覆盖。
- 有护卫的 Boss 必须同时验证护卫创建、技能、仇恨、血条优先级、死亡与清理。
- 需要正式场景才能触发的技能，必须写清测试系统采用的替代场景以及与正式战斗的差异。

## 二、测试目标不能掩盖技能行为

- 固定步兵和固定山丘之王不能移动，只适合验证伤害、命中范围和单位类型筛选。
- 追踪、转向、冲锋、连线、动态落点等技能，应使用可移动的玩家英雄作为测试目标。
- 测试命令显式传入的目标会覆盖技能内部的自动选敌逻辑。检查测试入口时必须追到最终传参，不能只看正式技能里的默认选敌。
- 追踪目标集合与伤害目标集合必须分开定义：技能可以只追踪一个玩家英雄，但范围伤害仍应枚举区域内全部敌人。
- 测试 Boss 当前可能归测试玩家所有，因此阵营染色、敌我筛选、仇恨和原生攻击行为可能与正式 Boss 不同。
- 测试系统不得为了方便观察而修改正式技能逻辑；差异应放在测试入口或测试场景配置中。

## 三、表现参数必须完整

创建特效前至少确认以下参数：

- 模型路径是否正确，模型本身是点特效、弹体、持续法阵还是附着特效。
- X、Y 是施法者脚下、身体中心、前方偏移、目标点还是路径中点。
- Z 是否需要叠加 `GetUnitFlyHeight`。飞行 Boss 的特效不能默认落在地面。
- 缩放是否与单位模型和技能实际范围匹配，不能只依赖模型默认尺寸。
- 水平朝向是否按当前 `GetUnitFacing` 设置，模型自身朝向不一致时必须配置修正角度。
- 持续追踪技能必须按表现刷新间隔重新读取面向；只在创建时设置一次不等于跟随。
- 特效持续时间和重建间隔是否会造成断层或过量叠加。
- 命中特效、飞行特效、残留区域特效必须分开配置，不能用同一个点特效代替整个过程。

单位模型只能可靠设置水平朝向。当前平台没有直接设置单位模型俯仰角的接口；独立特效可以使用 `EXEffectMatRotateX/Y/Z`。不要把物编最大俯仰角误认为运行时弹道俯仰 API。

## 四、伤害与表现必须分离

- 表现刷新 Tick、转向 Tick、伤害 Tick 应分别按设计运行。
- 项目统一技能伤害使用 `ATTACK_TYPE_NORMAL` 进入技能链路，物理、火、冰、毒、暗等分类由 `DAMAGE_TYPE_*` 决定；不能把 `ATTACK_TYPE_MAGIC` 当成“魔法伤害类型”。
- 伤害类型验收必须同时检查伤害数字颜色、对应属性抗性和生成 Lua 的 `attackType`/`damageType`，不能只看封装函数名称。
- 提高特效刷新频率时，不得顺带提高伤害次数、Buff 叠层次数或控制判定次数。
- 每个伤害 Tick 必须使用明确的命中区域和当前方向，不能让视觉朝向与伤害朝向分离。
- 持续技能应分别记录表现经过时间和伤害经过时间，避免用错间隔导致持续时间或总伤害变化。
- 首次表现是立即播放还是等待第一个 Tick，必须按技能前摇和音效时点明确决定。

## 五、预警必须与结算一致

- 预警形状、半径、长度、宽度、扇形角度和朝向必须与实际判定一致。
- 矩形和方向直线提示圈的 `X/Y` 一律传路径起点；底层会按朝向前移半个长度到模型中点。调用方禁止先手动移到中点，否则预警会额外偏移半段。
- 预警是在创建时取一次方向，还是持续跟随施法者，必须与技能机制一致。
- 提示圈会按来源单位所属玩家进行阵营染色。测试 Boss 属于玩家时显示友方白色，不代表正式敌方 Boss 也会显示白色。
- 不要仅凭类型名判断最终颜色，应检查提示圈工厂和底层染色逻辑。
- 安全区与危险区不得复用含义相反的提示类型。

## 六、弹幕系统检查

- 先确认飞行表现是单位马甲、附着特效还是独立特效。
- TS 原生弹幕默认单位载体马甲为 `eaaa`，模型通过 `DzSetUnitModel` 替换到单位上；纯视觉且不需要被攻击/击落的弹道应使用 `载体模式: "特效"`，由独立附加特效承担表现，不创建单位壳。
- 需要 XYZ 轨迹时，马甲物编必须允许飞行高度变化，并验证生成 Lua 中每 Tick 写入了 `SetUnitFlyHeight`。
- 贝塞尔轨迹必须同时验证起点、控制点、终点、Z 高度和 XY 切线朝向。
- 固定落点与追踪目标不能混用；到达回调只能在真正抵达后结算。
- 弹体到达后应按设计创建命中特效、伤害和残留区域，并正确销毁马甲。

## 七、生命周期与清理

- 每个延迟回调和周期回调都必须纳入对应 Boss 或技能上下文清理。
- Boss 死亡、战斗结束、切换 Boss、技能中断和阶段切换时，分别确认哪些护卫、弹幕、特效、机制单位和计时器需要清理。
- 原设计要求保留的护卫不能因统一清理误杀；原设计要求随 Boss 死亡的护卫不能残留。
- 周期回调内必须检查关键单位是否仍然有效，停止后立即返回，不能继续读取无效句柄。
- 不得把测试系统的清理规则带入正式 Boss 战运行逻辑。

## 十、构建规则

1. 普通 TS 修改优先执行：

   ```powershell
   npm run build:files -- "本次修改的TS文件1" "本次修改的TS文件2"
   ```

2. 参数只传本次修改或新建的 `TS` 目录下 `.ts` 文件，每个路径使用双引号。
3. 修改 `TS/global.d.ts`、`tsconfig.json`、公共类型或导出签名，删除或重命名 TS 文件，局部构建失败，或执行最终交付验证时，才运行 `npm run build`。
4. 只修改文档、规则、资源或其他不参与 TSTL 的文件时，不运行 TS 构建。
5. 不擅自打包地图。
