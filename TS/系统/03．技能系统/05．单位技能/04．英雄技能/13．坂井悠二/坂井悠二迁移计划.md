## 3. 技能迁移计划

### Q：吸血鬼（A0E8）

图片最终效果：普通攻击额外造成10%攻击力的暗魔法伤害；主动沿施法者朝目标方向发出黑暗冲击，约1秒内对直线敌人造成300%攻击力暗魔法伤害，命中者在持续时间内几乎无法移动。施法距离800，冷却8秒。魔耗以图片介绍的5%最大魔法为准，禁止在技能文件再次手工扣除百分比魔耗。

JASS时间线：

1. 入口保存施法者位置、目标方向和施法者当前飞行高度。
2. 每0.21秒推进一次，最多约5秒或施法者死亡停止。
3. 每次推进从起点沿角度前进40码，在半径175范围枚举敌人；每个单位只命中一次。
4. 命中时造成主伤害值的20%，并将目标移动速度设为0；1秒后恢复为单位默认移动速度。
5. 每个推进点创建 `e06T`，朝向为“施法方向+90度”，并将壳飞行高度设置为“施法者高度+壳默认飞行高度”。

实现要求：

- 直线推进必须按源JASS的0.21秒/40码/175范围/单次命中实现，不能用一次性圆形范围伤害替代。
- 伤害必须走项目统一伤害封装；目标去重、机械/远古/死亡单位过滤保持一致。
- `e06T` 属于本英雄指定的原单位壳例外，按JASS照抄，不改成直接模型特效。
- “几乎无法移动”要用可叠加、可清理的TS控制/Buff表达，不能直接永久写死移动速度；1秒后只恢复技能施加前的有效速度。
- 被动普通攻击额外伤害应接项目攻击/伤害事件中心，不要在Q主动入口重复实现。

Buff规划：Q命中控制状态需要一个可驱散/可清理的短暂控制Buff，图标先使用占位图标，后续放入 `imports/BuffIcon/Hero/SakaiYuuji/`。

### W：银之监牢（A0E9）

图片最终效果：指定敌人眩晕2秒，随后造成约350%攻击力暗魔法伤害；施法距离600。图片显示魔耗15%最大魔法，冷却/技能间隔按图片复核。

JASS时间线：

1. 入口播放 `gg_snd_ReviveUndead` 于目标单位。
2. 读取施法者攻击力的3倍作为伤害基准。
3. 在目标位置、目标飞行高度依次创建并各持续1秒：
   - `war3mapImported\\AbstruseEnergy.mdx`
   - `war3mapImported\\DarkBreathStream.mdx`
   - `war3mapImported\\ShadowAssault.mdx`
4. 每个直接特效使用目标单位的 `modelScale` 设置特效尺寸，并设置目标飞行高度Z。
5. 创建 `e008`，缩放为目标模型大小×2，设置到目标位置/高度；其用途是控制/表现载体，不是玩家单位。
6. 0.50秒后结算伤害。源JASS目标控制由物编/壳承担，迁移时用项目TS控制封装复现2秒眩晕，不能漏掉眩晕与伤害的先后关系。

实现要求：

- 伤害必须在2秒控制结束后结算，除非技能图片明确要求其它时点；不能把0.5秒JASS计时误读成技能最终眩晕时长。
- 三段特效直接创建，尺寸使用目标单位的模型缩放；位置使用目标飞行高度；逐段销毁时间为1秒。
- `e008` 是纯控制/表现马甲，可优化为TS控制和直接特效，但要保留壳造成的视觉和时间线参数。
- 物编魔耗100与图片15%最大魔法冲突，最终以技能介绍为准，接统一魔耗系统。

Buff规划：`银之监牢`眩晕状态需要显示Buff，计划可驱散，图标占位后生成并放到 `imports/BuffIcon/Hero/SakaiYuuji/`。

### E：Grammatica「语法」（A0EA）

图片最终效果分两条：

- 指定敌人：瞬移到目标面前，并使目标眩晕0.5秒。
- 指定自己：获得1.5秒抵挡Buff，伤害减免75%；受到超过自身最大生命20%的伤害或死亡时消失。
- 施法距离500，冷却8秒，魔耗5%最大魔法。

JASS时间线：

1. 入口保存目标、目标点、施法者位置/角度和飞行高度。
2. 0.05秒后执行传送/目标处理，创建 `war3mapImported\\DGate.MDX`，直接特效持续1秒。
3. 敌方目标路径使用 `e00D` 辅助马甲添加 `A04L` 并施放 `thunderbolt`；英雄移动到目标点/目标面前。
4. 传送过程涉及0.01秒周期移动与碰撞检测，结束后清理马甲、位置点和特效。

实现要求：

- 目标敌人和自施法必须是两个清晰分支；不能把自施法误当成目标点传送。
- `e00D` 只有施放控制命令的作用，可以用TS控制封装替代；若保留则按物编参数创建和清理。
- 自身抵挡状态必须使用TS Buff表达，显示75%减伤、1.5秒持续、20%单次伤害阈值和死亡移除；伤害拦截必须在统一伤害事件入口处理。
- 不能用本地分支修改真实单位属性/冷却；传送和控制是同步游戏逻辑，所有位置、伤害、Buff状态同步执行。

Buff规划：`Grammatica-抵挡`，持续1.5秒，不可被普通驱散（最终按项目Buff规则确认）；伤害超过20%最大生命或死亡时移除；图标目录为 `imports/BuffIcon/Hero/SakaiYuuji/`。

### R：神门（A0ED）

图片最终效果：额外消耗30%最大魔法，刷新语法，在目标区域打开神门；神门持续时间按图片版本记录（图片版本若为7/8.5/10秒，以技能介绍当前版本为最终值，JASS只作为时间线参考）；神门持续对下方敌人施放制裁，命中造成50%攻击力暗魔法伤害。神门开启后，D可用；二段`胧天震`要求英雄等级20。

JASS时间线：

1. R入口立刻将 `A0EA` 冷却设为0，创建 `e001` 神门单位于目标点，并设置为施法者飞行高度+神门默认高度。
2. 若英雄等级>20，隐藏/禁用 `A0ED`，给英雄添加 `A0EC`，允许二段技能。
3. 创建0.25秒周期计时器，神门持续约10秒，或在相应技能事件发生时进行处理。
4. 神门周期内对目标区域枚举敌人，按0.50秒周期处理；目标合法性、重复命中组和伤害点必须按JASS保留。
5. `A0EC`入口创建 `mantid_beaconlight_sha.mdx` 作为区域表现，周期伤害点随机/按区域处理；每个命中点创建 `DarknessMeteor.mdx` 或 `ShadowSpine.mdx`，持续0.35秒；命中点另有 `ThunderClapCaster.mdl`，持续0.5秒。
6. R结束时移除 `A0EC`，恢复/清理 `A0ED` 可用性，销毁神门单位、特效、组、计时器。

实现要求：

- 神门是实际承载持续状态的单位，先按JASS/`yduser`保留，不直接改成单一特效。
- R的百分比魔耗只交给统一魔耗系统处理；R技能逻辑不能再次扣除30%。物编固定Cost与图片百分比冲突，以图片为准。
- 刷新语法使用同步冷却接口，不能在 `GetLocalPlayer()` 分支中调用真实冷却修改。
- 神门持续时间、伤害频率、伤害倍率以技能介绍当前版本为准；在实现前必须从5张图片确认最终文本，并在本节记录结果。
- 二段技能只能在神门有效期内、等级要求满足时开放；关闭时彻底移除并清理，避免残留可用按钮。

Buff规划：神门开启状态需要显示Buff，持续与实际神门一致；`胧天震`的区域减速/持续伤害也需要独立可清理Buff或区域状态。神门Buff图标放入 `imports/BuffIcon/Hero/SakaiYuuji/`。

### D：神门-祭礼之蛇（A0EB）

图片最终效果：仅神门开启后可用；要求英雄等级≥40、力量>300，否则召唤失败。成功后持续10秒，移动速度最大化，暗魔法伤害提高30%，刷新一次语法，鼓舞附近友军（不包括自身）并提高基础攻击力100%，额外移动速度+20持续10秒。魔耗50，冷却90秒。具体“施法后攻击力”是一次性强化还是10秒状态，必须以图片文字和JASS动作最终核验。

JASS时间线：

1. `A0EB`入口检查技能条件。
2. 成功后给英雄添加 `S00B`，并每秒给命中/附近单位处理移速；结束时移除并恢复原值。
3. 创建第一层马甲：英雄当前位置、面向英雄，播放第0动画，时间缩放20，缩放1.2，顶点颜色RGB 100/100/100、透明度70，飞行高度为英雄高度+200；添加两个技能；绑定 `war3mapImported\\SakaiYuji_Snake_DAce(Head).mdl` 到 origin。
4. 创建第二层马甲：坐标按周期推进，面向为第一层面向+偏移角，播放第0动画，时间缩放20，缩放4.0，顶点颜色RGB 100/100/100、透明度70，飞行高度为英雄高度+300；绑定 `SakaiYuji_Snake_DAce.mdl` 和 `Beam(GreenBlack).mdl` 到 origin。
5. 第一层每1秒更新，第二层每0.05秒更新；持续10秒后清除所有马甲和特效，移除 `S00B`，移速恢复；同时恢复 `A0EA` 冷却为8秒。

单位壳规则：坂井悠二是原壳例外，以上两层马甲的缩放、颜色、动画、时间缩放、飞行高度和角度必须照抄JASS。不要把这两个壳直接替换为不带参数的特效。只有控制技能的`e00D`类辅助马甲可以优化。

Buff规划：

- `祭礼之蛇-神降临`：10秒，显示暗魔法伤害+30%、移速最大化、语法刷新和强化状态。
- `祭礼之蛇-移速`：+20移速，10秒；若项目允许合并显示，可与上一个Buff合并，但数值逻辑必须独立可清理。
- 附近友军攻击力强化：按项目属性Buff表处理，不能用每秒重复加减属性的方式造成叠加泄露。

## 5. 冲突与取值原则

1. 技能图片/技能介绍是最终规则；JASS用于还原时间线、目标过滤、表现顺序和历史细节。
2. 物编固定魔耗与图片百分比魔耗冲突时，使用图片百分比，并由项目统一魔耗系统扣除一次。
3. 物编冷却只是按钮基础配置；涉及R刷新E、D期间刷新E等动态冷却时走同步冷却封装，不能本地修改真实技能实例。
4. R神门持续时间存在7/8.5/10秒的历史文本版本痕迹，实施前以当前技能介绍图片为准，并在这里更新为唯一值。
5. 若JASS实现与技能介绍冲突，最终行为按介绍；冲突必须在实现提交前记录具体原因，不能默默选择。

## 6. 同步安全与工程规则

- 所有伤害、治疗、位置、创建/删除单位、Buff增删、属性修改、冷却、魔耗、技能可用性均为同步逻辑。
- `GetLocalPlayer()` 内只允许本地UI、图标、文字、音效等表现；禁止在本地分支调用真实单位/技能实例修改。
- 施法动作、暂停、吟唱/进度条、特效和伤害严格按时间线执行：先进入技能施法状态，再按源JASS延迟结算；不能为了“立即生效”提前伤害。
- 所有伤害走项目伤害封装，不直接裸调用 `UnitDamageTarget`。
- 所有持续状态走TS Buff表；结束、驱散、死亡、重复施加都必须有明确清理规则。
- 单位组、计时器、点、特效和临时单位必须在结束、死亡、取消和异常路径清理。
