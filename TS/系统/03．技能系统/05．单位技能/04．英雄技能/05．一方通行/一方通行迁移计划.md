- 本次不得修改 `04．E技能.ts`，包括重构、格式化、改注册方式、改伤害路径和改弹幕判定。

### 1.3 实现总规则

- 最终行为以技能介绍为准；技能介绍与 JASS 代码不一致时，必须在差异表中保留 JASS 原值，同时按技能介绍实现。
- 源 JASS 的事件顺序、等待时长、动作、音效、特效、控制和伤害先后仍然是迁移时间线的主要证据。不能为了代码简短而提前伤害、提前解除控制或合并不同阶段特效。
- 技能实现必须配置化。动作编号、动作速度、音效、特效路径、缩放、颜色、挂点、Z、高度、持续时间、周期和伤害时点放在配置或共享表现配置中，技能函数只读取配置执行。
- 涉及硬直时严格执行“先添加项目暂停来源，再播放动作，再进入等待/计时器”的顺序。不能先播放动作后暂停，不能用零秒眩晕或裸 `PauseUnit` 代替项目暂停系统。
- 伤害全部使用项目技能伤害封装，禁止新增裸 `UnitDamageTarget`。伤害类型、攻击类型、武器类型、单体/AOE/持续形态和是否参与技能加成要明确填写。
- 百分比魔耗接入项目统一魔耗系统。英雄技能文件不得同时保留一套自己的百分比扣魔；JASS 中自行扣魔的地方也要迁移成统一入口，避免重复扣除和真实游戏数据异步。
- Q/W/R/D 的玩法逻辑、伤害、控制、单位位置、地形、冷却、魔耗和 Buff 都必须走同步路径，禁止在 `GetLocalPlayer()` 或其他本地分支内修改。

### 2.4 TS Buff 表与图标规划

本英雄迁移不能只实现数值效果。凡是会持续一段时间、影响玩家决策、需要查看剩余时间或需要被后续逻辑查询的状态，都必须登记到 TS Buff 表；眩晕、减速、暂停等真实控制仍由项目控制封装负责，TS Buff 负责状态栏显示和生命周期同步。

#### Buff 文件与资源位置

- 后续新增 `TS\系统\05．Buff系统\03．Buff表\02．英雄\07．一方通行.ts`。
- 在 `TS\系统\05．Buff系统\03．Buff表\02．英雄\index.ts` 中导入并展开一方通行 Buff 表。
- 新图标统一放在 `imports\BuffIcon\Hero\Accelerator\`，目录名使用英雄罗马音/英文名 `Accelerator`，不要把图标路径写进 `map` 的物编 INI。
- 图标先生成 1024×1024 的带魔兽白银外框原生边框源图，再按项目图标流程等比例缩放、转换为 `.blp`，最终 TS 路径使用 `BuffIcon\\Hero\\Accelerator\\文件名.blp`。
- 图标只负责显示，不能在图标生成失败、路径错误或本地玩家看不到图标时改变伤害、控制、魔耗、冷却或技能阶段。

特效朝向必须遵守项目规则：确认项目封装角度单位后再传参；不要对已经是角度制的 `两点角度()` 再乘一次 `Math.PI/180`。特效创建后如果只是跟随位移，周期回调只能更新坐标/Z，不能反复叠加旋转矩阵。

## 4. Q 矢量移动迁移计划

### 4.1 目标行为（以技能介绍为准）

- `A0DW` 开启矢量移动，施法者移动时额外获得固定500移速。
- 这500为固定加成，不应被减速或加速影响。
- 启动消耗5%最大魔法；持续开启期间每秒消耗 `80 + 8%最大魔法`。
- 魔法值低于20%强制关闭。
- 玩家可以用 `A0DT` 主动关闭；到达目标附近、发布新命令或状态失效时也停止移动。
- 开启/关闭时的技能可用性、Q Buff 和移动类型必须成对恢复；死亡、重复开启和中断路径都要清理。

### 4.2 源 JASS 时间线与实现注意点

来源主要为 `一方通行.j:22-132`、`:748-788`。

1. `A0DW` 入口记录施法者，播放 `gg_snd_AcceleratorW01`，隐藏原 Q，添加 `A0DT` 和 `A0DZ`/`B01C` 状态。
2. 后续收到点目标/单位目标指令后开始移动；JASS 每0.05秒运行一次移动逻辑。
3. 每个 tick 计算目标方向和移动点，先创建移动尾迹，再移动单位并播放动作索引9；尾迹高度取施法者当前飞行高度，生命周期约0.8~1秒。
4. 若魔法低于20%、Q Buff 不存在或距离目标不超过100，停止移动、恢复动画和移动类型；低魔量分支同时移除关闭技能和 Buff、恢复原 Q 可用性。
5. `A0DT` 入口只关闭 Q，不应扣除额外魔法，不应造成技能冷却或伤害。

### 4.3 特效与冲突记录

| 源路径 | 源使用方式 | TS 计划 |
| --- | --- | --- |
| `Objects\\Spawnmodels\\Naga\\NagaDeath\\NagaDeath.mdl` | 浮空可行时的移动尾迹 | 直接点特效，放旧位置，Z=施法者当前飞行高度，按源寿命清理 |
| `war3mapImported\\slidingdustwithrocks.mdx` | 不可浮空地形时的移动尾迹 | 直接点特效，放旧位置，Z=施法者当前飞行高度，核对导入扩展名 |
| `gg_snd_AcceleratorW01` | 开启和开始移动时播放 | 沿用项目声音封装，不能放进本地分支改变玩法状态 |

JASS 移动 tick 的扣魔写法是 `4 + 最大魔法/250`，与技能介绍的 `80 + 8%最大魔法/秒` 不一致；JASS 入口还依赖外部局部变量“魔法消耗”。实现必须以介绍为准，接入统一魔耗系统，并在验收中确认启动扣魔只发生一次、周期扣魔按每秒而不是重复扣两套。

## 5. W 矢量操作迁移计划

### 5.1 目标行为

#### 单位目标

- 对目标造成200%攻击力的风/木属性技能伤害。
- 目标沿施法者到目标的方向被击退400码。
- 目标受到50%移速降低，持续1秒。
- 移动过程中遇到单位或地形停止。
- 碰撞后对原目标额外造成一次100%攻击力、300范围伤害，并眩晕0.5秒。

#### 地面单击

- 第一次对地面施放后，等待第二段输入窗口。
- 若窗口内没有再次施放，施法者周围400范围敌人受到300%攻击力风/木属性伤害。
- 命中单位被击飞0.6秒；JASS 用 `A04R` 并把两个持续时间数据改为0.60，TS 直接用击飞/飞行高度控制。
- JASS 在施法者硬直后播放动作索引10，并在约0.3秒阶段进入结算；TS 必须保持暂停先于动作。

#### 地面双击

- 第一次地面施法打开约0.5秒的二段输入窗口；第二次触发 `A0DY` 后进入双击分支。
- 消耗口径为 `50 + 15%最大魔法`，以技能介绍覆盖源 JASS 中第二段使用5%的历史值。
- 沿第一次记录的技能方向前进800码，前方半径200范围敌人受到400%攻击力风/木属性伤害。
- 移动代理每0.02秒前进20码，共40次；在第13、26、39次创建一次 `B00L` 地形，并播放两个地裂特效。
- 命中单位不能重复受同一轮技能伤害；附加减速20%，持续2秒。`A0DQ` 物编同时写了攻速20%，而技能介绍只写减速20%，最终按技能介绍确认只实现介绍明确的效果。
- 双击完成后解除施法者硬直、恢复 W 可用性、清除 `A0DY` 和所有临时状态。

### 5.2 单位目标时间线

来源：`一方通行.j:789-870`、`:135-223`。

1. `A0DU` 入口记录目标、计算施法者到目标方向并按统一魔耗系统扣除基础+百分比魔耗。
2. 目标分支立即播放 `gg_snd_AcceleratorW01`，施加1秒50%减速，记录伤害值为攻击力×2。
3. 以0.03秒延迟进入击退实例；每0.02秒检查前方125范围是否有敌方非远古/非机械存活单位，以及下一个位置是否可通行。
4. 未碰撞时把目标沿固定方向移动40码；到达10次后结算初始目标伤害并结束。
5. 碰撞时先创建碰撞特效，再对原目标结算额外伤害；300范围内的其他敌人也结算同一伤害，并给原目标添加0.5秒眩晕。枚举单位必须去重和清理。
6. 目标死亡、施法者死亡、技能被打断、技能重复释放时必须结束实例，移除减速、恢复目标飞行高度/移动状态并清理特效和组。

### 5.3 地面单击/双击时间线

- 地面单击入口创建一次0.5秒二段监听，同时隐藏 W 并使施法者进入项目硬直；不要直接使用 `PauseUnitBJ`。
- 单击结算播放 `ThunderclapCaster.mdl` 绑定特效和 `SandExplosion.mdx`，源 JASS 的 `SandExplosion` 缩放为1.40，Z 为施法者当前飞行高度；这些数值放入配置。
- 单击初始结算先对400范围敌人造成攻击力×3伤害，再执行约0.3秒、每0.02秒一次的上升/下降飞行高度表现，增量为25；结束后恢复原飞行状态。
- 单击命中目标的0.6秒击飞和碰撞控制必须使用 TS 控制封装，不创建 e00D。
- 双击分支以第一次记录的角度为绝对方向，创建地形时使用真实 `B00L` 破坏物；`B00L` 是玩法碰撞地形，不属于可替换的纯表现单位壳。
- 双击地形表现：每次创建地形点播放 `WarStompCaster.mdl`、`ThunderClapCaster.mdl`，各持续约1秒；地形本体约5秒后移除，模型为 `war3mapImported\\masserocheuse2.mdl`，缩放1，固定角度由源逻辑决定。

### 5.4 W 的伤害与控制封装要求

- 单位目标初始伤害、碰撞额外伤害、碰撞300范围伤害、地面单击伤害、地面双击伤害都必须带同一技能实例 ID，分别标注单体/AOE/路径形态。
- 伤害类型按技能介绍：单位目标和地面操作为风/木属性；不能直接照抄 JASS 的 `DAMAGE_TYPE_PLANT` 或 `DAMAGE_TYPE_MIND` 而不在项目伤害类型表中确认。
- `A0E0`、`A04L`、`A04R`、`A0DQ` 的所有玩法效果由 TS 控制/Buff 封装承担；隐藏单位只负责施法的做法不允许保留。

## 6. R 血液逆流迁移计划

### 6.1 目标行为

- `A0DX` 为150码目标技能，冷却40秒。
- 魔耗以技能介绍为准：`20%最大魔法值 + 300`，由统一魔耗系统一次性处理。
- 目标被压制3秒；期间每秒造成目标当前“已损失生命值”的10%强化伤害，共3次，总计30%。
- 压制结束后目标进入3秒虚弱：移动速度降低50%，造成伤害降低30%。
- 目标死亡、技能被打断或目标失效都必须清理暂停、动画速度、Buff、伤害修正和计时器。

### 6.2 源 JASS 时间线

来源：`一方通行.j:568-659`、`:873-903`。

1. 入口记录目标当前模型大小、目标点和总伤害值：`(目标最大生命-目标当前生命)×0.30`。
2. 施法者添加项目硬直并播放动作索引0；JASS 每0.10秒进入一次持续阶段。
3. 持续阶段先把目标位置锁回记录位置，再创建 `AFOD` 闪电，结算 `总伤害/30` 的强化伤害，创建 `RedMetamorphosis2.mdx` 并把缩放设为目标模型大小、Z 设为目标当前飞行高度。
4. 第10、20 tick 修改施法者动作；第25 tick 播放目标 `death` 动作并把目标时间缩放改为1.80；持续到第30 tick，即约3秒。
5. 目标死亡或达到30 tick后，解除施法者硬直、恢复目标时间缩放为1.00、解除目标暂停，创建 `bloodex-special-2 (4).mdx` 和 `xuebao.mdx`，二者缩放/Z均按目标模型大小/高度设置。
6. 源 JASS 创建 `e00D` 添加 `S00A`，目标虚弱应迁移为直接 TS Buff；`S00A` 物编持续3秒，但 `e00D` 本体因HP=2、负回血约2秒，不能依赖壳寿命表达最终效果。

### 6.3 源实现冲突与最终采用口径

| 项目 | JASS/物编 | 技能介绍/最终 TS |
| --- | --- | --- |
| 入口魔耗 | JASS 只计算20%最大魔法 | 20%最大魔法+300，由统一魔耗系统处理 |
| 后续移速降低 | `S00A.DataA=0.30` | 介绍明确50%，TS使用50% |
| 后续伤害降低 | `B01D`/运行时伤害修正-30% | 介绍明确30%，TS使用30% |
| 压制伤害 | JASS每0.10秒结算总伤害/30 | 介绍为每秒10%×3，TS保持3秒/每秒结算并保证总量一致；如项目 tick 需要更细分，必须保证每秒累计10% |
| 目标时间缩放 | 目标结束时恢复1.00，25 tick时设置1.80 | 保留源动作时间点，并在所有中断路径恢复1.00 |

### 6.4 R 特效迁移要求

R 的 `bloodex-special-2 (4).mdx`、`xuebao.mdx`、`RedMetamorphosis2.mdx` 是直接特效，不能误改成单位壳。创建时：

- 位置取目标当前位置/记录点的实际语义，不能全部挂到施法者。
- 缩放取目标单位物编 `modelScale`，不是固定常数；源 JASS 已经明确这样做。
- Z 取目标当前飞行高度；目标可能被其他系统抬升，不能使用默认0。
- 闪电 `AFOD` 的两端分别取施法者与目标，持续时间按源0.10秒。
- 颜色、旋转、动画如源资源或物编没有明确值，不得擅自补值；先在 `imp.ini` 和模型资源中核查。
