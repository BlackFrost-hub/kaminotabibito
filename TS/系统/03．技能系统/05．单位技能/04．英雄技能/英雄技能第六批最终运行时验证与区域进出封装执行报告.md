## 四、B 组：十六夜 RR 区域进出封装评估（已审计，保留原组逻辑）

### B1 只读拆解（RR inside 逻辑全貌）

| 要素 | 现状 |
|---|---|
| inside 集合 | 每 tick 在 `推进RR区域` 内新建局部 `inside`/`knifeInside` 表，标记本帧 800 码内合法单位/飞刀；与 `context.单位记录`/`context.飞刀记录`（上帧登记集合）对比判定进出 |
| 区域中心/半径 | `context.X/Y`（施法点快照）+ 固定 800（枚举半径与 `RR单位在区域` 的 800² 距离判断一致） |
| 进入识别 | 单位：排除施法者/世界单位/死亡/牛头人后 `RR进入单位`（登记+计数+暂停/Buff）；飞刀：`获取咲夜现存飞刀(800)` → `RR进入飞刀` |
| 离开识别 | 遍历记录，不在本帧 inside 中 → `RR离开单位/飞刀`（计数减、暂停移除、Buff 移除、状态表清理） |
| 计数 | **跨实例共享**：`RR单位全局状态表`/`RR飞刀全局状态表` 按单位 handleId 全局共享（同一单位被多个区域罩住计数累加），非每实例独立 |
| 筛选时点 | 进入时筛选（施法者/世界单位/死亡/牛头人），离开时不筛选（记录内必合法） |
| 结束清理 | `结束RR区域`：移除周期、遍历记录全部离开、世界计数递减与 Buff 移除、组销毁、单位壳移除 |
| 具名化状态 | `推进RR区域`/`结束RR区域`/`RR进入单位`/`RR离开单位`/`RR进入飞刀`/`RR离开飞刀` 全部具名 ✅ |

### B2/B3 决策：**不迁移 RR 到公共组件**

候选公共接口要求（区域中心/快照/上一帧集合/进入离开回调/结束清理/**每实例独立状态键**）与 RR 存在不可调和冲突：

1. **计数跨实例共享**：RR 的完美/缓速计数在全局状态表按单位 handleId 共享（多区域叠加），公共组件"每实例独立状态键"会导致叠加计数语义丢失（离开一个区域即清零）
2. **专属飞刀系统**：飞刀进出依赖 `获取咲夜现存飞刀`（十六夜专属飞刀注册系统），非通用单位枚举，公共组件无法表达
3. **顺序与时点**：进入先于离开判断、进入筛选离开不筛选，公共组件需完整复刻才能等价，收益低于风险

**保留原组逻辑**。RR 已是全具名回调 + 完整清理（组销毁/记录遍历离开/世界计数/Buff），无泄漏与匿名回调问题，无额外优化点。
