# 特效模型命名与去重备忘录

## 文件定位

本文件只做“乱码、纯编号、代号或哈希式导出名”的资源登记与去重，不是项目全部特效模型目录，也不是英雄技能特效规划表。

- `file_000796`、`155.mdx`、`JNTX (34).mdx`、`[TX] (272).mdx`、纯数字文件名和类似哈希导出名，属于本文件的登记范围。
- `iceflower.mdx`、`icespirits.mdx`、`sem_*.mdx`、`daoguang-blue-hengsao.mdx`、`BY_Wood_*.mdx` 等有明确语义的名称，不因为是特效模型就写入本文件。
- 有明确语义的模型，如果已经确认适合某个英雄技能，只记录在对应英雄的技能特效资源文件中；视觉描述由 `.cursor/rules/resources/visual/effect-asset-catalog.md` 维护。
- 同一个代号模型可以被多个英雄技能引用，但本文件只保留一条资源名/哈希登记；各英雄文件分别记录自己的用途。

## 规则

1. 外部源模型准备迁移前，先登记原始文件名、来源路径、字节数、完整 SHA-256、贴图依赖和候选用途。
2. 只有确认用途的代号模型才登记；没有明确英雄、技能和阶段归属的模型不因名字特殊而硬写。
3. 同名不同哈希、同哈希不同来源或同一模型的不同动画版本必须分开核对，不得按文件名覆盖。
4. 正式纳入项目资源库时，可以把代号名改成正常、可读的项目名；但必须在本文件原记录中追加“原始名称 -> 正式项目路径/名称”的映射，不能删除原始代号名。
5. 改名后的项目文件仍按完整 SHA-256 和贴图依赖查重；原始名称只用于追溯来源和阻止重复导入，不作为项目运行时路径。
6. 语义化模型不进入本文件的命名索引；它们的技能用途、主/备版本、朝向、缩放和生命周期由对应英雄资源文件维护。

固定流程：

1. 先看英雄技能说明、JASS/TS 表现需求，判断模型适合哪个英雄、哪个技能、哪个阶段。
2. 只导入确认适配的单个模型和它实际依赖的私有贴图；源目录只复制，不删除。
3. 待迁移阶段只记录来源路径、候选英雄/技能/阶段、动作语义和待核对依赖，不得写成项目已存在或已经接入。
4. 迁移后补写项目正式路径、正式名称、贴图重映射、MDX 序列、朝向、缩放和生命周期验收结果。

禁止整体扫描或批量迁入 `C:\Users\Administrator\Desktop\投射物`、`特效库` 等目录。普攻弹道和技能特效必须分别按英雄、技能、阶段确认。已存在于 `imports` 的模型不得重复导入；同名不同版本必须先比较完整哈希和贴图依赖。
