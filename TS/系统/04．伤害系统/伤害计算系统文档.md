## ⚠️ 重要：YDUserData属性名必须使用中文

> **YDUserDataGet/YDUserDataSet 的第三个参数（属性名）必须使用中文，不能使用英文key！**

```typescript
// ❌ 错误：使用英文key
YDUserDataGet("player", player, "critRate", "real")      // 错误！
YDUserDataGet("player", player, "lifeSteal", "real")     // 错误！
YDUserDataGet("unit", unit, "magicResist", "real")       // 错误！

// ✅ 正确：使用中文属性名（STAT_CONFIG中的name）
YDUserDataGet("player", player, "暴击率", "real")        // 正确！
YDUserDataGet("player", player, "伤害吸血", "real")      // 正确！
YDUserDataGet("unit", unit, "魔抗", "real")              // 正确！
```

**原因**：YDUserData底层存储使用的是中文字符串作为键名，与装备系统STAT_CONFIG中的`name`字段对应，而非`key`字段。

## 一、系统概述

### 1.1 功能描述
伤害计算系统负责处理单位受到伤害时的各种修正计算，包括：
- 基础伤害修正（伤害减少/增加）
- 护甲穿透计算
- 魔法抗性与穿透
- 各类伤害类型加成/抗性
- 属性伤害（金木水火雷光暗）
- 吸血系统（伤害吸血、魔法吸血、普攻吸血）
- 伤害吸魔

### 1.2 触发条件
- **事件**: 任意单位受到伤害
- **条件**: 
  - 伤害类型不是 `DAMAGE_TYPE_MIND`
  - 伤害值 >= 0.10

## 三、伤害计算流程

### 3.1 初始化变量
```
SH = GetEventDamage()        // 初始伤害
增加伤害 = 0.00              // 加法修正
最终伤害 = 1.00              // 乘法修正
```

### 3.2 计算步骤（按顺序）

#### Step 1: 固定伤害减少/增加
```
SH = SH - 伤害减少(受伤者)
SH = SH + 伤害增加(攻击者)
```

#### Step 2: 免疫判定
- 若 `免疫伤害 = true` 且 `减伤关闭 = false` → 伤害设为0
- 若 `免疫普攻 = true` 且 是普攻伤害 → 伤害设为0，显示"闪避"

#### Step 3: 护甲穿透计算
**条件**: 物理伤害 (`DAMAGE_TYPE_NORMAL`)

```
if 攻击者有无视护甲:
    穿透后护甲 = 0.01
else if 攻击者有护甲穿透:
    穿透后护甲 = 原护甲 × (1 - 护甲穿透)

初始伤害 = SH / (1 - 原护甲 / (原护甲 + 50))
SH = 初始伤害 × (1 - 穿透后护甲 / (穿透后护甲 + 50))
```

#### Step 4: 魔法抗性计算
**条件**: 魔法伤害 (`ATTACK_TYPE_NORMAL` 且非 `DAMAGE_TYPE_NORMAL/ENHANCED`)

```
// 魔抗上限50%（玩家）
if 魔抗 < 0:
    最终伤害 *= (1 - 魔抗)  // 负魔抗增加受到伤害
else:
    if 无视魔抗条件不满足:
        魔抗 *= (1 - 魔法穿透)
        最终伤害 *= (1 - 魔抗)
```

#### Step 5: 百分比伤害减少
```
最终伤害 *= (1 - 伤害减少%)
```

#### Step 6: 百分比伤害提高
```
if 伤害% >= 0:
    增加伤害 += 伤害%
else:
    最终伤害 *= (1 + 伤害%)
```

#### Step 7: 物理伤害修正
**条件**: `DAMAGE_TYPE_NORMAL`

```
最终伤害 *= (1 - 物理抗性)  // 物抗上限30%
// 物理伤害加成
if 物理伤害 >= 0:
    增加伤害 += 物理伤害
else:
    最终伤害 *= (1 + 物理伤害)
```

#### Step 8: 魔法伤害修正
**条件**: 魔法伤害

```
if 魔法伤害 >= 0:
    增加伤害 += 魔法伤害
else:
    最终伤害 *= (1 + 魔法伤害)
```

#### Step 9: 强化伤害修正
**条件**: `DAMAGE_TYPE_ENHANCED`

```
if 强化伤害 >= 0:
    增加伤害 += 强化伤害
else:
    最终伤害 *= (1 + 强化伤害)
```

#### Step 10: 技能伤害修正
**条件**: `ATTACK_TYPE_NORMAL`（技能攻击）

```
最终伤害 *= (1 - 技能抗性)
if 技能伤害 >= 0:
    增加伤害 += 技能伤害
else:
    最终伤害 *= (1 + 技能伤害)
```

#### Step 11: 普攻伤害修正
**条件**: 是普攻伤害

```
最终伤害 *= (1 - 普攻抗性)
if 普攻伤害 >= 0:
    增加伤害 += 普攻伤害
else:
    最终伤害 *= (1 + 普攻伤害)
```

#### Step 12: 魔法普攻伤害
**条件**: 普攻且魔法攻击

```
增加伤害 += 魔法普攻伤害
```

#### Step 13: 属性伤害修正

| 伤害类型 | 属性伤害 | 属性抗性 |
|---------|---------|---------|
| `DAMAGE_TYPE_SLOW_POISON` / `POISON` / `ACID` | 金属性伤害 | 金属性抗性 |
| `DAMAGE_TYPE_PLANT` | 木属性伤害 | 木属性抗性 |
| `DAMAGE_TYPE_COLD` | 水属性伤害 | 水属性抗性 |
| `DAMAGE_TYPE_FIRE` | 火属性伤害 | 火属性抗性 |
| `DAMAGE_TYPE_LIGHTNING` | 雷属性伤害 | 雷属性抗性 |
| `DAMAGE_TYPE_DIVINE` | 光属性伤害 | 光属性抗性 |
| `DAMAGE_TYPE_SHADOW_STRIKE` | 暗属性伤害 | 暗属性抗性 |

计算方式：
```
最终伤害 *= (1 - 属性抗性)
if 属性伤害 >= 0:
    增加伤害 += 属性伤害
else:
    最终伤害 *= (1 + 属性伤害)
```

#### Step 14: 召唤物伤害修正
**条件**: 攻击者是召唤物

```
最终伤害 *= (1 - 召唤物抗性)
if 召唤物伤害 >= 0:
    增加伤害 += 召唤物伤害
else:
    最终伤害 *= (1 + 召唤物伤害)
```

#### Step 15: 专精加成
**蝼蚁专精**: 目标非英雄且非恶魔种族
**Boss专精**: 目标是英雄或恶魔种族

```
if 专精 >= 0:
    增加伤害 += 专精
else:
    最终伤害 *= (1 + 专精)
```

#### Step 16: 最终伤害加成
```
最终伤害 *= (1 + 最终伤害%)
```

#### Step 17: 结算伤害
```
最终SH = SH × (1 + 增加伤害) × 最终伤害
YDWESetEventDamage(最终SH)
```

## 四、吸血系统

### 4.1 伤害吸血
```
总吸血百分比 = 伤害吸血
// 玩家上限5%，除非有伤害吸血上限属性
```

### 4.2 魔法伤害吸血
**条件**: 魔法伤害（非物理、非强化）

```
总吸血百分比 += 魔法伤害吸血
// 玩家上限15%
```

### 4.3 普攻伤害吸血
**条件**: 普攻伤害

```
总吸血百分比 += 普攻伤害吸血
// 玩家上限25%
```

### 4.4 吸血计算
```
回复值 = 伤害值 × 总吸血百分比
回复值 *= (1 + 受到的治疗加成)
SetUnitLife(攻击者, 当前生命 + 回复值)
```

### 4.5 伤害吸魔
**条件**: 攻击者是英雄

```
吸魔百分比 = 伤害吸魔
// 上限5%，除非有伤害吸魔突破
回复值 = 伤害值 × 吸魔百分比
SetUnitMana(攻击者, 当前魔法 + 回复值)
```

## 十、计算公式汇总

### 10.1 护甲减伤公式
```
减伤比例 = 护甲 / (护甲 + 50)
实际伤害 = 原始伤害 × (1 - 减伤比例)
```

### 10.2 最终伤害公式
```
最终伤害 = 初始伤害 
         × (1 - 魔抗修正)
         × (1 - 物抗修正)
         × (1 - 伤害减少%)
         × (1 - 技能抗性)
         × (1 - 普攻抗性)
         × (1 - 各属性抗性)
         × (1 + 增加伤害)
         × (1 + 最终伤害%)
```

### 10.3 吸血公式
```
回复值 = 最终伤害 × (伤害吸血 + 魔法吸血 + 普攻吸血)
实际回复 = 回复值 × (1 + 受到的治疗率)
```

## 十一、属性叠加机制规划

### 11.1 叠加类型说明

| 叠加类型 | 公式 | 特点 | 适用场景 |
|---------|------|------|---------|
| **加法叠加** | `最终 = 基础 × (1 + A + B + C)` | 收益线性，易叠加 | 伤害加成类 |
| **乘法叠加** | `最终 = 基础 × (1+A) × (1+B) × (1+C)` | 收益递减，防叠加过强 | 抗性减伤类 |
| **取最高值** | `最终 = max(A, B, C)` | 只生效一个 | 移动速度 |

### 11.2 属性叠加分类

#### 加法叠加（伤害加成类）
```
增加伤害总和 = 伤害% + 物理伤害 + 魔法伤害 + 技能伤害 + 普攻伤害 + ...
最终伤害 = 基础伤害 × (1 + 增加伤害总和)
```

**适用属性**：
- `伤害%`、`物理伤害`、`魔法伤害`、`强化伤害`
- `技能伤害`、`普攻伤害`、`魔法普攻伤害`
- `金/木/水/火/雷/光/暗属性伤害`
- `召唤物伤害`、`蝼蚁专精`、`Boss专精`

**设计理由**：加法叠加让玩家堆叠同类属性时有稳定的收益，不会因为乘法叠加导致数值爆炸。

#### 乘法叠加（抗性减伤类）
```
最终伤害 = 基础伤害
         × (1 - 魔抗)
         × (1 - 物理抗性)
         × (1 - 伤害减少%)
         × (1 - 技能抗性)
         × (1 - 普攻抗性)
         × (1 - 各属性抗性)
         × (1 + 最终伤害%)
```

**适用属性**：
- `魔抗`、`物理抗性`、`技能抗性`、`普攻抗性`
- `伤害减少%`、`最终伤害%`
- `金/木/水/火/雷/光/暗属性抗性`、`召唤物抗性`

**设计理由**：乘法叠加（独立乘区）防止抗性叠加过强，每增加一个抗性来源收益递减。

### 11.3 负数抗性处理

**规则**：负数抗性使用乘法叠加（独立乘区）

```
魔抗 = -0.2 (负20%魔抗)
最终伤害 = 基础伤害 × (1 - (-0.2)) = 基础伤害 × 1.2
即：受到的魔法伤害增加20%
```

**多个负抗性叠加示例**：
```
魔抗 = -0.2, 物抗 = -0.1
最终伤害 = 基础伤害 × 1.2 × 1.1 = 基础伤害 × 1.32
即：受到的伤害增加32%（乘法叠加）
```

**设计理由**：
1. 防止负抗性叠加过强（乘法收益递减）
2. 与正抗性计算方式一致，逻辑统一
3. 符合魔兽争霸3的伤害计算习惯

### 11.4 完整伤害公式

```
最终伤害 = 初始伤害
         × (1 + 增加伤害总和)     ← 加法叠加区
         × (1 - 魔抗)             ← 独立乘区
         × (1 - 物理抗性)         ← 独立乘区
         × (1 - 伤害减少%)        ← 独立乘区
         × (1 - 技能抗性)         ← 独立乘区
         × (1 - 普攻抗性)         ← 独立乘区
         × (1 - 属性抗性1)        ← 独立乘区
         × (1 - 属性抗性2)        ← 独立乘区
         × ...
         × (1 + 最终伤害%)        ← 独立乘区
```

### 11.5 计算示例

**场景**：玩家英雄受到一次魔法伤害
- 初始伤害：100
- 攻击者：物理伤害+20%，技能伤害+10%
- 受击者：魔抗30%，伤害减少%10%

**计算过程**：
```
增加伤害总和 = 0.2 + 0.1 = 0.3
最终伤害 = 100 × (1 + 0.3) × (1 - 0.3) × (1 - 0.1)
         = 100 × 1.3 × 0.7 × 0.9
         = 81.9
```

/**

  return playerId >= 0 && playerId <= 7;

 * @param value 原始值
 * @param isPlayer 是否为玩家单位

function getStatWithLimit(attrName: string, value: number, isPlayer: boolean): number {
  if (!isPlayer) return value;  // 敌对单位无上限

  if (limit === undefined) return value;
  
  return Math.min(value, limit);

## 十三、单位属性 vs 玩家属性

### 13.1 核心概念

```
┌─────────────────────────────────────────────────────────┐
│  属性读取优先级：先判断单位，再判断玩家                    │
├─────────────────────────────────────────────────────────┤
│  单位属性 = 敌对单位的属性（每个敌人都可能不同）           │
│  玩家属性 = 玩家英雄的属性（每个玩家只有一个英雄）         │
└─────────────────────────────────────────────────────────┘
```

### 13.2 属性归属说明

| 属性类型 | 归属 | 说明 |
|---------|------|------|
| 攻击者属性 | 单位优先 | 敌人的攻击属性 / 玩家英雄的攻击属性 |
| 受击者属性 | 单位优先 | 敌人的防御属性 / 玩家英雄的防御属性 |
| 玩家专属上限 | 仅玩家 | 吸血、魔抗等上限只对玩家生效 |

### 13.3 属性读取逻辑

```typescript
/**
 * 获取单位/玩家的属性值
 * 优先级：单位属性 > 玩家属性 > 默认值
 * 
 * @param tableType "unit" 或 "player"
 * @param target 目标对象（单位或玩家）
 * @param attrName 属性名（使用STAT_CONFIG中的name）
 * @param valueType 值类型 "real" | "integer" | "boolean"
 */
function getAttrValue(
  tableType: "unit" | "player",
  target: any,
  attrName: string,
  valueType: "real" | "integer" | "boolean"
): any {
  // 先尝试读取单位属性
  if (tableType === "unit") {
    const unitValue = YDUserDataGet("unit", target, attrName, valueType);
    if (unitValue != null && unitValue !== 0 && unitValue !== false) {
      return unitValue;
    }
    // 单位没有该属性，尝试读取玩家属性
    const player = jass.GetOwningPlayer(target);
    if (player != null) {
      return YDUserDataGet("player", player, attrName, valueType);
    }
  }
  // 直接读取玩家属性
  return YDUserDataGet(tableType, target, attrName, valueType);
}
```
