# 装备技能模块说明

本目录负责把装备/物品带来的主动、被动、伤害、拾取、丢弃、持有等效果拆成 TS 入口。

## 基本结构

- `00．物品`
  - 一件装备一个独立文件。
  - 所有具体装备业务最终都落在这里。
  - `index.ts` 只做 `export * from "./xx．装备名";` 聚合，不在这里二次 `require`。
- `01．死亡事件`
  - 击杀、死亡、尸体、死亡后触发类装备入口。
- `02．累计伤害`
  - 受到/造成累计伤害达到阈值后触发的装备入口。
- `03．主动技能`
  - 使用英雄技能后由装备追加效果的入口。
- `04．伤害事件`
  - 伤害修正、最终伤害、受伤、造成伤害触发类装备入口。
- `05．物品使用`
  - 主动使用物品/药剂/道具类入口。
- `06．获取丢弃`
  - 捡取/丢弃后判断装备是否仍在单位身上的通用层。
- `07．获得物品`
  - 捡取获得后立刻生效、持有型周期、条件开关、资源增减等逻辑迁移入口。
- `08．攻击效果`
  - 物品侧攻击类伤害编排。
  - 这里的“攻击效果”/“攻击特效”不是纯普攻，而是攻击类伤害入口；只要事件被标记为 `isNormalAttack` 或 `isSkillAttack`，都可能进入。
  - 纯普攻要求 `isNormalAttack === true`，并且 `isSkillAttack/isSkillDamage` 都不是 `true`；`isNormalAttack === true` 本身只能说明它走了普通攻击口径，不足以证明是纯普攻。
  - `isSkillAttack === true` 表示被封装识别为攻击伤害的技能/触发伤害，例如 `UnitDamageTarget(..., true, false, ATTACK_TYPE_NORMAL, ...)` 这类应进入攻击效果，但不能算纯普攻。
  - `仅普通攻击` 只是单件装备的额外过滤，语义是纯普攻；只有装备语义明确写“普通攻击/普攻”时才加。写“攻击效果/攻击特效/每次攻击”时不要加，否则会错误挡掉 `isSkillAttack`。
  - 公共攻击机制优先放在 `TS\系统\03．技能系统\00．技能模板+函数\01．技能函数\21．攻击效果`，不要在装备技能里重复造底层。
  - “强化下一次普攻 / X 秒内强化 X 次普攻 / 远程临时换弹道”的装备或技能，统一调用 `21．攻击效果/04．强化普攻.ts` 的 `添加强化普攻`。临时弹道恢复必须传 `恢复弹道`，底层不自动猜原始物编弹道。
- `99．物品测试`
  - `wp1 / wp2 / ...` 测试发装配置。
  - 新装备测试按当前序列末尾追加，不要重排旧编号。

## 装备识别规则

不要写内部 4 位 raw id。

正确做法：
1. 在 `TS\系统\02．物品系统\01．装备数据.ts` 确认装备 `name` 已存在。
2. 在对应配置表里用装备名反查：
   - `TS\系统\02．物品系统\13．物品名反查.ts`
   - 安全 FourCC 转换优先用 `stringToFourCCSafe`
3. 单装备文件里只使用配置表导出的装备 ID。

## 装备概率规则

- 装备触发概率统一走 `TS\系统\03．技能系统\00．技能模板+函数\01．技能函数\22．幸运值`。
- 单装备文件需要手动判定概率时，使用 `装备触发概率通过(原始概率, 触发单位)`。
- 只需要显示或计算最终概率时，使用 `装备触发概率修正(原始概率, 触发单位)`。
- 不要在装备文件里直接用 `GetRandomReal`、`随机实数` 或自己写概率修正。
- `08．攻击效果` 配置表里的 `概率`、`概率计算`、`伤害概率`、`治疗概率` 已由攻击效果核心统一接入幸运值，不需要单件装备二次修正。
- 幸运值语义：`0.3` 表示触发概率提高 30%，`-0.3` 表示降低 30%，`5` 表示提高 500%；最终概率会限制在 `0..1`。

## 新增装备时怎么选入口

按语义选入口，不要把所有装备塞进同一个核心文件。

1. 如果是主动使用物品
   - 更新 `05．物品使用/00．公共/00．物品使用装备名.ts`
   - 更新 `05．物品使用/00．公共/01．物品使用配置表.ts`
   - 在 `00．物品` 新增单装备文件
   - 在 `05．物品使用/00．公共/03．物品使用核心.ts` 调用对应处理函数
2. 如果是使用英雄技能后触发
   - 放到 `03．主动技能` 的对应语义模块。
3. 如果是受到/造成伤害触发
   - 放到 `04．伤害事件` 或现有 `02．累计伤害`。
   - 最终伤害类用最终伤害回调；伤害改写类用伤害修正回调。
4. 如果是捡取/丢弃/持有效果
   - 优先接 `06．获取丢弃` 或 `07．获得物品` 的公共函数。
   - 单装备文件负责自己的属性、特效、周期效果回收。
5. 如果是攻击类伤害触发
   - 走 `08．攻击效果`。
   - 文案写“普攻/普通攻击”才配置 `仅普通攻击: true`，它只认纯普攻；文案写“攻击效果/攻击特效/每次攻击”默认必须同时允许 `isNormalAttack` 和 `isSkillAttack`。
   - 远程/近战、普通攻击/技能攻击、目标生命系数、目标类型分层，都优先放在这里做配置化处理。

## 单装备文件约定

- 文件顶部加 `/** @noSelfInFile */`。
- 导出清晰的业务函数，例如：
  - `处理某装备使用`
  - `处理某装备伤害`
  - `初始化某装备持有逻辑`
- 不在单装备文件里写大而全的事件注册，除非这个装备确实需要独立监听捡取/丢弃/周期扫描。
- 单装备文件优先调用现有封装：
  - 治疗/回血：`TS\系统\04．伤害系统\02．治疗系统`
  - 护盾：`TS\系统\03．技能系统\00．技能模板+函数\01．技能函数\07．护盾`
  - 扩散伤害：`08．扩散伤害`
  - 反击：`13．反击`
  - 控制、DOT、HOT、Buff：`19．扩展效果`，其中燃烧入口已收敛到 `01．debuff/03．燃烧.ts`
  - 攻击效果公共层：`21．攻击效果`，包含 `添加强化普攻`
  - 范围选敌、物品判断、属性底层：优先找 `TS\lib\扩展函数`

## TSTL 和回调约定

- JASS/JAPI API 必须先绑定局部别名，再调用。
- 不要直接写 `jass.Xxx(...)` / `japi.Xxx(...)`。
- 进入 JASS、Dz、中心计时器、触发器的回调必须用模块级具名函数。
- 不要新增匿名闭包作为 JASS 回调。
- 不要用 `Math.*`，运行时数学优先用项目封装或 JASS 对齐函数。
- 不要为了 TSTL 修改 `scripts/fix-lua-for-pack.js`。
- 修改导出函数、事件注册、计时器、护盾、伤害/治疗调用后，必须：
  - `npm run build`
  - 检查相关生成 Lua 是否有 `self/nil` 参数错位

## Buff 与护盾注意

- Buff 表只负责 UI、分类、图标、特效和驱散规则，不等于实际效果完成。
- 有持续逻辑的 Buff 必须检查 Buff 是否仍存在；被驱散后要提前结束。
- 原生魔法效果清理时，要兼容 `UnitRemoveAbility`。
- 属性护盾用护盾系统，不要自己写伤害抵扣表。

## 测试约定

- 测试入口在 `99．物品测试`。
- 命令按 `wp数字` 递增追加。
- 不要插入旧序列中间，避免旧测试编号错位。
- 测试配置里已有“序号 / 命令 / 装备名”说明表，追加后可直接对照命令。

## 提交前自检

最少检查：
1. 装备名能在 `01．装备数据.ts` 找到。
2. 配置表用装备名反查，没有写 raw id。
3. 单装备文件已在 `00．物品/index.ts` 导出。
4. 对应入口核心已调用单装备处理。
5. 测试序列已追加。
6. `npm run build` 通过。
7. 相关生成 Lua 的 require、事件回调、计时器、护盾、伤害/治疗调用没有 `self/nil` 参数错位。
