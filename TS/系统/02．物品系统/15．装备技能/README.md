# 装备技能模块说明

本目录负责把装备/物品带来的主动、被动、伤害、拾取、丢弃、持有等效果收编到 TS。后续 AI 修改这里时，先读本文件，再读 `.cursor/rules/README.md`、`.cursor/rules/GLOBAL_AGENT_PROMPT.mdc`、`.cursor/rules/agent-shared/tstl-hard-rules.mdc` 和相关子目录规则。

## 基本结构

- `00．物品`
  - 一件装备一个独立文件。
  - 所有具体装备业务最终都落在这里。
  - `index.ts` 只做 `export * from "./xx．装备名";` 聚合，不写 `export` 后再 `require`。
- `01．死亡事件`
  - 击杀、死亡、尸体、死亡后触发类装备入口。
- `02．累计伤害`
  - 受到/造成累计伤害达到阈值后触发的装备入口。
- `03．主动技能`
  - 使用英雄技能后由装备追加效果的入口。
  - 如果装备语义是“单位施放目标单位技能后触发”，通常放这里。
- `04．伤害事件`
  - 伤害修正、最终伤害、受伤/造成伤害触发类装备入口。
  - 伤害事件类优先走伤害修正的最终伤害回调，不要用旧 JASS 伤害事件直连。
- `05．物品使用`
  - 主动使用物品/药剂/道具类入口。
  - 可以用物品技能事件中心时，只用事件中心上下文里的 `物品 / 技能ID / 目标点 / 目标单位`。
  - 不回头按技能 raw id 做业务判断，只判断使用的物品是不是目标装备。
- `06．获取丢弃`
  - 拾取/丢弃后判断装备是否仍在单位身上的通用层。
- `07．获得物品`
  - 拾取获得后立即生效、持有型周期、条件开关、资源增减等从 `获得物品.J` 迁来的逻辑。
- `08．攻击效果`
  - 物品侧攻击效果编排。
  - 公共攻击机制优先放在 `TS\系统\03．技能系统\00．技能模板+函数\01．技能函数\21．攻击效果`，不要在装备技能里重复造底层。
- `99．物品测试`
  - `wp1 / wp2 / ...` 测试发装配置。
  - 新装备测试按当前序列末尾追加，不要重排旧编号。

## 装备识别规则

不要写内部 4 位 raw id。

正确做法：

1. 在 `TS\系统\02．物品系统\01．装备数据.ts` 确认装备 `name` 已存在。
2. 在对应配置表里用装备名反查：
   - `TS\系统\02．物品系统\13．物品名反查.ts`
   - 安全 FourCC 转换优先用 `stringToFourCCSafe`
3. 单装备文件里只使用配置表导出的装备 ID。

例子：`抗毒药水`

- 装备数据：`name: "抗毒药水"`
- 配置表：`抗毒药水: 反查物品类型ID(物品使用装备名称.抗毒药水)`
- 业务判断：`是否为使用物品(ctx.物品, 物品使用装备ID.抗毒药水)`

## 添加一个新装备

按语义选择入口，不要所有装备都塞进一个核心文件。

1. 如果是主动使用物品
   - 更新 `05．物品使用/00．公共/00．物品使用装备名.ts`
   - 更新 `05．物品使用/00．公共/01．物品使用配置表.ts`
   - 在 `00．物品` 新增单装备文件。
   - 在 `05．物品使用/00．公共/03．物品使用核心.ts` require 并调用单装备处理函数。
2. 如果是使用英雄技能后触发
   - 放到 `03．主动技能` 的对应语义模块。
   - 单装备业务仍放 `00．物品`。
3. 如果是受到/造成伤害触发
   - 放到 `04．伤害事件` 或现有 `02．累计伤害`。
   - 最终伤害类用最终伤害回调；伤害改写类用伤害修正回调。
4. 如果是拾取/丢弃/持有生效
   - 优先接 `06．获取丢弃` 或 `07．获得物品` 的公共函数。
   - 单装备文件负责自己的属性、特效、周期效果回收。
5. 更新 `00．物品/index.ts`
   - 只追加一行 `export * from "./编号．装备名";`
6. 更新 `99．物品测试`
   - 在当前测试序列末尾追加装备名和 `wp` 命令。

## 单装备文件约定

- 文件顶部写 `/** @noSelfInFile */`。
- 导出明确的业务函数，例如：
  - `处理某装备使用`
  - `处理某装备伤害`
  - `初始化某装备持有逻辑`
- 不在单装备文件里写大而全的事件注册，除非这个装备确实需要独立监听拾取/丢弃或周期扫描。
- 单装备文件优先调用现有封装：
  - 治疗/回蓝：`TS\系统\04．伤害系统\02．治疗系统`
  - 护盾：`TS\系统\03．技能系统\00．技能模板+函数\01．技能函数\07．护盾`
  - 扩散伤害：`08．扩散伤害`
  - 反击：`13．反击`
  - 控制、DOT、HOT、Buff：`19．拓展效果`
  - 攻击效果公共层：`21．攻击效果`
  - 范围选敌、物品判断、属性底层：优先查 `TS\lib\扩展函数`

## TSTL 与回调约束

- JASS/JAPI API 必须先绑局部别名，再调用。
- 不要直接写 `jass.Xxx(...)` / `japi.Xxx(...)`。
- 进入 JASS、Dz、中心计时器、触发器的回调必须用模块级具名函数。
- 不要新增匿名闭包作为 JASS 回调。
- 不要用 `Math.*`，运行时数学优先用项目封装或 JASS 对齐函数。
- 不要为了 TSTL 修改 `scripts/fix-lua-for-pack.js`。
- 修改导出函数、事件注册、计时器、护盾、伤害回调后，必须：
  - `npm run build`
  - 检查 `src` 下相关 Lua 是否有 `self/nil` 或参数错位。

## Buff 与护盾注意

- Buff 表只负责 UI、分类、图标、特效和驱散规则，不等于实际效果完成。
- 有持续逻辑的 Buff 必须检查 Buff 是否仍存在；被驱散后要提前结束。
- 原生魔法效果需要清理时，要兼容 `UnitRemoveAbility`。
- 属性护盾用护盾系统，不要自己写伤害抵扣表。
- 例如 `抗毒药水` 使用 `开始属性护盾(unit, "毒", ...)`，抵挡项目伤害系统中归为金/毒桶的毒、酸、缓毒、疾病类伤害。

## 测试约定

- 测试入口在 `99．物品测试`。
- 命令按 `wp数字` 递增追加。
- 不要插入旧序列中间，避免旧测试编号错位。
- 测试配置里已有“序号/命令/装备名”说明列表，追加后可直接用来对照命令。

## 提交前自检

最少检查：

1. 装备名能在 `01．装备数据.ts` 里找到。
2. 配置表用装备名反查，没有写 raw id。
3. 单装备文件已在 `00．物品/index.ts` 导出。
4. 对应入口核心已调用单装备函数。
5. 测试序列已追加。
6. `npm run build` 通过。
7. 相关生成 Lua 的 require、事件回调、中心计时器、护盾/伤害/治疗调用没有 `self/nil` 参数错位。
