# 吟唱条系统迁移规划

## Summary

在 `TS/系统/09．表现系统/08．吟唱条` 下新增一套独立的吟唱条模块，把旧 `JASS/jass复制粘贴/吟唱条.j` 迁移到 TS/Lua。

保留旧 STES 入口，供 JASS 继续触发；核心业务逻辑放到 TS，后续 TS/Lua 内部直接调用新接口，不再绕旧 JASS 业务。

参考实现：
- `TS/系统/03．技能系统/00．技能模板+函数/01．技能函数/17．单位倒计时`
- `JASS/jass复制粘贴/吟唱条.j`

目标资源路径：
- 前景主模型默认使用 `UI\CastBar\UI_shengmingzhi_p2.mdx`
- 对应背景模型路径也统一改成去掉 `imports\` 的运行时路径

## 目标

实现一套本地 UI 吟唱条系统，具备：
- 居中显示的吟唱前景/背景
- 吟唱标题文本
- 当前时间 / 总时间数值显示
- 文本提示区域
- 统一中心计时器驱动
- JASS 通过 STES 兼容调用
- TS/Lua 通过对外接口直接调用

## 模块拆分

建议目录结构：

- `00．常量定义.ts`
  - UI 坐标、层级、字体、默认文本
  - 颜色 ID 到模型路径映射
  - 默认模型路径使用 `UI\CastBar\...`

- `01．类型.ts`
  - 吟唱条参数
  - 吟唱条实例状态
  - 颜色枚举 / 文本配置

- `02．UI创建.ts`
  - 创建前景 `SPRITE`
  - 创建背景 `SPRITE`
  - 创建标题/进度/分隔符/剩余时间/提示文本 `TEXT`
  - 统一设置点位、优先级、显示隐藏

- `03．吟唱条核心.ts`
  - 启动吟唱条
  - 推进时间
  - 刷新动画偏移
  - 刷新文本
  - 到时销毁
  - 顶掉上一个吟唱条

- `04．数字格式化.ts`
  - 本地格式化剩余秒和总秒
  - 优先直接 TS 实现，不依赖旧 `NumberToString` STES

- `05．吟唱条STES桥接.ts`
  - 注册旧事件名
  - 读取 JASS/YDLocal 参数
  - 调用核心接口
  - `finally` 中清理 YDLocal 上下文

- `06．对外接口.ts`
  - 导出 `显示吟唱条(参数)`
  - 导出 `关闭吟唱条()`

- `index.ts`
  - 统一导出

## STES 兼容规划

保留旧 JASS 触发方式，事件名沿用：
- `注册吟唱条`

桥接层只做兼容，不承载业务：
- `ydl_triggerstep` 对齐
- 读取 YDLocal 参数
- 调用 `显示吟唱条`
- `finally` 中恢复父页并 cleanup

建议兼容参数：
- `sj`: 总时长
- `颜色ID`: 颜色/模型选择
- `string`: 提示文本

如旧 JASS 还有隐式默认值，也在桥接层补齐，而不是散落到核心逻辑里。

## 核心行为规划

### 1. 单实例模型

默认按“本地当前仅一条吟唱条”实现：
- 新吟唱条启动时，先关闭上一条
- 不做多条堆叠

这和旧 JASS 里 `上一個场地ui` 的覆盖语义一致，风险最低。

### 2. 驱动方式

不复刻旧 JASS 每次创建独立 timer 的做法。

改为：
- 模块级单实例状态
- 接入现有中心计时器
- 固定 tick 推进

这样更符合项目当前规则：
- 不引入匿名 JASS 回调
- 不增加大量独立 timer
- 更容易检查 TSTL 生成形态

### 3. 动画推进

旧逻辑核心是：
- 已过时间 `s`
- 归一化进度 `ss = s / sj`
- `DzFrameSetAnimateOffset(前景, 1 - ss)`

迁移后保持这个语义不变。

### 4. 文本显示

建议显示：
- 标题：默认 `吟唱中`
- 进度：`当前秒`
- 分隔符：`/`
- 剩余或总时长：按最终定稿决定
- 提示文本：默认 `场地技能：`

如果传入自定义提示文本，则覆盖默认提示。

### 5. 颜色与模型

旧 JASS 用 `颜色ID` 选择不同前景/背景模型。

迁移后保留这个兼容层：
- `1..7` 对应旧资源
- 默认使用 `5`
- 路径全部改为运行时路径，不带 `imports\`

默认前景重点确认：
- `UI\CastBar\UI_shengmingzhi_p2.mdx`

## 表现系统放置理由

该模块更偏：
- 本地 UI 表现
- 通用吟唱/场地提示条

不是单一技能函数，因此放在：
- `TS/系统/09．表现系统/08．吟唱条`

而不是继续挂在技能函数目录。

## 联机与 UI 安全要求

遵守表现系统和 DzUI 规则：
- Frame 创建、初始化、驱动注册走全端对称路径
- 最终显示内容可在本地表现阶段控制
- 不在 `GetLocalPlayer()` 分支里创建/销毁驱动链
- 不在本地分支里单独起 timer

如果最终采用“仅本地可见”的吟唱条，也应：
- 全端初始化同构壳
- 本地只做显示控制

## TSTL 约束

实现阶段必须遵守：
- `jass` / `japi` 全部先绑本地别名再调用
- 中心计时器回调用模块级命名函数
- STES 桥接用命名函数
- 不用匿名闭包进入 JASS / DzAPI 回调
- 不用 `Math.*`
- 不改 `fix-lua-for-pack.js`

## 建议对外接口

```ts
显示吟唱条({
  总时长: number,
  颜色ID?: number,
  标题文本?: string,
  提示文本?: string,
}): void

关闭吟唱条(): void
```

兼容层把旧字段翻译成新参数，新逻辑统一走这个接口。
