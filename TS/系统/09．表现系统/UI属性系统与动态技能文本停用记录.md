## 为什么必须停用多个入口

只注释表现系统总入口不够。UI 属性系统存在独立的模块入口、模块加载后的延迟启动，以及玩家英雄注册联动的面板回调；任意一条旁路都可能创建面板或启动刷新计时器。

动态技能文本恢复后，装备事件与同步 Alt 事件只负责进入全端对称的 Update 循环；本地选中快照仅计算和写入允许本地变化的提示文本，不参与 Update 的技能 ID、调用次数或执行分支。

## 恢复时检查清单

恢复前必须同时检查：

1. UI 属性系统总入口、独立入口、延迟启动和英雄注册联动。
2. 动态技能文本初始化入口和装备变化刷新入口。
3. `DzSetUnitAbilityUpdate` 的调用上下文必须保持全局同步链条，不能放回本地选择或本地 Alt 分支。
4. 恢复后先局部构建相关 TS 文件，再进行地图运行测试；不要直接打包地图。

### 物品提示模拟异步审计记录

2026-08-09：静态审计确认物品栏鼠标进入与离开使用 `DzFrameSetScriptByCode(..., false)`，属于确定的本机异步 UI 回调。鼠标进入时会注册 6 个中心计时器延迟任务，因此各客户端的延迟任务队列和回调 ID 计数会出现确定差异。

当前这些本机路径的下游操作仅包括自定义提示帧与原生 Tooltip 的文本、显隐、尺寸、位置调整，以及物品提示读取缓存；未发现创建或修改单位、物品、技能、奖励等同步游戏状态的操作。实机联机测试暂未出现掉线，因此目前保留现有实现，不进行修改。

后续若复现异步，优先按以下顺序二分：

1. 先移除鼠标进入回调中的 6 次中心计时器延迟压制，仅保留已经全端注册的周期 UI 压制。
2. 再停用本地物品提示缓存的全端周期清理，移除物品实例 `GetHandleId` 缓存键。
3. 最后检查本地回调中对原生 Tooltip 执行 `DzFrameClearAllPoints`、`DzFrameSetPoint` 的高频布局修改。

补充：`01．物品提示UI.ts` 当前使用 `Math.floor` / `Math.ceil`，违反项目“不使用 Lua 数学库”的规则；本轮只记录，不修改。
