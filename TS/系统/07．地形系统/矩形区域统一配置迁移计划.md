# 矩形区域统一配置迁移计划

> 临时计划文档。统一矩形区域系统完成并验证后删除。

## 目标

为每个可复用的地图区域定义一个稳定的语义名称，例如：

- `精灵森`
- `史莱姆草原`
- `迷雾森林`
- `奇幻湖`
- `精灵村`

世界地图、区域背景音乐、剧情入口、剧情视野和其它 TS 消费者已经改为引用统一表名称。地区正式名称尚未最终对齐，当前语义键按实际业务用途命名；旧 `gg_rct_*` 只保留在统一映射表和明确的旧 JASS 说明中。

## 统一配置原则

统一配置表是矩形区域定义的唯一来源。每个区域名称可以包含多个用途矩形，因为“当前定位范围”“解锁范围”“BGM覆盖范围”和“剧情触发范围”不一定相同。

示意结构：

```ts
{
  名称: "精灵森",
  当前位置矩形名称列表: ["精灵森"],
  解锁矩形名称: "精灵村",
  背景音乐矩形名称列表: ["精灵森.BGM区域"],
  剧情矩形名称: "精灵村.门禁区域",
}
```

配置必须区分两种矩形来源：

1. 地图编辑器预置矩形：通过统一读取层从 `jass.globals` 取得，不交给动态矩形注销逻辑；原 JASS 明确要求一次性 `RemoveRect` 的门禁/入口清理仍保留原行为。
2. 运行时坐标矩形：由统一注册表创建、缓存和销毁，供剧情或动态 BGM 使用。

地图预置矩形先按用途分为两个一级分类：

- `场地区域`：表示可复用的地图空间范围，包括地区主体、补充范围和 BGM 覆盖范围；
- `其他`：表示解锁入口、剧情入口、门禁、视野、Boss 战、刷新、镜头和英雄选择等功能性范围。

分类只用于维护和后续分批动态化，不改变业务读取名称，也不改变原 `gg_rct_*` 映射。

运行时动态矩形按文件分流：

- `01A．场地区域配置表.ts`：可复用的场地、场景和场景组范围；
- `01B．Boss战斗区域配置表.ts`：Boss 启动属性配置引用的地图预设战斗区域；未提供边界前只登记原地图变量名；
- `01．动态矩形区域配置表.ts`：剧情、支线等其他功能区域，并保留兼容聚合导出；
- 所有业务继续经 `读取动态矩形区域配置` 或 `获取矩形区域` 按语义键读取，不直接依赖分表位置。

## 现有来源盘点

### 世界地图

`08．世界地图/01．世界地图地点配置.ts` 当前分别维护：

- 地点当前位置矩形；
- 进入矩形后的解锁矩形；
- 旅行奖励矩形；
- 地图传送地点。

这些配置应改为引用统一区域名称。地点解锁来源、提示文本、图标、剧情进度和传送目标仍属于世界地图业务，不移动到矩形定义表。

### 区域背景音乐

`07．区域背景音乐/01．区域背景音乐配置表.ts` 已改为写 `矩形区域名称列表`。

迁移后应引用区域名称或背景音乐矩形列表。相同场景的重复音乐配置合并为一个音乐方案，例如：

- 沙漠区域的 `055/086/083` 合并为一个矩形列表；
- 蛇人领地的 `012A/012B` 合并为一个矩形列表；
- 同一音乐方案和多个矩形不再重复写配置对象。

### 剧情系统

剧情系统中存在两类矩形：

- 已存在的 `gg_rct_*` 地图矩形，例如主线入口、剧情视野、停止区域音乐等；
- 剧情运行时按固定坐标创建的临时矩形，例如副本入口、剧情监听范围和一次性区域。

两类都通过统一注册表解析，但生命周期不同。临时矩形必须保留显式清理，不得因为统一引用而误删地图预置矩形。

支线和世界线中的运行时矩形按生命周期分流：

- 固定坐标、长期存在且需要按语义键注销的监听范围，登记到动态矩形配置表并由注册表持有句柄；
- `RegionAddRect` 后立即释放的适配矩形，以及按单位坐标、Boss 坐标或半径临时计算的实例范围，继续由剧情局部创建和清理；
- 不把后一类临时句柄写入全局缓存，避免缓存已经被 `RemoveRect` 的失效句柄。

### 动态矩形注册表

现有 `09．动态矩形区域注册表` 是迁移基础。后续将其概念扩展为统一矩形区域注册表，同时保留旧导出函数作为兼容层，避免一次修改所有剧情调用方。

## 目标 API

计划提供以下语义入口：

```ts
读取矩形区域配置("精灵森")
获取矩形区域("精灵森", "背景音乐")
获取矩形区域列表("精灵森", "当前定位")
注册矩形区域("剧情.王城门禁入口")
注销运行时矩形区域("剧情.王城门禁入口")
```

其中：

- `获取矩形区域` 可以返回地图预置句柄或运行时创建句柄；
- `获取矩形区域列表` 用于一个地区覆盖多块矩形；
- `注册矩形区域` 只对运行时坐标定义创建矩形；
- `注销运行时矩形区域` 只能清理统一注册表创建的矩形。

## 名称和冲突处理

统一名称采用地图实际地区名，不使用 `gg_rct_*` 作为业务键。

如果同一地区存在多个用途范围，不创建多个地区名，而是在地区定义下分别维护用途列表。

已发现需要人工确认的旧配置冲突：

- BGM 表把 `gg_rct_007____________u` 标成“精灵森”；世界地图当前配置把它作为“奇幻湖”。迁移前必须根据地图实际位置确认归属。
- `gg_rct______________086` 在世界地图中用于“悲风山谷”，BGM 中归入“沙漠区域”。需要确认这是同一大区域下的不同业务用途，还是旧命名错误。

## 分阶段迁移

### 阶段 1：统一定义和兼容层（已完成当前批次）

- 在 `09．动态矩形区域注册表` 增加地图预置矩形登记表，当前 TS 侧 56 个 `gg_rct_*` 值均已登记。
- 添加按名称读取地图预置矩形、读取矩形列表，并兼容旧变量名的 API。
- 保存旧的 `按配置键注册动态矩形区域`、`获取动态矩形区域` 等导出函数。
- 地图预置矩形只通过 `jass.globals` 读取，不交给动态注销逻辑。

### 阶段 2：迁移区域背景音乐（已完成当前批次）

- 将静态 BGM 配置改为引用语义名称。
- 合并同一音乐方案下的多矩形配置。
- 保留剧情动态 BGM 的注册、启用、停用和永久清理行为。

### 阶段 3：迁移世界地图（已完成当前批次）

- 将当前位置矩形、解锁矩形和旅行奖励矩形改为统一名称引用。
- 将 `当前位置矩形键1/2/3` 收敛为 `当前位置矩形区域名称列表`。
- 保持地图解锁来源、剧情进度、图标和传送限制不变。

### 阶段 4：迁移剧情系统（已完成当前批次）

- 固定入口、视野配置和直接矩形读取已改用语义名称。
- 剧情背景音乐表达式已改用语义名称。
- Boss 战、单位初始化、英雄选择、怪物刷新、传送点揭示和物品区域判断已改用统一读取层。
- 对一次性副本、半径监听和临时战斗区域保留显式生命周期。

### 阶段 5：按边界数据逐步动态化地图预置矩形

- 用户提供上、下、左、右边界后，直接将对应预置矩形改为 TS 动态定义。
- 已动态化：`精灵村`（原 `gg_rct________________QY`，`zhuchengBGM01`）、`史莱姆草原`（原 `gg_rct________________00X`，`BGM006`）、`精灵森`（原 `gg_rct______________084`，`BGM007`）、`地精洞窟`（原 `gg_rct______________0734354`，`BGM015`）、`地精洞窟深处`（原 `gg_rct______________025`）。
- 所有预置矩形动态化、构建和剧情入口回归完成后，删除本计划文档。

## 验收标准

- 同一个地区的矩形定义只出现一个语义真源。
- 世界地图、BGM、剧情和旅行奖励可以从统一名称取得正确矩形。
- 地图预置矩形不会被动态清理逻辑删除。
- 运行时矩形仍能按剧情时机创建和销毁。
- 旧剧情入口行为、BGM切换和地图解锁行为不改变。
- 全部 TS 改动完成后按修改文件执行局部构建，不手动打包地图。
