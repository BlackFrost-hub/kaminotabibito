- `TS/系统/08．任务系统/02．主线配置驱动.ts` 更适合作为**旧兼容实现来源**，不适合作为最终归宿。

## 剧情对白迁移原则

- 后续正式剧情对白，不建议继续把 `TransmissionFromUnitWithNameBJ` / 旧电影 BJ 函数当最终归宿。
- 旧 JASS 电影函数仍然可以作为：
  - 行为参考来源
  - 过渡兼容层
- 但真正迁到 TS 后，建议统一进 `11．剧情系统` 自己的剧情步骤播放器。

### 为什么不继续长期依赖旧电影系统

- 后续要支持：
  - `ESC` 跳过整段对白
  - 输入 `-2` / `-3` 之类做倍速
  - 对话中途插入特效、给物品、播动画、切镜头、改 BGM、开门关门、启动 Boss 战
- 这些需求都要求我们自己掌控：
  - 剧情队列
  - 当前播放状态
  - 阻塞与非阻塞步骤
  - 跳过后哪些步骤仍要执行
- 旧 `TransmissionFromUnitWithNameBJ` 更适合参考，不适合承载这套控制能力。

## 剧情步骤表方向

- 后续不要只做“对白文本表”，而是做“剧情步骤表 / 剧情片段编排表”。
- 一段剧情应由多个步骤组成，步骤类型至少预留：
  - `dialog`
  - `broadcast`
  - `wait`
  - `effect`
  - `animation`
  - `camera`
  - `giveItem`
  - `runAction`
  - `setMusic`
  - `startBossFight`
- 这样以后剧情里即使出现：
  - 一句对白
  - 中途插特效
  - 主线 NPC 给玩家物品
  - 播放单位动画
  - 再接下一句对白
  - 也不需要再回退到旧 JASS 串调用法。

## 主线 / 支线模板约定

- 先以主线剧情为基准，把统一的剧情步骤模板跑通。
- 模板文件放在：
  - `TS/系统/11．剧情系统/01．主线任务/02．剧情步骤/03．剧情片段模板.ts`
- 后续支线剧情默认不再另起一套对白结构。
- 支线只需要：
  - 换片段 ID
  - 换文本
  - 换动作步骤
  - 保持同一套 `broadcast / wait / music / unitControl / effect / runAction / startBossFight` 骨架

## 对旧电影系统的使用边界

- 不是说以后完全不能用 JASS 电影函数。
- 建议口径是：
  - **短期过渡**：可以继续兼容调用
  - **正式迁移**：优先进剧情步骤系统
- 也就是说：
  - `TransmissionFromUnitWithNameBJ` 可以保留为旧行为参考
  - 新的剧情实现仍然尽量写成 TS 可控流程
  - 但原生电影系统可以作为**可选底层壳**
    - 用于阻止玩家操作
    - 用于承接 `ESC` 直接跳过
    - 用于“空白内容 + 持续时间”的阻塞等待

## 剧情播放控制方向

- 后续剧情系统建议支持：
  - `ESC` 跳过当前整段剧情
  - 聊天命令切换倍速，例如 `-2`
  - 阻塞式对白播放
  - 非阻塞广播播放
  - 跳过时仍执行关键状态步骤
    - 例如发物品
    - 场景切换
    - 开门关门
    - Boss 战启动

## 暂定实现思路

- 对于正式剧情演出：
  - 可以暂停指定玩家英雄
  - 暂停指定敌人 / NPC
  - 临时屏蔽玩家关键指令
  - 切镜头、播对白、播动作
- 原生电影系统改成**可选项**：
  - 需要原生 `ESC` 跳过和输入屏蔽时，可以启用
  - 不需要时，也可以只走剧情播放器自身控制
- 但这些控制最终都应挂在我们自己的剧情播放器里统一管理，不要继续散写在旧电影 BJ 调用之间。
- Boss 战、普通广播、正式剧情三类表现应继续区分：
  - 战斗喊话：`广播提示消息`
  - 正式连续对白：剧情步骤播放器
  - 旧 JASS 电影函数：兼容、参考，或作为可选阻塞壳

## 任务 UI 迁移口径

- 由于项目里原生 `F9` 任务面板已被遮挡，后续迁移时：
  - `QuestMessageBJ(...)` 这类原生任务消息仍可保留
  - `QuestSetDescription(...)`
  - `QuestSetTitle(...)`
  - 这类原生任务面板更新接口默认不再作为主要迁移目标
- 也就是说：
  - 需要弹任务提示：继续可用原生 `QuestMessageBJ(...)`
  - 需要更新任务内容：直接接自定义任务 UI
  - 直接同步 `questDB / questManager / triggerUIRefresh`

## 剧情协作方式

- 后续如果要正式扩写主线剧情，可以直接提供：
  - 剧情大纲
  - 章节目标
  - 人设
  - 阵营关系
  - 伏笔与禁改点
  - 你希望的语气和文风
- 在这个前提下，后续可由 TS 侧剧情系统继续承接：
  - 章节拆分
  - NPC 对白
  - Boss 战前后演出
  - 任务目标文案
  - 剧情步骤表
  - 与区域/BGM/Boss 战流程的衔接
