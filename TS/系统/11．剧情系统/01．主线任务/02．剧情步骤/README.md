# 剧情步骤

## 目标

- 不再只用“纯对白表”描述剧情。
- 统一承载：
  - 对白
  - 广播
  - 等待
  - 镜头
  - 视野
  - 音乐
  - 单位控制
  - 动画
  - 特效
  - 发物品
  - 自定义动作
  - Boss 战启动

## 当前文件

- `00．剧情步骤类型.ts`
  - 剧情步骤类型与片段配置定义。
- `01．剧情片段配置表.ts`
  - 主线剧情片段配置表。
- `02．剧情步骤播放器.ts`
  - 剧情播放器骨架。

## 设计原则

- 一个剧情片段只有一张步骤表。
- 不拆成“纯对白表 + 辅助动作表”。
- 原因：
  - 两句对白之间经常要插入特效、镜头、发物品、单位动画。
  - 分表后顺序维护困难。
  - `ESC` 跳过、倍速、阻塞控制也会更复杂。

## 原生电影系统

- 原生电影系统不是禁用项。
- 在这里的定位是：
  - 可选阻塞壳
  - 可选 `ESC` 跳过壳
- 正式剧情结构仍由步骤播放器统一调度。

## 文本常量迁移口径

- 迁移 `TRIGSTR_*` 时，优先对照 `文本常量.wts`，不要凭名字猜。
- 常见情况：
  - 一条常量就是完整正文
    - 例如 `TRIGSTR_710`
    - 这种直接落成一步 `dialog` 或 `broadcast`
  - 一条常量是说话者名字，下一条常量是正文
    - 例如：
      - `TRIGSTR_711 = 阿尔文`
      - `TRIGSTR_712 = ..既是帝国使者，我等自当引见...`
    - 这种不要拆成两步
    - 应直接合并成一条：
      - `说话者: "阿尔文"`
      - `文本: "TRIGSTR_712 对应正文"`

## broadcast / dialog 的默认划分

- `broadcast`
  - 系统提示
  - Quest 警告
  - 战斗喊话
  - 短插话
  - 不需要正式对白框承载的内容
- `dialog`
  - 正式连续对白
  - 需要阻塞后续剧情推进
  - 需要配合 `ESC` 整段跳过
  - 需要承载明确说话者的内容

## 任务消息口径

- 部分任务消息仍然应保留原生 `QuestMessageBJ(...)`。
- 不要把所有任务消息都强行并进广播系统。
- 适合继续走原生任务消息的内容：
  - `bj_QUESTMESSAGE_UPDATED`
  - `bj_QUESTMESSAGE_WARNING`
  - `bj_QUESTMESSAGE_ITEMACQUIRED`
  - 这类本来就依赖原生提示框、原生音效、原生任务语义的消息
- 也就是说：
  - 正式剧情对白：优先 `dialog`
  - 短台词/战斗喊话：可用 `broadcast`
  - 任务提示/任务警告/获得类提示：优先保留 `QuestMessageBJ(...)`
- `QuestSetDescription` / `QuestSetTitle` 这类原生任务面板接口，后续默认不再作为迁移目标。
- 如果只是更新主线/支线/小任务内容：
  - 直接接你自己的任务 UI 数据层
  - 直接刷新 `questDB / questManager / UI`
  - 不再依赖原生 `F9` 任务面板

## 坏常量处理

- 如果 `文本常量.wts` 里出现明显无效占位，例如：
  - `无（系统bug）`
- 这种不要直接当正式文本迁进剧情片段。
- 处理方式：
  - 标为待人工修文
  - 或在迁移时直接替换成合理文本
