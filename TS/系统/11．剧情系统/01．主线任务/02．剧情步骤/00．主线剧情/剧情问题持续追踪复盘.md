# 主线剧情问题持续追踪复盘

## 使用方式

- 每次实测发现问题，先记录现象、剧情进度、是否 ESC、实际画面和单位状态。
- 核对顺序固定为：剧情配置挂点 -> 剧情动作实现 -> Boss/NPC/地形等 TS 系统配置 -> 生成 Lua -> 游戏实测。
- 旧 JASS 只用于核对原始动作和数值；Boss 战启动统一走现有 TS 桥接，不重新调用旧 GUI Boss 触发器。
- 仓库内找不到的旧编辑器参数必须列出并向用户索取截图，不得从其他 Boss 配置猜值。

## 后续节点验收清单

- 入口触发只执行一次，触发事件在消费后注销。
- 说话者必须在场；场景变化后检查 NPC 是否重新到场、转向和播放动作。
- Boss 必须在对白前按需要创建、暂停、无敌；对白结束或 ESC 后走同一启动收束。
- Boss 启动必须调用 `启动剧情Boss战`，不得只写 YD 字段或只在配置中写“启动”。
- 核对战斗矩形、Boss 落点、玩家落点、BGM、胜利音乐、弱点、护盾和抗性。
- 临时单位、特效、计时器、范围事件必须在正常结束、ESC、死亡三条路径清理。
- 每次修改后先局部构建，再完整构建；生成 Lua 检查实际调用顺序，最后游戏实测回填状态。
