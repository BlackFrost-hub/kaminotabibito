## 6. 施工顺序（后续每次只推进一小段）

1. 先读本文和剧情规则，再用 `rg` 定位当前目标节点的唯一入口、片段和节点配置。
2. 先确认缺失的坐标、归属、说话者在场状态；信息不完整就停在文档/问题清单，不臆测代码。
3. 制作一个节点或一个动作后，立刻更新本工作台的状态和索引，再进入下一个节点。
4. TS 修改优先执行：

   ```text
   npm run build:files -- "本次修改的TS文件1" "本次修改的TS文件2"
   ```

5. 涉及公共类型/导出、删除或重命名 TS、局部构建失败或最终交付时才执行 `npm run build`。只改本文档不运行 TS 构建。
6. 生成 Lua 只在检查 TSTL `self/nil` 错位或用户明确要求时查看；不要把生成物当作 TS 事实源。
