# 主线任务

这里是主线剧情迁移的正式入口。

## 当前结构

- `00．剧情系统核心工具`
  - 主线剧情动作上下文、剧情进度读写、任务消息/小地图/大门/广播等桥接函数。
- `99．迁移资料`
  - 旧主线任务兼容配置和迁移说明归档，不参与正式编译和初始化链路。
- `01．主线剧情入口`
  - 主线 NPC 创建、YDUserData 兼容绑定、矩形/范围入口注册、物品事件桥接的配置与初始化实现。
- `02．剧情步骤`
  - 正式剧情步骤系统。
- `03．主线引导UI`
  - 按剧情进度提供单玩家提示与镜头引导；维护时必须遵守该目录的 `README.md`，同步核对进度、任务文本和镜头目标。

## 主线节点维护

- 进度 `1` 及之后的主线任务目标、任务提示、小地图信号与点击引导统一维护在 `00．剧情系统核心工具/09．主线节点配置.ts`。
- 新剧情优先使用 `主线.写入进度`、`主线.发布节点目标`、`主线.进入节点` 和 `剧情.停止触发单位`，不再在片段参数里重复保存同一份任务文本与坐标。
- 业务动作只处理自身逻辑；若同时承担节点承接，必须显式调用标准节点函数。未迁移动作需进入兼容白名单，未知动作 ID 不得静默执行。
- 修改主线进度、任务文本或目标位置时，必须同时核对主线引导的提示文本、镜头坐标或跟随单位是否与当前节点一致。

## 迁移原则

- 先对齐真实 JASS 执行顺序，再做中文润色。
- 迁移顺序固定为：读 JASS 条件和触发事件 -> 抽 `剧情进度` 变化 -> 拆入口事件/物品事件/Boss死亡索引 -> 写剧情片段 -> 把动作映射到核心工具或动作注册表 -> 更新报告。
- 配置里优先写语义名，不写内部 4 位 ID；只有反查不到或旧 JASS 物品事件必须兼容时，才在入口/动作实现内部保留 raw id，并在报告里说明。
- 一段剧情里允许混合对白、广播、等待、镜头、音乐、特效、物品、Boss 启动。
- 原生 `QuestMessageBJ(...)` 只保留在任务语义明确的地方。
- Boss 死亡触发到主线剧情时，优先走剧情系统片段；只有后续死亡分支足够多时，才新增轻量 `Boss死亡剧情索引`，不要把具体剧情写进 Boss 运行清理文件。
- 当前已经有 `02．剧情步骤/06．Boss死亡剧情索引.ts`，用于维护 Boss 死亡到剧情片段的映射；具体剧情内容仍放在片段文件内。
- `01．主线剧情入口` 已接入主线任务 `init()`，负责创建主线 NPC、写入兼容 YDUserData、注册 TS 侧剧情入口事件；旧 JASS 的 `主线剧情NPC4.0S` 不应再同时启用，否则会重复创建 NPC。
- `剧情传送CS` 物品拾取事件已接入 TS 侧初始化，用于承接 `9 -> 10` 的“接受任务-狩猎食人魔”桥接，并播放 `jlc_snake_ogre_task_accept`。
- `ZX02` 物品事件已接入 TS 侧初始化，用于承接 `28 -> 29` 的信件交付桥接；当前使用任务物品 `I0ES`（残缺的魔法信件），不再复用经验之书 `texp`。
