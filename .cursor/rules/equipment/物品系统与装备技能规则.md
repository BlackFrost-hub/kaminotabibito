# 物品系统与装备技能规则

适用范围：
- `TS/系统/02．物品系统/**`
- `TS/lib/扩展函数/物品相关函数/**`
- `TS/系统/03．技能系统/**` 中与物品直接联动的功能

这份文档给后续 AI 一个总入口，避免每次都从头猜物品系统结构。

## 1. 总体结构

### 1.1 物品主系统
- `TS/系统/02．物品系统/11．装备系统.ts`
  - 负责装备拾取 / 丢弃时的属性加减
  - 装备属性是否按次数放大，最终在这里结算
- `TS/系统/02．物品系统/01．装备数据.ts`
  - 装备数据源
- `TS/系统/02．物品系统/13．物品名反查.ts`
  - 用装备名 / 物品名反查物品 raw id
  - 业务侧优先走这里，不要手写 4 位 raw id

### 1.2 装备技能体系
- `TS/系统/02．物品系统/15．装备技能/**`
  - 这是业务侧装备效果主目录
- `00．物品/`
  - 一个物品 / 装备一个独立文件
- `99．物品测试/`
  - 物品测试命令与物品功能测试

### 1.3 lib 侧物品通用能力
- `TS/lib/扩展函数/物品相关函数/物品判断函数.ts`
- `TS/lib/扩展函数/物品相关函数/物品叠加函数.ts`
- `TS/lib/扩展函数/物品相关函数/物品叠加配置.ts`
- `TS/lib/扩展函数/物品相关函数/装备数据查询.ts`

## 2. 识别物品的正确方式

- 默认不要写 raw id。
- 优先写装备数据里的 `name`。
- 通过 `TS/系统/02．物品系统/13．物品名反查.ts` 反查。
- 再通过 `stringToFourCCSafe` 转类型 ID。

推荐做法：
- 配置表里维护“装备名 / 物品名”
- 初始化时统一转成类型 ID
- 业务逻辑只用配置表产出的类型 ID

## 3. 物品事件入口

### 3.1 统一优先
- `TS/系统/00．核心系统/01．事件中心/04．物品事件中心.lua/ts`
- 有“使用该物品触发效果”的场景，优先挂物品事件中心

### 3.2 使用物品时
- 以物品事件中心上下文提供的参数为准
- 上下文里通常已有：
  - 物品
  - 技能ID
  - 目标点
  - 目标单位
- 不要回头再靠技能 ID 做二次反查，除非这个效果本身明确依赖技能

### 3.3 拾取物品时
- 通用物品迁移入口是：
  - `TS/系统/02．物品系统/15．装备技能/00．物品/00．通用物品/**`
- 拾取逻辑优先挂 `onItemPickup`

## 4. 物品叠加系统

### 4.1 默认行为
- 文件：`TS/lib/扩展函数/物品相关函数/物品叠加函数.ts`
- 这个模块默认开启
- 文件底部直接执行：
  - `StarItem_OpenStack(ItemRange);`

### 4.2 默认哪些物品可叠加
- 默认只允许两类物品参与叠加：
  - `ITEM_TYPE_CHARGED`
  - `ITEM_TYPE_PURCHASABLE`

### 4.3 额外白名单
- 文件：`TS/lib/扩展函数/物品相关函数/物品叠加配置.ts`
- 用于维护“即使不是 charged / purchasable，也允许叠加”的物品
- 白名单统一写物品名字，不写 raw id

当前已知：
- `触手残片` 已加进白名单

### 4.4 叠加生效条件
- 同一个 `itemTypeId`
- 英雄单位
- 单位有背包能力 `AInv`
- 事件来源在这套注册玩家范围内

### 4.5 叠加结果
- 多个同类物品会合并为一个物品
- `charges` 相加

## 5. 装备次数是否会放大属性

这是另一个独立概念，不要和“物品可叠加”混淆。

### 5.1 控制文件
- `TS/系统/02．物品系统/16．装备次数叠加配置.ts`

### 5.2 默认行为
- 默认不开
- 只有放进这个配置表的装备名，装备属性才会按 `charges` 放大

### 5.3 实际结算位置
- `TS/系统/02．物品系统/11．装备系统.ts`

核心语义：
- 如果 `是否允许装备次数叠加(装备名)` 为真
- 则倍率 `mult = charges > 0 ? charges : 1`
- 然后装备属性按这个倍率加到角色身上

### 5.4 已知已开启按次数放大属性的物品
- `触手残片`

### 5.5 重要区分
- 放进 `物品叠加配置.ts`
  - 只是让多个物品能合并成一个带次数的物品
- 放进 `装备次数叠加配置.ts`
  - 才会让装备属性按次数乘上去

通常要两边都配，才能做到：
- 物品会堆叠
- 属性也会随次数增长

## 6. 装备技能实现原则

### 6.1 文件组织
- 一个物品 / 装备一个独立文件
- 放在：
  - `TS/系统/02．物品系统/15．装备技能/00．物品`

### 6.2 index 规则
- 新建 / 追加 `index.ts` 时，只做：
  - `export * from "./xxx"`
- 不要做二次 `require`

### 6.3 业务挂载规则
- 只有“伤害修正器自己”继续挂 `registerDamageCallback`
- 业务侧受伤 / 命中逻辑优先挂：
  - `registerAppliedFinalDamageListener`

### 6.4 周期效果
- 除非确实必要，不要做“每 tick 扫玩家英雄单位组是否持有物品”
- 若必须做持有型效果：
  - 用获取 / 丢弃注册与注销
  - 不要靠每 tick 扫描物品持有状态

### 6.5 计时器
- 全部走中心计时器
- 不要自己单独创建原生 timer

## 7. 通用物品目录规则

- 目录：`TS/系统/02．物品系统/15．装备技能/00．物品/00．通用物品`

当前通用物品逻辑按功能拆分：
- `01．吃书清理.ts`
- `02．获取特效.ts`
- `03．合成打造.ts`
- `04．领取技能.ts`
- `01．传送集合/`

适合放这里的，是：
- 不属于“单件装备技能”的公共物品逻辑
- 任务物品
- 合成 / 打造类
- 传送门类
- 领取技能类

## 9. 不要做的事

- 不要手写 4 位 raw id，优先写名字反查
- 不要因为 TSTL 去改 `fix-lua-for-pack.js`
- 不要给底层 lib 随便加 `@noSelfInFile`
- 不要为了持有型效果每 tick 扫单位组查物品
- 不要在业务代码里直接散写旧 JASS 风格大触发器
- 不要把“物品可叠加”和“属性按次数叠加”当成一回事

## 10. AI 实施建议

当需求涉及物品时，建议按这个顺序理解：

1. 这是普通装备属性，还是装备技能，还是通用物品逻辑
2. 物品识别是否应该走“名字 -> 反查 -> 类型ID”
3. 是否需要挂物品事件中心
4. 是否需要进入物品叠加白名单
5. 是否还需要进入装备次数叠加配置
6. 是否涉及伤害系统、治疗系统、Buff 系统、中心计时器

如果是新装备迁移，先看：
- `TS/系统/02．物品系统/15．装备技能/README.md`
- 同目录已有类似物品实现
- `lib` 和 `00．技能模板+函数` 下是否已有现成封装

## 11. 物品使用防重

- `EVENT_PLAYER_UNIT_USE_ITEM` 在当前项目里可能对同一次使用派发两次
- 这类逻辑不要只靠“只注册一次触发器”防重
- 需要用 `globalThis` 存稳定 key 和“已执行”标记，再用定时器清空
- 物品使用、装备热触发、回血类物品逻辑，优先按这个规则做防重
