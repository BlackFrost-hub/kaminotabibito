# 装备制作落地流程

在已经有装备图标资源的情况下，新装备默认按这个顺序落地。

## 1. 先做物遍

在 `objediting\Equipment\` 对应分类目录里创建或追加 `createEquipmentItem`，写清：

- `id`
- 名称
- 图标
- 模型
- 分类
- tooltip / description
- 是否主动使用

正式装备的 tooltip / description 最后一行必须补灰色介绍文本，颜色码统一用 `|cFF808080...|r`；不要额外写“背景：”标签。

消耗品、战斗临时拾取物和纯 Buff 道具不强制加介绍。

## 2. 再更新装备数据

同步更新：

- `TS/系统/02．物品系统/01．装备数据.ts`

这是属性、评分、等级、分类的唯一完整数据源。

## 3. 再接业务入口

- 如果是首领奖励，更新 `TS/系统/02．物品系统/18．首领奖励选择/01．奖励配置表/`。
- 如果是死亡结算、宝箱或商店，再接对应系统。

## 4. 再落装备技能

每件装备在 `TS/系统/02．物品系统/15．装备技能/00．物品/` 下建独立文件，并挂到 `index.ts`。

按语义接主动使用、伤害事件、攻击效果、获得 / 丢弃或持有逻辑。

## 5. 最后构建验证

- 运行 `npm run build`。
- 如果改了物遍，再运行 ObjEditing 构建或等待用户打包时验证。

## 没有图标资源时

如果还没有装备图标资源，先制作 / 转换 / 检查图标，再进入物遍步骤。

不要先写一批占位图标路径后忘记回补。

## 文案与语义

- 物遍 tooltip 可以写图标、模型、展示文本。
- 装备数据只写系统属性，不写图标路径。
- 文案语义要和接入系统一致：
  - 写“攻击效果”就走攻击效果系统。
  - 写“普攻 / 普通攻击”才加普通攻击过滤。
  - 写“技能造成伤害”就只响应技能伤害标记。

## Boss 掉落装备语义

Boss 掉落装备不能设计成“专门反制该 Boss 机制”的战后解法；Boss 已死亡后再针对该 Boss 没有玩法意义。

装备应把 Boss 的视觉、元素、战斗风格转化成未来通用战斗价值，例如：

- 通用抗性
- 团队续航
- 输出循环
- 生存窗口
- 控制
- 资源管理

## Boss 装备强度阶梯

同一章节内，主线 Boss 掉落装备强度默认按 Boss 顺序递增：

`主线1 < 主线2 < 主线3 < 主线4 < 主线5`

隐藏 Boss 掉落默认高于普通主线 Boss：

`主线普通 Boss < 隐藏 Boss`

章节最终 Boss 是例外：装备强度上，章节主线最终 Boss 与隐藏 Boss 同档，不要低配最终 Boss，也不要让隐藏 Boss 无脑碾压章节最终 Boss。

跨章节时，后一章节的同定位 Boss 装备通常应高于前一章节同定位 Boss；如果剧情、难度或系统节奏另有设定，以具体规划为准。

## 装备定位分布

- 不要把 Boss 掉落装备无脑做成战士装备。
- 装备属性应基本符合 Boss 特色，但必须转化成未来通用玩法价值。
- 奖励池应尽量覆盖多类角色需求，例如战士、法师、辅助、全能、召唤或特殊机制装。
- Boss 风格决定装备主题，不等于只能给同一种职业。例如“剑魂 Boss”也可以掉落法师资源循环、辅助团队号令或召唤风格装备。

## 主动与被动比例

- 不要把“优先被动”理解成全部装备都做被动。
- 一个 Boss 的奖励池如果有 4-5 件装备，通常可以选择 1 件设计为主动装备；其余以常驻属性、被动触发、攻击效果、技能伤害触发、受伤触发、治疗触发等为主。
- 如果奖励池超过 5 件，也不要无脑增加主动装备；仍以“主动是否有明确操作价值”为准。
- 主动装备必须提供明确操作决策，例如团队护盾时机、爆发窗口、救急治疗、范围控制、位移或资源爆发；如果只是换个方式触发数值加成，优先改成被动触发。
- 主动装备必须遵守通用物品技能模板和命令 ID 冲突规则。
