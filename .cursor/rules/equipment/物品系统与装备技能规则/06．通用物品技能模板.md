# 通用物品技能模板

## 基本原则

- 装备主动技能优先复用 ObjEditing 通用物品技能模板。
- 不要仅因为冷却时间、魔法消耗、施法距离不同，就为每件装备单独创建一个技能。
- 通用物品技能模板按行为差异拆分，玩家可用物品至少覆盖无目标、单位目标、点目标。
- 真正的装备效果仍由 TS 侧物品 / 装备技能系统按物品 ID 分发。

## 当前通用槽位来源

通用 Channel 槽位由这里生成：

- `objediting/Equipment/EquipmentAbilityTemplates.lua`

槽位按目标类型分组：

- `IU00-IU14`：单位目标
- `IP00-IP14`：点目标
- `IN00-IN14`：无目标

分配装备主动技能时必须按同目标类型数组顺序取下一个空槽，不要凭记忆复用已有码位。

例：

- 第一个无目标主动装备用 `IN00`
- 第二个无目标主动装备用 `IN01`
- 第三个用 `IN02`
- 单位目标和点目标同理使用 `IUxx` / `IPxx`

这样做的核心目的，是避免同一名英雄身上同时拥有两个使用相同基础命令 ID 的主动物品，导致使用命令冲突。

## 运行时参数同步

- 冷却时间、魔法消耗、施法距离等单位身上的技能参数，优先在获取 / 装备 / 使用前通过 Dz 单位技能参数 API 同步。
- 物品丢弃后若游戏会自动恢复物编默认值，不需要额外手动 reset。
- 玩家物品施法距离统一从 500 起步，常用配置只允许 `500 / 600 / 700 / 800 / 900 / 1000`。
- 这些距离是运行时配置档位，不作为 ObjEditing 技能数量的拆分维度。

## 多个主动物品并存

同一单位上多个主动物品若需要同时并存，并且冷却 / 耗蓝 / 施法距离等参数不同，不要共用同一个通用技能壳子；应分配不同的通用技能槽位。

通用物品技能槽位应使用显式且稳定的命令 ID，避免使用默认或临时 order。

新增槽位时要检查现有 ObjEditing 技能，确认命令 ID 没有冲突。

## 命令 ID 冲突兜底

获取 / 装备主动物品时必须做命令 ID 冲突兜底。

当前项目已在以下文件实现：

- `TS/系统/02．物品系统/15．装备技能/03．主动技能/04．总入口/05．技能壳参数同步.ts`

拾取时扫描英雄 6 格背包，若新物品默认命令 ID 已被其它主动物品占用，则用 `DzSetUnitAbilityOrderId` 把新物品对应的单位技能壳改成同目标类型的空闲命令 ID。

丢弃物品时清理运行态映射，物编默认命令 ID 由引擎恢复。

## 点目标物品

- 点目标通用物品技能需要在 ObjEditing 侧打开目标选取图像。
- 运行时若配置了 `施法区域 > 0`，应通过 `DzSetUnitAbilityArea` 同步到单位身上的技能壳，让玩家使用物品时能看到实际范围提示。

## 旧主动物品补物遍

- 模板图缺少旧主动物品的物遍时，只补“物品内部主动技能”到通用 Channel 壳，不要重建整件物品，不要覆盖旧物品的名称、图标、模型、说明、售价、分类等字段。
- 通用物品技能壳是槽位池，不是物品一对一专属壳。补旧物品时按目标类型分别从 `IU00-IU14`、`IP00-IP14`、`IN00-IN14` 顺序分配；同类型超过 15 个后从 00 重新循环。
- 旧 `abilList` 中如果同时有主动技能和被动/光环技能，只替换旧 `cooldownID` 对应的主动技能，保留其他能力。
- 运行时仍由主动物品技能配置同步冷却、耗蓝、施法距离、命令 ID；命令冲突靠拾取/装备时的冲突兜底处理。
- 旧主动或通用主动物品如果有敌方 / 友方 / 可破坏物等目标限制，不要把限制硬编码到 `IUxx` 槽位本身；应在主动物品技能配置里写 `目标允许`，运行时通过 `DzConvertStr2Targs` + `DzSetUnitAbilityTargs` 同步到单位身上的当前技能壳。

若未来维护命令 ID 表，通用物品技能槽位必须登记：

- 技能 raw id
- 目标类型
- 命令 ID
- 按钮槽位
- 预期用途

只有当原生技能行为、目标类型、命令 ID 并存关系或引擎限制无法复用时，才允许为单件装备创建专用 ObjEditing 技能。
