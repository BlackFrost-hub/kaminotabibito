# 实施检查清单

当需求涉及物品时，按这个顺序理解：

1. 这是普通装备属性、装备技能，还是通用物品逻辑。
2. 物品识别是否应该走“名字 -> 反查 -> 类型 ID”。
3. 是否需要挂物品事件中心。
4. 是否需要进入物品叠加白名单。
5. 是否还需要进入装备次数叠加配置。
6. 是否涉及伤害系统、治疗系统、Buff 系统、中心计时器。

如果是新装备迁移，先看：

- `TS/系统/02．物品系统/15．装备技能/README.md`
- 同目录已有类似物品实现
- `lib` 和 `00．技能模板+函数` 下是否已有现成封装
- 如果需要新增“技能模板 / 行为模板 / 可配置执行模板”，只能放在 `TS/系统/03．技能系统/00．技能模板+函数/00．技能模板`；不要放到物品辅助、技能函数、机制组件或装备侧目录。
- `01．装备风格/` 下对应风格规则

## 不要做的事

- 不要手写 4 位 raw id，优先写名字反查。
- 不要因为 TSTL 去改 `fix-lua-for-pack.js`。
- 不要给底层 lib 随便加 `@noSelfInFile`。
- 不要为了持有型效果每 tick 扫单位组查物品。
- 不要在业务代码里直接散写旧 JASS 风格大触发器。
- 不要把“物品可叠加”和“属性按次数叠加”当成一回事。
- 不要把 Boss 掉落装备设计成专门反制已死亡 Boss 的机制解法。
- 不要无脑把 Boss 掉落都做成战士装备；奖励池要按 Boss 特色覆盖不同角色需求。
- 不要为了炫技优先做主动装备；一个 Boss 4-5 件奖励装备通常最多 1 件主动，其余以常驻或被动触发为主。
