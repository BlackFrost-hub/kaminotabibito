# 剧情任务迁移与对白时长规则

适用范围：

- `TS/系统/11．剧情系统/**`
- 主线/支线剧情迁移
- 紧凑剧情片段 `对白列表` / `动作时间线`

## 执行摘要

1. 先按原 JASS 的真实剧情子段拆分，不把多段事件硬拼成一个对白序号表。
2. 每条动作明确使用 `beforeDialog`、`afterDialog` 或 `absoluteTime`，并指向正确对白序号或绝对时间。
3. 单位、物品、技能和 Boss 参数优先写语义名或配置键，不保留长期 raw id。
4. 每句对白按可见字数和标点计算时长，再按剧情节奏小幅调整。
5. 先验证顺序、挂点和可读时长，再做文案润色与公共动作抽取。

## 1. 配置结构规则

- 同一个文件可以覆盖一条连续剧情链，但文件内必须按真实子段拆开。
- 每个子段独立编号。
- 不允许把多个子段硬拼成一个连续对白序号表。
- `动作时间线` 必须显式写明挂点类型：

| 挂点 | 用途 | 必填关联 |
|------|------|----------|
| `beforeDialog` | 某句对白显示前执行 | 对白序号 |
| `afterDialog` | 某句对白结束后执行 | 对白序号 |
| `absoluteTime` | 与对白无直接关系的固定时间点 | 绝对秒数 |

## 2. 紧凑排版规则

- `对白列表` 默认一行一个对象。
- `动作时间线` 默认采用：
  - `序号 / 挂点 / 对白序号` 一行
  - `动作ID / 名称` 一行
  - `参数` 单独展开
- 不要把一个动作对象拆成很多零碎短行，优先保证人工对照 JASS 快速扫描。
- `参数` 里不要直接写 4 位内部 ID。
  - 单位、物品、技能、Boss 等默认优先写真实名、语义名、配置键。
  - 只有做“反查工具补全前的临时占位”时才允许短暂出现内部 ID，且后续必须清掉。
- 旧 JASS 功能描述也尽量同步改成语义名，不要把 `N00C / I00X / I04E` 这类内部 ID 长期留在剧情配置里。
- 涉及“预创建 Boss / 预创建单位”的动作，不能只在动作名称里写语义；是否暂停、是否无敌、是否冻结等待触发，都要在参数里显式写出。

## 3. 对白持续时间规则

- 每句对白必须显式填写 `持续时间`。
- 默认按“可见文字长度 + 标点停顿”估算，不靠主观拍脑袋。
- 计算时忽略颜色码，如 `|cxxxx|r`。

建议基准：

```text
持续时间 = 可见字数 * 0.12 + 标点停顿
```

| 项目 | 增量或边界 |
|------|------------|
| `，`、`、` | 每个 `+0.15s` |
| `。`、`！`、`？` | 每个 `+0.35s` |
| `：`、`；` | 每个 `+0.25s` |
| `……` 或明显省略停顿 | 每处 `+0.5s` |
| 最小时长 | 不低于 `2.2s` |
| 普通对白上限 | 默认不高于 `12s` |

## 4. 时长微调规则

- 重要说明型长句：允许在公式基础上再略增，保证首次阅读能跟上。
- 语气短句、应答句、承接句：优先压短，但仍不得低于最小时长。
- 如果对白包含组织名、人名、颜色重点词、专有名词较多，时长可以略增。
- 后续用户如果提出更偏快或更偏慢的阅读节奏，以用户最新要求覆盖本规则。

## 5. 迁移优先级

- 先保证：
  - JASS 顺序正确
  - 对白与动作挂点正确
  - 时长可读
- 再考虑：
  - 文本润色
  - 抽公共动作
  - 执行器优化

## 6. 完成检查

- 剧情子段、对白编号和原 JASS 执行顺序一致。
- 每个动作的挂点、对白序号或绝对时间完整且可解释。
- 参数使用语义名或配置键；临时 raw id 已清理。
- 预创建单位的暂停、无敌和冻结等待状态均已显式记录。
- 每句对白有持续时间，颜色码未计入可见字数，长短句节奏符合场景。

## 7. 后续维护

- 新剧情默认沿用本规则。
- 若用户对节奏、格式、对白颗粒度提出新要求，直接更新本文件，不要只停留在口头约定。

## 8. 主线节点与引导同步

- 制作、迁移或检查主线剧情时，必须同时检查对应进度的主线引导，不得只确认剧情对白和动作。
- 进度 `1` 及之后的任务描述、任务提示、小地图信号、引导镜头坐标和引导跟随单位统一维护在 `00．剧情系统核心工具/09．主线节点配置.ts`。
- 剧情实际写入的进度、任务目标文本和目标位置必须与主线引导一致；无法使用相同坐标时，需要在节点配置中明确区分小地图坐标与引导镜头坐标。
- 新的节点承接优先使用 `主线.写入进度`、`主线.发布节点目标`、`主线.进入节点` 和 `剧情.停止触发单位`，不得继续复制任务文本与坐标到多个剧情动作参数中。

## 9. 说话者必须在场

- 每一句 NPC 对白显示时，该说话者必须已在当前剧情场景中存在、存活且处于合理站位；不允许只配置对白而让地图另一处的单位“隔空说话”。
- 同一段剧情发生场景切换时，先在首句对白前用 `beforeDialog` 动作完成全部参与者的创建、读取、移动、面向和停止命令；不要等对白开始后或结束后才补单位位置。
- 已存在的 NPC 先读取语义单位引用并确认其没有被移除；若剧情需要更换场景，必须移动到当前场景站位并重新登记。仅当确认不存在时，才按语义单位名创建，不能依赖 YD 临时变量或猜测单位 ID。
- `玩家` 对白要求触发玩家的英雄队伍已在当前场景；`众人` 对白要求对应参与者已就位。它们不是免除场景检查的占位说话者。
- 多人对话必须在配置或执行器中能看出每个参与 NPC 的来源与站位。首次出现可使用固定地图出生点；后续场景明显变化时，必须单独配置转场站位。
- 缺少实际坐标、面向或单位归属时，停止臆测并向用户索取；不得为让对白“看似接上”而复用不相干场景坐标。
- 审查每个主线进度时，除对白、动作、主线引导外，还要逐句核对说话者是否在场；Boss 死亡、传送、撤离、单位移除和 Esc 跳过后的后续对白尤其需要复查。
