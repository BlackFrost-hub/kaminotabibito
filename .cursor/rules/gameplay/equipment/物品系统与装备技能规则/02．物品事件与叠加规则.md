# 物品事件与叠加规则

## 物品事件入口

优先入口：

- `TS/系统/00．核心系统/01．事件中心/04．物品事件中心.lua/ts`

有“使用该物品触发效果”的场景，优先挂物品事件中心。

使用物品时：

- 以物品事件中心上下文提供的参数为准。
- 上下文里通常已有物品、技能 ID、目标点、目标单位。
- 不要回头再靠技能 ID 做二次反查，除非这个效果本身明确依赖技能。

拾取物品时：

- 通用物品迁移入口是：`TS/系统/02．物品系统/15．装备技能/00．物品/00．通用物品/**`
- 拾取逻辑优先挂 `onItemPickup`。

## 物品入包与事件：UnitAddItem 会被原生拾取检测（实测）

**本项目雪月引擎（1.9.4k3 Classic）的 `UnitAddItem` 会触发原生 `EVENT_PLAYER_UNIT_PICKUP_ITEM`，`RemoveItem` 会触发原生丢弃事件。** 已实测验证：裸 `UnitAddItem` 入包后，装备属性由 `onItemPickup` 订阅者正常结算一次（裸 `RemoveItem` 删除后属性也正常扣一次）。

因此：

- **禁止**在“入包成功后”手动分发拾取事件（此前版本曾加 `触发物品拾取事件` 手动分发，导致同一物品被原生 + 手动各结算一次，装备属性双加，如湮灭之风戒指 +40 变成 +80）。该手动分发入口已从 `04．物品事件中心.ts` 移除。
- 封装职责只到“入包”为止，不补事件、不重复模拟：
  - `给予单位物品(unit, item)`：仅 `UnitAddItem`，原生事件自行结算。
  - `创建物品并给予单位(unit, itemId)`：创建（带排泄登记）+ 入包；背包满销毁并返回 0。
  - 两个封装位于 `lib/扩展函数/物品相关函数/创建物品函数.ts`（index 桶导出可用），仍是发放物品的规范入口；裸 `UnitAddItem` 属性虽能生效，但新代码仍应走封装以便统一管理。
- 内部转移仍不得走以上“新发放”路径（会重复结算）：
  - 主/副背包切换（`按Ctrl切换背包.ts`）
  - 背包满移交宠物（`背包满移交宠物.ts`）
  - 材料放回篝火继续加工（`物品加工.ts`，已有静默标志）
  - 仓库/虚拟分区的物品回退（`物品判断函数.ts` 的 `TryGiveItemToUnitBJ`）
- 教训：涉及物品事件语义的改动，先在本环境实测原生 API 行为（雪月引擎对物品 API 的原生检测比原版引擎更完整），不要凭原版引擎记忆下结论。

## 物品叠加系统

默认行为：

- 文件：`TS/lib/扩展函数/物品相关函数/物品叠加函数.ts`
- 这个模块默认开启。
- 文件底部直接执行：`StarItem_OpenStack(ItemRange);`

默认只允许两类物品参与叠加：

- `ITEM_TYPE_CHARGED`
- `ITEM_TYPE_PURCHASABLE`

额外白名单：

- 文件：`TS/lib/扩展函数/物品相关函数/物品叠加配置.ts`
- 用于维护“即使不是 charged / purchasable，也允许叠加”的物品。
- 白名单统一写物品名字，不写 raw id。

当前已知：

- `触手残片` 已加进白名单。

叠加生效条件：

- 同一个 `itemTypeId`
- 英雄单位
- 单位有背包能力 `AInv`
- 事件来源在这套注册玩家范围内

叠加结果：

- 多个同类物品会合并为一个物品。
- `charges` 相加。

## 装备次数是否会放大属性

这是另一个独立概念，不要和“物品可叠加”混淆。

控制文件：

- `TS/系统/02．物品系统/16．装备次数叠加配置.ts`

默认行为：

- 默认不开。
- 只有放进这个配置表的装备名，装备属性才会按 `charges` 放大。

实际结算位置：

- `TS/系统/02．物品系统/11．装备系统.ts`

核心语义：

- 如果 `是否允许装备次数叠加(装备名)` 为真。
- 则倍率 `mult = charges > 0 ? charges : 1`。
- 然后装备属性按这个倍率加到角色身上。

已知已开启按次数放大属性的物品：

- `触手残片`

重要区分：

- 放进 `物品叠加配置.ts` 只是让多个物品能合并成一个带次数的物品。
- 放进 `装备次数叠加配置.ts` 才会让装备属性按次数乘上去。

通常要两边都配，才能做到物品会堆叠且属性也会随次数增长。

## 物品使用防重

- `EVENT_PLAYER_UNIT_USE_ITEM` 在当前项目里可能对同一次使用派发两次。
- 这类逻辑不要只靠“只注册一次触发器”防重。
- 需要用 `globalThis` 存稳定 key 和“已执行”标记，再用定时器清空。
- 物品使用、装备热触发、回血类物品逻辑，优先按这个规则做防重。
