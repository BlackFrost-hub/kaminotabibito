# 配音台词与分段提示词规则

本规则用于把 Boss 中文台词整理成英文 AI Voice 文本，尤其适用于 ElevenLabs `eleven_v3` 的情绪标签和分段提示词。

## 执行摘要

1. 中文 `台词` 负责游戏内显示，英文 `配音台词` 负责 TTS；两者语义一致，但不要求逐字对应。
2. 先判断角色人格、战斗场景和一句话内的情绪变化，再选择声线、英文措辞和标签。
3. 情绪稳定时只用一个短标签；只有明显转折才在句中加入第二个标签。
4. 战斗台词保持紧凑，开场宣判、阶段转折和死亡收束才允许稍慢。
5. 用户确认后把文件写回配置与 `voice_pack_manifest/Boss/<BossKey>.json`；Voice 走外置 MIX，不迁入地图 `imports`。

## 总原则

- 配音文本不是逐字翻译。先理解中文台词的战斗语义、角色人格、情绪走向，再写英文。
- 游戏内 `台词` 保持中文，用于系统消息/广播显示；`配音台词` 使用英文，用于 TTS。
- 系统提示类中文不要直译成播报员口吻，应改写成 Boss 本人能说的话，除非用户明确要求系统播报。
- 短句不强行优化。像 `Pop!`、`The scar will stay.` 这种短促反馈，单个情绪标签即可，甚至可以不加第二段标签。
- 不要为了“看起来专业”堆满标签。标签太多会让声音碎、拖、表演失焦。

## 分段提示词写法

`eleven_v3` 支持在句子中段加入提示词来改变后半句语气。优先在情绪发生转折的地方插入第二个标签。

推荐结构：

```text
[前半情绪] 前半句... [后半情绪] 后半句...
```

适合分段的情况：

- 痛苦 -> 病态释然
- 害怕 -> 占有欲
- 低语 -> 威胁
- 命令 -> 崩溃
- 温柔 -> 残忍
- 冷静 -> 愤怒
- 仇恨 -> 诅咒
- 死亡痛苦 -> 平静收束

示例：

```text
[pained whisper] Purity... it burns... [obsessive relief] The water must be... black...
[softly relieved] Like this... [fading comfort] it doesn't hurt anymore...
[torn with pain] The water remembers pain. [furious curse] So will you!
[weak and pained] The water... hurts less now... [fading whisper] so quiet...
```

不建议：

```text
[pained][whispering][sad][dark][wet][corrupted] The water remembers pain.
```

原因：标签拥挤，模型可能乱读、拖慢或忽略重点。

## 标签决策速查

| 台词状态 | 标签策略 | 节奏 |
|----------|----------|------|
| 单一命令、短促反馈 | 0-1 个标签 | 快、干脆 |
| 同一情绪持续整句 | 句首 1 个标签 | 稳定，不额外切段 |
| 句中发生态度转折 | 转折点增加第 2 个标签 | 前后形成清楚对比 |
| 痛苦、咳嗽、断气等表演动作 | 只在实际发生处放动作标签 | 不让动作词抢走正文 |
| 长篇导演风格描述 | 仅在声线确实需要校正时使用 | 不与大量局部标签叠加 |

## 翻译与改写步骤

1. 先判断这句是不是 Boss 本人说的话。
2. 如果中文是系统提示，改写成 Boss 自身视角的台词。
3. 保留原句核心语义，不要为了英文顺口改掉机制含义。
4. 判断是否有情绪转折；有才加第二段标签。
5. 战斗中台词要短，避免长篇宣言；开场、转阶段、死亡可以稍长。
6. 用户确认某种情绪方向后，把确认版本写回配置表 `配音台词`，不要只留在聊天里。

## 用户当前偏好沉淀

- 用户喜欢台词里有明确角色感，而不是直白系统播报。
- 用户认可 `Ilinca - Vampire Countess` 用于米亚：女性、优雅、病态、腐化、可听清。
- 米亚方向：腐化魔法灵猫，不是老女巫，不是恶魔，不是人类尖叫。
- 米亚台词可带湿润、病态、亲密不安、疼痛、执念、污染纯净等感觉。
- “水会记住痛。你们也会。”应是撕裂、愤怒、仇恨、诅咒情绪，而不是冷淡威胁。
- 死亡/收束台词不要套单一模板，必须先判断角色人格、阵营、战败语义和当前剧情状态，再选择情绪路线。
- 不要把所有死亡句都做成淡然安详。即使中文是“终于安静了”这类收束语，也要看角色是否还有疼痛、执念、怨恨、使命感或不可置信；否则会显得像无事发生、过于平和。
- 骑士、执法者、军团长、守护者等角色，死亡可以更决绝、憋着一口气、守住尊严或使命到底，例如“强撑 -> 誓言/秩序不灭 -> 断气”。
- 邪恶、诅咒、恶魔、亡灵、黑暗人格等角色，死亡可以是虚弱消散，也可以是歇斯底里、不服、怨毒诅咒、临死威胁或疯狂崩溃；不要默认温和收束。
- 自负王者、天才、贵族、神性/半神类角色，死亡可以是不可置信、不相信自己会输或会死，再转为愤怒、崩溃或短暂失神。
- 悲剧污染/寄生/被腐化角色，死亡可走“疼痛解除但仍有残留痛苦”的路线。米亚死亡确认方向是“虚弱疼痛 -> 消散安静”，示例：`[weak and pained] The water... hurts less now... [fading whisper] so quiet...`。
- 如果用户说“这个不错/通过”，立即记录确认文件到配置 `配音资源` 和 `voice_pack_manifest/Boss/<BossKey>.json`；配置路径使用 MIX target，不写 `audio_temp` 或地图 `imports` 路径。
- 用户希望关键战斗技能具备明确而沉重的警告感：玩家应在听到台词时立刻意识到危险正在逼近，而不是只听到平淡的技能说明或普通角色对白。
- 不需要把 Boss 的每一句都做成怒吼。优先挑选高威胁预警、惩罚结算、点名诅咒、阶段大招和终局机制等少数关键节点加强；开场、叙事、普通号令和部分短句仍应保留角色节奏与层次。
- 当用户反馈“整体情绪较淡”时，不要只抬音量或单独提高 `style`。应同时调整句子内容、停顿和情绪弧线，例如“警告 -> 威胁”“仪式命令 -> 捕猎压迫”“痛苦 -> 复仇警告”，必要时再配合降低稳定度、提高 style 和略微加快战斗语速。
- 强警告版本可以使用 `[fierce warning]`、`[thunderous warning]`、`[grave warning]`、`[predatory threat]`、`[vengeful warning]` 等明确标签，但必须避免变成人类尖叫、持续咆哮或失去台词清晰度。
- 用户要求先试听加强版时，必须生成独立候选文件，不覆盖已确认或原始候选；只有用户明确选择后，才更新配置文本、`配音资源` 和 manifest。

## 参数经验

默认可用：

```text
stability: 0.48
similarity_boost: 0.84
style: 0.55
speed: 1.00
```

如果需要更强表演、愤怒、诅咒、崩溃感，可略微调整：

```text
stability: 0.45
similarity_boost: 0.86
style: 0.65
speed: 1.00
```

不要因为一条台词需要愤怒，就全 Boss 都用高 style。按句子语义调整。
