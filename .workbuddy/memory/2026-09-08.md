## 修复：芙莉莲被动效果运行时 nil 报错

游戏内报错：`02．被动效果.lua:23: attempt to call a nil value (upvalue '计算被动冷却')`，触发链有两条（英雄选择注册、伤害事件记录芙莉莲受伤），都会走到"启动隐藏计时"里调用 `计算被动冷却`。

**根因**：`02．被动效果.ts:59` 解构 `const { 计算被动冷却 } = require("...01．冷却缩减计算")`，但该模块的真实导出名是英文 `calcPassiveCooldown`（旧代码英文命名，按中文命名规则不改旧代码）。模块里根本没有 `计算被动冷却` 字段，运行时为 nil；`as {...}` 类型断言把编译器骗过了，TS 侧零报错。

**修复**：解构改名为 `const { calcPassiveCooldown: 计算被动冷却 } = ...`，调用点（203 行）不用动。局部构建通过，生成 Lua 已核对：取的是 `module.calcPassiveCooldown`，调用为局部点调用无 self 污染。

**教训（防复发）**：
- 解构 require + `as {...}` 断言是编译器盲区——断言里的字段名写错 TS 不报错，运行时才炸。新增解构导入时必须 grep 目标模块确认 `export function/const <名字>` 真实存在。
- 排查技巧：TSTL 把中文标识符转义为 UTF-16 code unit 的 hex（如 `8BA1_7B97_88AB...` = 计算被动冷却），在生成 Lua 里 grep 中文 grep 不到，要按 hex 搜或先解码。
- `01．技能冷却/index.ts` 里的 `calcPassiveCooldown: 计算被动冷却` 只是模块内局部别名，`export *` 转发的仍是英文名——读代码时别把局部解构重命名当成 re-export。

## 修复：食人魔雷霆震怒 硬直结束回调 nil self 崩溃

游戏报错：`方向抵抗牵引.lua:160: attempt to index a nil value (local 'self')`，traceback：中心计时器-延迟回调 → `共享机制.lua:411 in local 'callback'` → `方向抵抗牵引.lua:160 in field '停止'`。

**根因**：`01．共享机制.ts` 把控制器类型撒谎声明成 `{ 停止: (this: void) => void }`（require 断言与 `雷霆震怒数据.牵引控制器` 字段两处）。`this: void` 让 TSTL 把 `data.牵引控制器.停止()` 编译成**点调用不传 self**（旧 Lua `:411 data["牵引控制器"]["停止"]()`），而真实实现是 class 方法 `function(self)` → `self["已停止"]` 索引 nil 崩溃。模块内部与清理篮子闭包都显式传 self 所以不炸；第二个调用方 `03．深海涡流.ts` 不保存控制器（清理走清理篮子）也安全，全项目仅此一处。

**修复**：`import type { 方向抵抗牵引控制器 } from '.../方向抵抗牵引'`（相对路径类型导入，TSTL 完全擦除、无运行时 require），require 断言返回类型与 `牵引控制器` 字段都改用该接口。接口方法签名 `停止(): void`（无 this: void）→ 生成 Lua 变为 `local ____self_13 = data["牵引控制器"]; ____self_13["停止"](____self_13)`，self 正确传入。编译通过。

**教训（防复发）**：require `as {...}` 断言里给 class 实例方法标 `this: void` 是运行时炸弹（TS 零报错）——凡返回"带方法的对象/类实例"的封装，必须导入真实接口类型（方法签名不带 this 注解 → 冒号调用带 self），不要手写内联 `{ 方法: (this: void) => void }`。与上午"解构 require 断言骗过编译器"是同一类盲区。
